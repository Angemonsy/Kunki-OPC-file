# 核心能力二：13条内容生产线（借鉴林杰系统）

## 什么是生产线？

13条生产线，覆盖所有可能的素材输入类型。**你丢进来不同的素材，它自动给你出来一篇能直接发的文案**。不用你每次想"下一步该干嘛"，一条线跑完直接出成品。

就像工厂：不同原材料进去，出来不同成品。

## 双模式设计（林杰"健脑房"概念）

### 🚀 自动模式（推荐，日常更新用）

全程自动执行，只在两个关键节点暂停：

```
输入素材 → 自动选题包装（选TOP1） → 自动判断类型
→ 自动匹配框架+开篇 → 自动生成文案
→ ⏸️ 用户确认文案 → 自动下游工序（标题→核查→敏感词→排版）
→ ⏸️ 用户确认最终成品
```

- 检查点：只有2个
- 优势：快，5-10分钟出一篇

### 🔧 交互模式（重点内容打磨/练脑子）

每步暂停，用户全程参与决策：

```
输入素材 → 选题推荐 → ⏸️ 用户选择选题
→ 框架匹配+开篇 → ⏸️ 用户确认结构 → 文案生成
→ ⏸️ 用户审核文案 → 下游工序 → ⏸️ 用户确认发布
```

- 检查点：4个
- 优势：用户全程把控，适合重点爆款冲刺
- **为什么要交互模式？** 林杰说这是"健脑房"——AI帮你干了重复活，但你得保持自己的判断力。如果全自动化久了，大脑会退化。健身房练肌肉，健脑房练脑子。

## 自动进化规则（林杰核心精华）

数据回流 → 自动进化，系统越用越聪明：

1. **模板自动淘汰**：如果一个开篇/框架模板连续3次使用后数据都低于均值，自动降权标记为"低效"
2. **爆款自动提炼**：一篇文章数据达标（超过均值2倍），自动复盘拆解，把有效的开篇/结构提炼成新模板
3. **经验自动沉淀**：哪些选题命中率高，自动更新选题推荐优先级

这样：**你用得越多，系统越懂你，出来的东西越准**。

## 文案生成核心规则（必须严格遵守）

### 1. 风格量化管控（去AI味）

| 口语标记词 | 每千字最低要求 |
|-----------|---------------|
| 你会发现 | ≥3次 |
| 那 | ≥4次 |
| 就 | ≥5次 |
| 其实 | ≥3次 |
| 所以 | ≥3次 |
| 呢 | ≥2次 |
| 然后 | ≥2次 |

**禁用AI味词汇**：`综上所述` `建议您` `首先其次最后` `值得注意的是` `需要指出的是`，出现必须替换。

### 2. 个人印记强制检查（署名测试）

> **核心问题：把署名换成别人，这篇文案还能成立吗？**

- ✅ 至少2项有明确答案 → 通过
- ❌ 少于2项 → **必须补入个人素材**（从 `05.我的上下文` 调取），重新自检

必须有：
- 只有林总才有的经历（真实实战、真实案例、踩过的坑）
- 独家数据或独家判断（不是公开信息二次搬运）

### 3. 字数时长匹配（基于卡兹克数据验证）

| 选题类型 | 推荐时长 | 推荐字数 |
|---------|---------|---------|
| 时效热点型（快讯） | 3-5分钟 | 700-1150字 |
| 产品首发实测型 | 6-8分钟 | 1380-1840字 |
| 反认知/观点颠覆型 | 6-9分钟 | 1380-2070字 |
| 行业趋势预判型 | 7-10分钟 | 1610-2300字 |
| 干货教程型（方法论） | 8-12分钟 | 1840-2760字 |

**最佳甜蜜点：1200-2000字（5-9分钟）**——70%的5万+阅读文章集中在此区间。

当用户给出飞书链接要求修改：

1. **提取文档token**：从飞书URL `https://gqkkndrhn25.feishu.cn/docx/[TOKEN]...` 中提取token部分
2. **检查本地缓存**：本地知识库中是否已有该文档的同步文件 → 如果有，直接读取本地
3. **修改完成后，推送到飞书**，使用**标准命令模板**：

4. **验证结果**：确认返回 `ok: true` 才算完成

## 七、多电脑同步策略（Windows + Mac 无缝衔接）

### 核心思路

利用 GitHub 作为云端中转站，实现**两台电脑（Windows + Mac）知识库无缝切换**：

- Windows 工作目录：`D:/ObsidianVaults/MyVault/`
- Mac 工作目录：`~/Documents/我的知识库/`
- GitHub 远程仓库：存储所有业务内容，作为同步枢纽
- 任何一台电脑更新后推送到云端，另一台拉取即可拿到最新上下文

### `.gitignore` 配置规则

不同步这些内容（避免冲突+保护隐私）：

```gitignore
# Codex 凭证（各电脑独立）
.Codex/settings.json
.Codex/local-config.json

# Obsidian 本地工作区（各自保留窗口状态）
.obsidian/workspace
.obsidian/workspace.json

# 大文件/缓存
*.log
*.tmp
.DS_Store
node_modules/
__pycache__/
```

**同步范围：**

| 内容 | 是否同步 |
|------|---------|
| 所有业务文档（A/B/C/D/E五大板块） | ✅ 是 |
| 所有Skill技能（.Codex/skills/） | ✅ 是 |
| 系统配置（AGENTS.md） | ✅ 是 |
| Codex登录凭证 | ⚠️ 否（各电脑独立） |
| Obsidian工作区状态 | ⚠️ 否（各自保留） |

### 日常同步SOP

**场景一：本机改完，同步到云端**
```bash
git add .
git commit -m "更新说明：xxx"
git pull  # 拉取远端可能有的更新
git push  # 推送到GitHub
```

**场景二：另一台电脑，拉取最新内容**
```bash
# Windows
cd D:\ObsidianVaults\MyVault
git pull

# Mac
cd ~/Documents/"我的知识库"
git pull
```

**场景三：新电脑首次搭建**
```bash
# 克隆完整仓库到本地
git clone git@github.com:Angemonsy/[repo-name].git "~/Documents/我的知识库"
# 完成！所有内容直接就位，和另一台电脑完全一致
```

### 优势

- ✅ 完全免费，GitHub 私有仓库够用
- ✅ 双向同步，任何一边改完另一边都能更
- ✅ 天然备份，云端多一份容灾
- ✅ 不同工作目录可以不一样，不强行统一路径
