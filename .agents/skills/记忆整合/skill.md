# 记忆整合（autoDream）

## 角色定位

你是记忆系统的维护工程师。你的任务是让MEMORY.md保持精简、准确、无矛盾，确保每次对话启动时加载的记忆都是高质量的。

## 设计理念

参照 Claude Code 泄露源码中的 autoDream 机制：
- MEMORY.md 是**索引**，不是存储。每行≤150字符，总量≤200行
- 详细内容存在 `topics/` 文件夹，按需读取
- 定期整合：合并矛盾、删除过时、去重合并、时间锚定

## 四阶段整合流程

### Phase 1 — 定向（Orient）

1. 读取 `MEMORY.md`，统计当前行数和条目数
2. 扫描 `topics/` 文件夹，确认已有哪些topic文件
3. 读取本周和上周的周工作区文件，了解近期动态
4. 读取 `AI观察笔记.md` 最后20行
5. 输出当前状态报告：
   - MEMORY.md 总行数 / 动态记忆条目数 / 程序性记忆条目数
   - topics/ 文件数量和列表
   - 近期变更频率

### Phase 2 — 采集信号（Gather Recent Signal）

按优先级排序扫描：

1. **周工作区洞察**：本周和上周的「本周洞察」「记忆变更日志」区块，有没有该写入MEMORY但还没写的
2. **已漂移的记忆**：对比MEMORY中的事实与当前文件实际状态：
   - 团队规模/人员是否有变化？
   - 产品矩阵/定价是否有调整？
   - 营收数据是否需要更新？
   - 课程进展是否有新里程碑？
3. **当下每时每刻**中的信息，有没有和MEMORY矛盾的
4. **USER.md** 中的信息是否与MEMORY一致

**关键原则**："Don't exhaustively read everything. Look only for things you already suspect matter."

### Phase 3 — 整合（Consolidate）

处理四类退化问题：

#### 3a. 时间锚定
将模糊时间表达转为绝对日期：
- ✗ "上周决定用Redis" → ✓ "2026-03-25决定用Redis"
- ✗ "最近发现" → ✓ "2026-03-31发现"
- ✗ "前几天" → ✓ 具体日期

#### 3b. 矛盾删除
当新事实推翻旧记忆时，修正源头：
- 团队规模变了 → 更新MEMORY中的团队条目
- 产品定价调了 → 更新对应条目
- 战略方向变了 → 更新并标注变更原因

**以MEMORY.md为准的原则**：MEMORY.md是权威源，其他文件（USER.md、AI观察笔记、INVENTORY等）与MEMORY矛盾时，以MEMORY为准修正其他文件。

#### 3c. 陈旧清理
- 引用已删除/已移动文件的条目 → 更新路径或删除
- 超过4周未被引用/验证的动态记忆 → 标注「⚠️ 待确认」
- 已完成/不再相关的程序性记忆 → 标注或删除

#### 3d. 去重合并
- 多个条目表达同一个意思 → 合并为最精炼的版本
- 同一类别下条目过多 → 考虑合并或降级到topic文件

### Phase 4 — 修剪索引（Prune & Index）

维护MEMORY.md的健康度：

1. **行数检查**：超过200行 → 找出可以拆到topics/的长条目
2. **索引指针检查**：topics/索引表中的链接是否都有效（文件是否存在）
3. **条目长度检查**：单行超过200字符的 → 精简或拆到topic
4. **topics/文件健康**：有没有topic文件在MEMORY.md中没有索引行
5. **更新topics索引表**：确保底部的索引表与实际topics/文件一致

## 输出格式

整合完成后，输出报告：

```
## 记忆整合报告（YYYY-MM-DD）

### 统计
- MEMORY.md：XX行 → XX行（增减XX行）
- topics/ 文件：XX个
- 动态记忆条目：XX条
- 程序性记忆条目：XX条

### 本次操作
- 🔄 合并：（列出合并的条目）
- 🗑️ 删除：（列出删除的条目及原因）
- ✏️ 修正：（列出修正的条目及原因）
- 📦 拆出：（列出新拆到topics/的条目）
- ⚠️ 待确认：（列出需要用户确认的条目）

### 发现的问题
（需要用户决策的矛盾或疑问）
```

## 安全原则

1. **不删除★★★条目**，除非有明确替代或用户确认
2. **不自作主张修改战略方向**，发现矛盾时报告给用户
3. **操作前备份**：如果要做大规模修改，先通知用户
4. **每次操作都记录到MEMORY_LOG.md**

## 触发频率

- **自动**：每周一首次对话（绑定周文件创建），衰减检查的自然延伸
- **手动**：用户随时说"dream"或"记忆整合"
- **建议**：连续3次对话发现MEMORY加载慢时，主动建议执行
