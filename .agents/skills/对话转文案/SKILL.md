# 对话转文案

> 聊着聊着，一篇文章就出来了

## 🎯 功能概述

这是一个**对话素材提炼 + 智能路由 + 流水线调度 skill**，解决一个核心问题：
你和AI聊了一个很好的话题，里面有观点、有案例、有思考，但对话是散的，需要有人帮你把它"捏"成一篇结构化的文章。

```
对话记录输入 → 素材提炼（观点/案例/金句/论据） → 文案路径判断 → 框架选择 → 文案生成 → 标题生成 → 排版优化 → 敏感词检测 → 存档反馈
```

## 📥 输入参数

| 参数 | 必填 | 说明 | 默认值 |
|------|------|------|--------|
| `对话内容` | ✅ 是 | 用户与AI的对话记录，可以是当前会话或粘贴的历史对话 | 当前会话上下文 |
| `文案类型` | ❌ 否 | 教知识/聊观点/讲故事/晒过程 | AI自动判断 |
| `执行模式` | ❌ 否 | 自动模式/交互模式 | **询问用户选择** |
| `目标平台` | ❌ 否 | 公众号/小红书/视频号 | 公众号 |
| `侧重角度` | ❌ 否 | 用户希望文章侧重的方向（如果对话涉及多个话题） | AI根据对话重心判断 |

## 🔄 完整工作流程

### Step 0：对话素材提炼（本skill独有步骤）

这是与「灵感碎片转文案」的核心区别。对话记录通常是多轮、发散的，需要先提炼再创作。

**0.1 通读完整对话**

回溯当前会话（或用户粘贴的对话记录），梳理：
- 对话起因：用户最初在问什么/讨论什么？
- 讨论脉络：话题是怎么展开的？经历了哪些转折？
- 核心结论：最终达成了什么共识或判断？

**0.2 提取四类素材**

从对话中提取以下素材，作为文案的原材料：

| 素材类型 | 提取标准 | 示例 |
|---------|---------|------|
| 核心观点 | 对话中明确表达的立场、判断、结论 | "内容创作的核心瓶颈不是效率，是质量" |
| 真实案例 | 对话中提到的具体经历、数据、场景 | "我有40多个AI智能体""研究了迁移方案" |
| 金句/比喻 | 对话中出现的精彩表达、类比 | "主厨vs自动炒菜机""一人公司≠零人公司" |
| 论据/逻辑链 | 支撑观点的推理过程 | "全自动化解决效率→但瓶颈是质量→所以方向错了" |

**0.3 确定文章主线**

对话可能涉及多个话题，需要选择一条主线：
- 如果用户指定了侧重角度 → 按用户指定
- 如果对话有明确的核心结论 → 围绕结论展开
- 如果对话是发散的 → 选择爆款潜力最高的那条线（基于13大爆款元素评估）

输出格式：
```
📋 对话素材提炼结果：

🎯 文章主线：[一句话概括]
💡 核心观点：
  1. [观点1]
  2. [观点2]
  3. [观点3]
📖 可用案例：
  1. [案例1]
  2. [案例2]
✨ 金句/比喻：
  1. [金句1]
  2. [金句2]
🔗 论据链：[A→B→C的逻辑]

是否按这个方向继续？（可调整主线或补充素材）
```

### Step 1：内容类型判断

基于Step 0提炼的素材，按以下决策树判断文案类型：

```
提炼的素材中，核心是什么？
├─ 有明确的立场/判断要纠正大众认知 → 「聊观点」
│    └─ 进一步判断路径：误解澄清/趋势预判/行业内幕/方法论/创业感悟
├─ 有可复制的步骤/方法/教程 → 「教知识」
│    └─ 进一步判断：认知刷新型/方法论型/工具教程型
├─ 有完整的故事线（起因→经过→结果→感悟） → 「讲故事」
│    └─ 进一步判断：个人经历型/他人故事型/行业故事型
├─ 有实战过程的展示（做了什么→怎么做的→结果如何） → 「晒过程」
│    └─ 进一步判断：工具实操型/项目复盘型/成长记录型
└─ 混合型 → 选择最突出的那个类型，其他作为辅助素材
```

**判断后输出：**
```
📝 类型判断：[类型] — [具体路径/角度]
📐 推荐框架：[框架名称]
💡 判断理由：[为什么选这个类型，一句话]
```

交互模式下等待用户确认，自动模式下直接进入Step 2。

### Step 2：文案生成（必须调用对应文案skill）

**⚠️ 强制规则：本步骤必须调用对应的文案生成skill，禁止跳过直接手写。**

根据Step 1判断的类型，调用对应skill：
- 聊观点 → 调用「聊观点文案」skill
- 教知识 → 调用「教知识文案」skill
- 讲故事 → 调用「讲故事文案」skill
- 晒过程 → 调用「实战复盘转内容」skill

**调用时传入：**
1. Step 0提炼的四类素材（观点/案例/金句/论据链）
2. Step 1确定的框架和路径
3. 对话原始上下文（供skill提取真实表达）

**生成要求：**
1. 以Step 0提炼的素材为核心原材料
2. 按Step 1确定的框架结构展开
3. 先读取直播口语风格萃取（⚠️风格底座，口语节奏打底），再读取公众号文案风格萃取，确保风格分层注入
4. 保留对话中的真实案例和金句（这是"人味儿"的来源）
4. 遵循AI创作规范：70%对话原始素材 + 30%框架补充
5. 开篇从对应的开篇模板库中选择或改编
6. 结尾从`公众号结尾引流钩子模板`中选择匹配的钩子

**关键原则：对话中的真实表达 > AI重新生成的表达。** 对话里说过的好句子、好比喻，直接用，不要改。

### Step 2.5：AI味自检（必做，不可跳过）

文案初稿生成后，在进入下游流水线之前，必须执行AI味自检：

**自检清单：**
- [ ] 开篇是否有真实场景/个人经历？（禁止"有个朋友问我"式虚构开场）
- [ ] 是否有内心独白/思考过程？（"我当时就想""研究完之后我反而想明白了"）
- [ ] 比喻是否具体生动？（"超级能干的秘书" > "强大的引擎"）
- [ ] 案例密度是否足够？（每500字至少1个具体案例或数据）
- [ ] 是否使用了口语高频词？（那/就/其实/你会发现/所以）
- [ ] 是否避免了AI禁用词？（综上所述/建议您/首先其次最后/非常有效）
- [ ] 段落节奏是否有呼吸感？（长短句交替，每段不超过3-4行）
- [ ] 结尾是否自然过渡到引流？（不生硬，不突兀）

**不通过处理：** 如果自检发现≥3项不达标，必须重写对应段落后再继续。

### Step 2.6：署名测试（不可替代性检查）

> **核心问题：把署名换成别人，这篇文案还能成立吗？**

逐项检查：
- [ ] 文中是否有**只有你才有的经历**？（个人实战、真实案例、踩过的坑）
- [ ] 文中是否有**独家数据或独家判断**？（不是公开信息的二次搬运）
- [ ] 去掉所有个人印记后，和通用AI生成的内容**区别在哪**？（必须能说清）

**判定：**
- ✅ 至少2项有明确答案 → 通过，继续下游流水线
- ❌ 少于2项 → **必须补入个人素材**（从 `02.领域/0.内容创作系统/🔧06.我的档案/我的个人上下文` 或 `思想力武器库` 中调取），重新过一遍自检

### Step 3：标题生成（必须调用「标题生成」skill）

**⚠️ 强制规则：必须调用「爆款标题生成助手」skill，禁止手动生成或用后台agent替代。**

调用「标题生成」skill，传入完整文案内容，生成20个标题候选：
- 按9大标题公式分类生成
- 标注每个标题使用的公式和爆款元素
- 推荐TOP 3并说明理由
- 结尾补充各平台（视频号/抖音/B站/小红书/公众号）推荐标题

交互模式下等待用户选择，自动模式下选择推荐第1个。

### Step 4：排版优化（必须调用「公众号排版」skill）

**⚠️ 强制规则：必须调用「公众号排版」skill，禁止手动排版。**

调用「公众号排版」skill：
- 提炼2-4个二级标题（融入爆款元素）
- 拆分长段落为3-5行短段落
- 全文使用中文标点
- 正文不加粗
- 插入配图标记

### Step 5：敏感词检测（必须调用「敏感词检测」skill）

**⚠️ 强制规则：必须调用「敏感词检测」skill，禁止跳过。**

调用「敏感词检测」skill：
- 检测全文违规敏感词
- 给出替换建议
- 确认无风险后进入下一步

### Step 6：存档 + 反馈闭环

> ⚠️ **铁律：文案正文生成后必须立即存档草稿，不得等定稿。** 上下文窗口有限，对话结束后内容永久丢失。后续所有修改直接 Edit 该文件，不重新生成。

**存档位置：** `02.领域/0.内容创作系统/🔥02.发布文案/2026年/草稿/公众号/`

**存档时机：文案正文输出完毕后立即执行 Write，不等标题确认，不等自检通过。**

**文件命名：** `YYYY年M月D日-标题关键词.md`

**frontmatter 包含：**
```yaml
---
type: [文案类型·路径·角度]
status: 草稿
created: [日期]

```

> 完整字段规范参见 `02.领域/0.内容创作系统/🛠️11.系统配置/frontmatter规范.md`

**反馈闭环：**
```

- 素材来源：与AI对话
- 对话主题：[主题]
- 文案类型：[类型]
- 使用框架：[框架]
- 字数：[X]字

🔄 后续可选操作：
1. 发布到公众号草稿箱（调用微信公众号发布skill）
2. 生成配套朋友圈文案（调用朋友圈文案生成skill）
```

## 🔁 重写重跑机制

**触发条件：** 当文案在任何阶段被重写或大幅修改时（包括用户要求重写、AI味自检不通过后重写、用户手动修改超过30%内容），必须重新执行所有下游步骤。

**重跑规则：**
```
文案被重写/大幅修改
  → 重新执行 Step 2.5（AI味自检）
  → 重新执行 Step 3（标题生成）— 因为内容变了，标题也要重新匹配
  → 重新执行 Step 4（排版优化）— 段落结构可能变了
  → 重新执行 Step 5（敏感词检测）— 新内容可能引入新敏感词
  → 重新执行 Step 6（存档）— 覆盖旧版本
```

**禁止行为：**
- ❌ 重写文案后只更新文件，不重跑下游步骤
- ❌ 重写后手动排版，不调用排版skill
- ❌ 重写后跳过敏感词检测

## ✅ 下游串联检查清单（存档前必须全部打勾）

每次执行完整流程后，在Step 6存档前，必须确认以下所有步骤已完成：

```
□ Step 2   文案生成 — 已调用对应文案skill（聊观点/教知识/讲故事/晒过程）
□ Step 2.5 AI味自检 — 已执行，8项检查全部通过
□ Step 3   标题生成 — 已调用「标题生成」skill，用户已选定标题
□ Step 4   排版优化 — 已调用「公众号排版」skill，文件已更新
□ Step 5   敏感词检测 — 已调用「敏感词检测」skill，无风险项
□ Step 6   存档反馈 — frontmatter完整，文件已保存
```

**任何一项未打勾，禁止进入存档步骤。**

### 配图标记（调用「文案配图生成」skill）

配图标记由「文案配图生成」skill统一执行，不再在本skill内手动标记。

文案生成并存档后，调用「文案配图生成」skill为文案添加配图标记：
- 自动分析文案内容，识别适合配图的关键位置
- 联网搜索确认截图/录屏类配图的URL有效性
- 插入5种类型的配图标记（设计图/网页截图/滚动录屏/动画录屏/本地截图）
- 配图标记直接写入文案文件
