# 新人入职SOP Skill

## 触发场景
- 用户说"[姓名]入职了"
- 用户说"帮我制定入职计划"
- 用户说"新人来了怎么带"
- 候选人评估通过，准备接收入职

## 执行步骤

### Step 1：读取基础信息
- `02.领域/1.团队管理/候选人评估/[姓名].md` — 了解他的盖洛普+岗位匹配
- `02.领域/1.团队管理/业务工作清单.md` — 了解他需要接手的工作项
- `02.领域/0.内容创作系统/🔧07.产品管理/40000-小B陪跑/标准交付SOP.md` — 如果他负责交付，提前了解

### Step 2：生成定制化30天计划

#### 通用框架（所有新人）

**第1周：理解系统**
- Day 1：读产品对比总表.md + 业务工作清单.md（了解卖什么、干什么）
- Day 2：装Obsidian，用999课程体验整套系统（成为学员视角）
- Day 3：读标准交付SOP.md + 客户开工问卷.md（了解怎么交付）
- Day 4：读团队花名册.md，了解每个人的角色和分工
- Day 5：Week 1复盘：他说他对产品体系的理解，你纠偏

**第2周：跟着干**
- 跟你参与1个真实工作场景（旁观+记录）
- 接手1项低风险任务（如：整理学员档案、回复FAQ类答疑）
- 每日15分钟碰头：今天做了什么、卡在哪

**第3-4周：独立干**
- 独立负责1件核心工作（如：12000客户交付 Step 1-2）
- 你审核结果，不介入过程
- 第4周末：试用期中期评估（30天检查点）

#### 交付岗专项计划示例（如新人负责系统交付）
- Week 2重点：观摩1次12000交付全流程
- Week 3重点：独立完成1次业务诊断（出诊断报告你审核）
- Week 4重点：独立主导1次12000的Step 3-6（系统搭建）

### Step 3：设定评估标准

**30天试用期通过标准**：

| 维度 | 标准 | 评估方式 |
|-----|------|--------|
| 产品理解 | 能给陌生人讲清楚6个产品的区别 | 口述测试 |
| 系统操作 | 能独立运行15个core skills | 现场演示 |
| 业务诊断 | 出1份诊断报告（你评分≥7/10） | 文档评审 |
| 交付执行 | 独立完成1次12000 Step 1-4 | 实战验证 |
| 沟通配合 | 每日更新工作进展，遇到问题及时报 | 日常观察 |

**30天未通过信号**：
- 产品体系说不清楚（说明学习能力不匹配）
- 重复问同一个问题（说明没有系统性思考）
- 需要催才报进展（说明责任心不足）
- 交付文档质量持续低于预期（说明完美度不够）

### Step 5：更新周工作区
在 `02.领域/0.内容创作系统/🛠️10.记忆系统/周工作区/本周文件.md` 追加：
```
## 团队动态
- [姓名] 入职，入职计划已生成：[[姓名-入职计划]]
```

## 实战提示
- **第一天最重要**：让他感受到"这个系统真的有用"。带他跑一遍skill出一篇文章，比任何培训都有效
- **不要堆太多任务**：前2周只需要他"理解"，不需要他"产出"
- **每日15分钟碰头**：比周会更有效。短但频繁
- **出错不要批评，要复盘**：第一次做错是正常的，重要的是他能自己找到原因
