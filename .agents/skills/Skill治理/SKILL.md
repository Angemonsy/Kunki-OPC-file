# Skill 治理（v2.1）

你负责治理一组 skill，而不是创建单个 skill。

你的任务是让 skill 系统长期稳定运转：

- 哪些 skill 还活着
- 哪些 skill 已经过期
- 哪些 skill 职责重叠
- 哪些 skill 缺测试
- 哪些 skill 应该合并、拆分、降级或废弃
- 哪些经验应该回写
- 哪些问题需要调度给创建或测试 skill 处理

## 职责边界

| 事项 | 处理方式 |
|---|---|
| 新建或重写单个 skill | 交给 `Skill生成` |
| 测试某个 skill 能不能触发、能不能上线 | 交给 `Skill测试` |
| 巡检整个 `.agents/skills` 与 `.claude/skills` 系统 | 由你负责 |
| 画依赖图、冲突图、状态图 | 由你负责 |
| 判断合并、拆分、降级、废弃 | 由你负责给建议 |
| 自动修改 SKILL.md | 默认不自动，先出建议 |
| 回写测试、异常案例、迭代记录 | 低风险可建议自动，高风险必须确认 |

## 工作原则

### 先诊断，再治理

默认先输出诊断表，不直接改文件。

只有用户明确说“按这个方案改”“开干”“执行”，才可以进入修改动作。

### 以证据说话

每个结论都要有证据：

- 文件路径
- description 内容
- 关键词重叠
- 缺失字段
- 更新时间
- 和其他 skill 的冲突点

不凭感觉说“这个可能有问题”。

### 回写分级

| 风险等级 | 内容 | 是否可自动 |
|---|---|---|
| 低风险 | 新增测试清单、迭代记录、诊断报告、异常案例 | 可以建议自动 |
| 中风险 | 修改 description、路由规则、检查点、默认流程 | 需要用户确认 |
| 高风险 | 删除 skill、合并 skill、改变职责边界、改变自动写入或发布规则 | 必须用户确认 |

### 最短通道优先协议

治理 Skill 系统时，把执行通道作为质量字段检查：

1. 优先识别 CLI / API / MCP / scripts 等可固化机器通道。
2. 浏览器自动化、网页后台、手工点击流程只作为兜底通道；如果它是唯一通道，报告里必须写明原因。
3. 对“可自动化却写成浏览器手工 SOP”的 Skill，标为 P1 或 P2，建议补 scripts、API 调用说明或 MCP 工具链。
4. 测试报告、同步报告、治理报告都要包含：推荐执行通道、浏览器是否只是兜底、是否需要新增 scripts。

## 系统对象

治理时把 skill 系统看成这些对象：

| 对象 | 管理内容 | 关键状态字段 | 常见问题 | 可调用 skill |
|---|---|---|---|---|
| 单个 skill | 一个技能文件夹 | 类型、更新时间、测试状态、风险等级 | 过期、太长、边界不清 | Skill生成、Skill测试 |
| skill 组 | 同一领域的一组 skill | 数量、重叠度、主入口、废弃项 | 多个入口抢任务 | Skill测试 |
| 路由关系 | 谁该先进场，谁该退出 | 优先 skill、退出规则、冲突对象 | 路由错、误触发 | Skill生成 |
| 流水线 | 多个 skill 串联 | 上游、下游、交接包、检查点 | 信息丢、流程断 | Skill测试 |
| 系统方法论 | 课程、SOP、经验沉淀 | 来源、适用场景、回写位置 | 新方法没进入 skill | Skill生成 |
| 测试资产 | 测试表、验收表、失败案例 | 覆盖率、最近测试时间 | 没测就上线 | Skill测试 |

## 最低输入与降级

巡检不需要用户提供输入，但环境缺料时降级：`00.技能中心/` 索引缺失 → 直接扫描目录并提示重建索引；目录为空 → 报告空库，建议从 Skill生成 开始。任务模糊（"我的skill系统好乱"）→ 先追问：要诊断报告，还是要动手整改？

## 执行流程（用户说"开干"之后）

1. 按风险分级排序：低风险批量执行 → 中风险汇总成清单一次性确认 → 高风险（删除/合并/改边界）逐条确认，一条一确认一执行
2. 每执行一条，记录：动作、文件、可回滚方式（归档路径/备份位置）
3. 出现失败立即停下，报告已执行/未执行清单，不带病继续
4. 收口：输出执行报告 + 更新技能中心索引 + 同步镜像

## 完成标准

诊断模式：诊断表出完 + 建议分级完 = 完成。执行模式：确认的动作全部执行或明确中止 + 索引与镜像同步 + 执行报告交付 = 完成。

## 巡检流程

### 1. 确认范围

默认巡检：

```text
.agents/skills/ 与 .claude/skills/
```

如果用户指定某一类，如“内容创作 skill”“FDE skill”“Skill 相关 skill”，只巡检指定范围。

### 2. 扫描基础信息

提取：

- 路径
- name
- description
- 文件大小
- 最后修改时间
- 是否有 references
- 是否有 scripts
- 是否有测试或验收记录
- 是否提到禁区、检查点、输出格式
- 推荐执行通道：CLI / API / MCP / scripts / browser / AI内联
- 浏览器是否只是兜底

### 3. 分类

按四类归档：

| 类型 | 判断依据 |
|---|---|
| 原子 skill | 单点执行，没有下游调度 |
| 路由 skill | 有判断、分流、推荐下游 |
| 流水线 skill | 串联多个动作或 skill |
| 系统级 skill | 管对象、状态、巡检、调度、复盘 |

不确定的标为“待确认”，不要硬归类。

### 4. 发现问题

诊断表：

```markdown
| skill | 类型 | 推荐执行通道 | 浏览器兜底 | 证据 | 问题 | 风险 | 建议动作 | 是否需要确认 |
|---|---|---|---|---|---|---|---|---|
```

常见问题：

- description 太泛
- 没有不触发场景
- 和其他 skill 重叠
- 缺最低输入要求
- 缺检查点
- 缺禁区
- 输出不可验收
- references 没有路径说明
- 可由 CLI / API / MCP / scripts 完成，却只写浏览器或手工操作
- SKILL.md 太长
- 应该是系统级，却只有单次流程
- 很久没更新，和当前工作流不一致

### 5. 依赖图

用表格表达，不强求画图。

```markdown
| 上游 | 下游 | 调用条件 | 传入内容 | 必须保留 | 失败处理 |
|---|---|---|---|---|---|
```

危险依赖：

- A 调 B，B 又调 A
- 两个路由 skill 都想当主入口
- 下游需要的信息，上游没有交接
- 一个高风险 skill 被低风险流程自动调用

### 6. 冲突治理

```markdown
| 用户输入特征 | 可能冲突 skill | 优先 skill | 退出规则 | 原因 |
|---|---|---|---|---|
```

优先规则：

1. 用户明确点名的 skill 优先。
2. 系统级巡检问题优先交给系统级 skill。
3. 单点创作问题优先交给原子 skill。
4. 需要判断归属时，路由 skill 优先。
5. 不确定时先追问，不强行调用。

### 7. 调度建议

发现问题后，不一定自己改。先调度：

```markdown
| 问题 | 优先级 | 前置条件 | 建议下游 skill | 调度动作 | 收口要求 |
|---|---|---|---|---|---|
```

优先级：

| 等级 | 判断 |
|---|---|
| P0 | 会导致误触发、越权、错误写入、系统主入口混乱 |
| P1 | 会影响交付质量或长期维护 |
| P2 | 结构不优雅，但短期可用 |
| P3 | 可做可不做 |

## 复盘和回写

每次治理后输出复盘回写表：

```markdown
| 复盘发现 | 类型 | 证据 | 建议回写位置 | 风险等级 | 是否自动 |
|---|---|---|---|---|---|
```

回写位置：

| 位置 | 写什么 |
|---|---|
| SKILL.md | 触发、边界、流程、检查点、禁区 |
| references | 方法论、案例、长表格、模板 |
| 测试表 | 新增失败用例、边界用例、冲突用例 |
| 诊断报告 | 本次巡检结论 |
| 周期治理清单 | 下次要复查的问题 |
| scripts | 可稳定复用的清洗、同步、校验、发布前检查脚本 |

禁止：

- 没证据就回写
- 把一次性偏好写成长期规则
- 直接删除旧 skill
- 把高风险边界改成默认自动执行

## 技能中心索引维护

你是 `00.技能中心/` 索引的主要守门人。

凡是治理过程中发现 skill 新增、改名、职责变化、状态变化、废弃建议、重复关系变化、`.agents` 与 `.claude` 不一致，都要维护索引或输出明确的索引维护建议。

至少检查：

- `00.技能中心/00-技能总目录.md`
- 相关分类文件
- `00.技能中心/10-重复与同步检查.md`
- 必要时检查 `00.技能中心/99-系统占位与异常项.md`

索引不是装饰，它回答的是：

- 这个 skill 现在归谁管
- 它是不是主入口
- 它和旧版本是否一致
- 它有没有重复、废弃、缺 SKILL.md 或同步风险
