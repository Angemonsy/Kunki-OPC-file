# 内容复盘&Playbook更新

## 触发方式

- 主动触发：用户说"帮我复盘"、"复盘上周内容"、"更新Playbook"
- 启动协议检测：发现数据监控中心有"待复盘"条目时，在汇报里催促

## 前置条件

复盘前必须有数据。如果数据监控中心对应条目没有数据，先调用「数据采集」skill采集。

## 核心文件路径

- 数据源：`02.领域/0.内容创作系统/🔥03.数据反馈/📊 数据反馈汇总.md`
- Playbook：`02.领域/0.内容创作系统/🔥04.复盘与方法论/Playbook/PLAYBOOK.md`
- 迭代日志：`02.领域/0.内容创作系统/🔥04.复盘与方法论/Playbook/迭代日志.md`
- 爆款案例库：`02.领域/0.内容创作系统/🔥03.数据反馈/爆款案例库/`（按类型分文件）
- 失败案例库：`02.领域/0.内容创作系统/🔥03.数据反馈/❌ 失败案例库.md`
- 选题备选库：`02.领域/0.内容创作系统/🔥01.选题决策/📋 选题备选库.md`

## 5步执行流程

### 第1步：数据读取

1. 读取 `📊 数据反馈汇总.md`
2. 筛选所有状态为"待复盘"或"爆款待复盘"的条目
3. 一次最多处理3篇，超过的告知用户"还有X篇下次继续"
4. 同时读取对应的原文（在 `🔥02.发布文案/` 下找到对应文件）

### 第2步：结构化归因分析

对每篇待复盘内容，输出以下结构（**禁止用"综合原因"这种废话，必须具体到层**）：

```
## 复盘：[标题]

### 数据看板
- 平台：XX
- 阅读/播放：XX
- 互动率：XX% | 收藏率：XX% | 转发率：XX%
- 判定：⭐爆款 / ⚠️中等 / ❌低互动

### 预期 vs 实际
- 预期区间：基于选题类型+历史数据，应该在什么范围
- 实际表现：超出/持平/低于
- 差距：具体数字

### 四层归因（每层必须填）

**选题层**：
- 命中了哪些爆款元素？（对照13大元素逐一检查）
- 遗漏了哪些高频成功元素？
- 选题评分（事后评）：XX分

**开篇层**：
- 用了哪个开篇公式？（对照PLAYBOOK TOP5）
- 是否是本账号历史验证最优的公式？
- 开篇是否在前3句就完成了钩子？

**结构层**：
- 清单式/流程演示式/案例拆解式？
- 与同类型历史最高数据相比，差在哪？
- 篇幅是否合适？（公众号爆款甜区：2000-3000字）

**时机层**：
- 是否蹭了热点？热点窗口期内发的吗？
- 发布时间是否在最优时段？
- 平台选择是否匹配内容类型？

### 可提炼的新规则（如有）
格式："当[条件]时，[做法]能提升[指标]"
```

**失败案例额外加一层**：
```
### 失败根因（选1个主因，不允许多因并列）
- 主因：XX
- 避坑规则："以后不要在[条件]下做[做法]"
```

### 第3步：与PLAYBOOK对比

读取 `🔥04.复盘与方法论/Playbook/PLAYBOOK.md`，逐条对比：

- ✅ **验证**：本次数据是否验证了现有规则？→ 如果是，在该规则旁标注样本量+1
- 🔧 **精化**：是否发现了规则的边界条件？→ 如果是，补充适用条件
- ❌ **颠覆**：是否有数据与现有规则矛盾？→ 如果是，标记冲突，等2次以上验证再修改
- 🆕 **新增**：是否出现了PLAYBOOK里没有的新模式？→ 如果是，新增条目

输出对比结论给用户确认，不自作主张改PLAYBOOK。

### 第4步：更新文件

用户确认后，执行以下更新：

**4a. 爆款案例库**（爆款条目）：
- 按内容类型写入对应文件（教知识/聊观点/讲故事/晒过程）
- 格式遵循案例库已有模板
- 数据监控中心对应条目状态改为"✅已复盘"

**4b. 失败案例库**（低互动条目）：
- 写入 `❌ 失败案例库.md`
- 包含失败根因和避坑规则

**4c. PLAYBOOK.md**：
- 执行第3步确认的修改（验证/精化/颠覆/新增）
- 版本号+1
- 更新"最后更新"日期和数据来源说明

**4d. 迭代日志**：
- 追加一行：`{日期} | v{N}→v{N+1} | 改了什么 | 触发原因`

### 第4e：PREFERENCE反哺

复盘完成后，自动更新 `02.领域/0.内容创作系统/🛠️10.记忆系统/PREFERENCE.md` 的"数据验证"板块：

- **高数据方向**（收藏率≥200% 或 互动率≥15%）→ 追加或强化"持续跑出数据的选题方向"
- **持续跑出的标题公式**（同一公式出现在2篇以上爆款）→ 追加到"持续跑出数据的标题公式"
- **黑洞区**（同一方向连续2篇低互动）→ 追加到"黑洞区（数据差、不再推）"
- 同步更新PREFERENCE.md底部的更新记录表格，追加一行

**执行时机**：在第4步文件更新完成后自动执行，不需用户确认。

---

### 第5步：选题回流

扫描复盘过程中发现的以下线索：
- 用户评论里的高频需求/问题
- 数据验证的高效选题方向的延伸
- 爆款的续集/换角度/换平台可能

将有价值的选题写入 `📋 选题备选库.md`，标记来源为"📊 数据回流"，与人工收集的选题区分。

格式：
```
| 选题 | 来源 | 类型 | 预期 | 备注 |
| [选题名称] | 📊 数据回流 | 教知识/聊观点/讲故事/晒过程 | 基于[案例X]数据推算 | 具体理由 |
```

## 批量复盘模式

当一次复盘3篇以上时，在所有单篇复盘完成后，额外输出：

```
## 批量复盘洞察

### 跨文章共性规律
- 这几篇爆款/失败案例的共同点是什么？

### 元素组合发现
- 哪些元素组合反复出现在爆款中？

### PLAYBOOK更新建议汇总
- 需要修改的规则列表（合并去重）
```

## 注意事项

- 归因分析必须基于数据，不能凭感觉
- PLAYBOOK修改必须经过用户确认，AI不自作主张
- 单条规则被颠覆需要2次以上数据验证才能修改
- 每次复盘完成后，检查是否有遗漏的"待复盘"条目，提醒用户
