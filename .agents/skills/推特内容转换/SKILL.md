## 核心原则

1. **Hook决定一切**：Thread第1条推文决定整个串的传播量，必须花最大精力
2. **每条独立可读**：用户可能只看到Thread中的某一条，每条都要有独立价值
3. **停留时间为王**：X算法核心指标是Dwell Time，内容要让人读得慢、想得多
4. **280字符铁律**：每条推文不超过280字符（约140个中文字），这是硬限制
5. **中英文混排OK**：AI/科技领域中英文混排是常态，不必强求纯中文或纯英文
6. **转发>点赞**：引导转发比点赞更有传播价值

## 工作流程

### Step 1: 读取知识库

- 必须先读取「跨平台分发方法论」获取X/推特内容规范
- 读取「用户画像」了解目标用户
- 读取「文案风格样本库」了解用户风格

### Step 2: 分析原文案

- 读取用户提供的公众号文案
- 提炼核心主题和关键观点
- 识别最有冲击力的数据、案例、金句
- 判断最适合的推特内容形式

### Step 3: 确认输出格式

询问用户需要哪种格式（或全部生成）：

| 格式 | 适用场景 | 说明 |
|------|---------|------|
| Thread推文串 | 干货/方法论/深度内容 | 7-12条推文，完整传递价值 |
| 单条金句推文 | 观点/快评/日常 | 1-3条备选，简短有力 |
| 引流推文 | 为公众号导流 | Hook+预告+链接 |

如果用户没有明确指定，默认全部生成。

### Step 4: 生成Thread推文串（7-12条）

#### 4.1 生成Hook（第1条）- 提供3个备选

基于方法论中的7大Hook公式：
- **版本A**：数字承诺型（如"I spent 100+ hours..."）
- **版本B**：反直觉型（如"Most people do X wrong..."）
- **版本C**：故事开头型 或 痛点直击型

Hook规则：
- 第一句话就是重点
- 必须制造好奇心缺口
- 以"👇"或"🧵"结尾暗示有Thread
- 融入13大爆款元素

#### 4.2 生成正文推文（第2-9条）

- 每条一个核心要点
- 第一句话就是该条的重点
- 用数字、对比、具体案例
- 适当用emoji做视觉锚点（比小红书少）
- 每条结尾留悬念引导读下一条

#### 4.3 生成总结条（第10条）

- TL;DR格式
- 用清单回顾所有要点
- 简洁有力

#### 4.4 生成CTA条（第11条）

- 引导转发（♻️ Repost）
- 引导关注（🔔 Follow）
- 引导回复（💬 Reply）

#### 4.5 生成回链条（最后一条）

- 引用第1条推文
- "Start from the beginning 👆"

#### 4.6 字符数检查

每条推文必须标注字符数，确保≤280字符。

### Step 5: 生成单条金句推文（3条备选）

5种类型各选最适合的：
- **金句型**：一句话说透一个道理
- **快评型**：对热点的即时评论
- **数据型**：用数据说话
- **提问型**：引发讨论
- **分享型**：分享资源或发现

每条标注字符数。

### Step 6: 生成引流推文

- 1个吸引人的Hook
- 1-2个核心观点做预告
- 附公众号文章链接占位符 `[文章链接]`
- 标注字符数

### Step 7: 输出完整内容包

以清晰格式输出：

```
## 🐦 X/推特内容包

### 一、Thread推文串

#### Hook（3选1）
A: ... [XX字符]
B: ... [XX字符]
C: ... [XX字符]

#### 正文
2/ ... [XX字符]
3/ ... [XX字符]
...（依次列出）

#### 总结
10/ TL;DR: ... [XX字符]

#### CTA
11/ ... [XX字符]

#### 回链
12/ [引用第1条] Start from the beginning 👆 [XX字符]

---

### 二、单条金句推文（3选1）
A: ... [XX字符]
B: ... [XX字符]
C: ... [XX字符]

---

### 三、引流推文
... [XX字符]

---

### 发布建议
- 最佳发布时间：...
- Thread发布后操作：...
- 日常推文节奏：...
```

## 自检报告

输出自检：

| 检查项 | 标准 | 结果 |
|--------|------|------|
| 每条字符数 | ≤280 | ✅/❌ |
| Hook吸引力 | 有好奇心缺口 | ✅/❌ |
| 每条独立可读 | 不依赖上下文 | ✅/❌ |
| Thread条数 | 7-12条 | ✅/❌ |
| 有CTA引导 | 转发/关注/回复 | ✅/❌ |
| 有回链 | 最后一条引用第1条 | ✅/❌ |
| 爆款元素融入 | ≥1个 | ✅/❌ |
| 语言风格 | 简洁直接有锐度 | ✅/❌ |

## 配图信息标记规则

文案生成完成后，必须执行配图信息标记：
1. 通读完整文案，找出适合配图的关键位置
2. 在对应位置插入配图标记，格式：`【配图①：图片类型，具体描述内容】`
3. 图片类型包括：对比图、流程图、数据图、场景图、示意图、步骤图等
4. 描述要具体到可直接交给设计师制作

## Step 8: 自动发布到X/推特（可选）

内容包生成完成后，询问用户是否要自动发布：

**询问话术**："Thread内容包已生成完毕，要帮你自动发布到X/推特吗？"

### 发布流程

如果用户确认发布：

1. **提取Thread推文列表**：从生成的内容包中，按用户选择的Hook版本 + 正文 + 总结 + CTA 组装完整推文列表（不含回链条，回链需要发布后手动引用）
2. **生成Thread JSON文件**：将推文列表写入 `05.插件/twitter-thread-publisher/thread_待发布.json`，格式：
   ```json
   {
     "title": "文章标题",
     "created": "2026-02-21",
     "tweets": [
       "第1条Hook推文内容",
       "2/ 第2条推文内容",
       "3/ 第3条推文内容"
     ]
   }
   ```
3. **调用发布脚本**：执行以下命令：
   ```bash
   cd 05.插件/twitter-thread-publisher
   python twitter_thread_publisher.py --file thread_待发布.json --show
   ```
4. **报告发布结果**：将发布条数和状态告知用户

### 发布前检查清单

- [ ] tweepy 已安装（`pip install tweepy`）
- [ ] `.env` 文件已配置4个Twitter API密钥（在 `05.插件/twitter-thread-publisher/.env`）
- [ ] developer.x.com 账户有API积分余额
- [ ] App权限已设为 Read and Write
- [ ] 每条推文 ≤ 280字符
- [ ] 用户已确认发布

### 注意事项

- X API为按量付费，每次调用约 $0.01，一个12条Thread约 $0.12
- 发布间隔默认2秒，避免被限流
- 如果发布失败，脚本会输出错误信息，根据提示排查
