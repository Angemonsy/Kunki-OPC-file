# SKILL.md 九块模板与完整范例

## `description` 字段五要素模板

> 当用户提供【输入对象】，并希望【用户意图】时使用。本 Skill 会【核心动作】，最终输出【输出结果】。不适用于【排除边界】。

范例：

> 当用户提供客户咨询、私信记录或客户疑虑，并希望生成可直接发送的回复话术时使用。本 Skill 会先判断疑虑类型，再匹配卖点和策略，最终输出一段自然的微信回复。不适用于合同审核、退款政策、夸大承诺或自动发送。

再补一层"用户真实问法"（用户不会说标准名字），例如"灵感碎片转文案" Skill 的用户可能说：

- 我有个想法帮我写成公众号
- 这段话能不能变成一篇文章
- 我刚想到一个观点帮我整理
- 这个经历能不能写成故事

把这类口语说法写进 `description` 字段，触发才稳定。

## 反面教材

- `name`：写文案
- `description`：用来写文案
- 正文：你是厉害文案专家，写出吸引人的文案

问题：几乎没有边界，会和所有 Skill 打架；没告诉它怎么判断、到哪停。

## 可直接套用的 SKILL.md 骨架

```markdown
---
name: （清楚、具体、不冲突）
description: （五要素 + 用户真实问法）
---

# （Skill 名称）

## 功能概述
（一段话：这个岗位是干什么的）

## 输入要求
（至少要给什么；给不够先追问）

## 角色定位
（身份 + 擅长任务 + 工作原则 + 决策边界）

## 工作流程
（每步：目标 / 输入 / 判断标准 / 暂停点 / 输出 / 异常处理；
 每一步的结果明确交给下一步）

## 检查点
（方向判断、高成本执行、高风险动作、偏好选择、交付确认——哪里必须停）

## 下游依赖
（读什么资料、调什么工具、接什么 Skill）

## 输出格式
（固定结构：判断结果 / 交付正文 / 操作记录 / 风险提示 / 验收方式）

## 禁区边界
（允许动作 / 必须暂停确认 / 禁止行为 / 异常处理；对照风险等级 A–E）
```

## 完整范例：客户咨询回复 Skill

| 块 | 内容 |
|----|------|
| `name` 名称字段 | 客户咨询回复 |
| `description` 触发说明字段 | 当用户提供客户聊天记录或疑虑，希望生成可发送话术时使用；不适用于自动发送、合同审核 |
| 角色 | 你是销售对话分析和话术教练，只基于用户记录分析，不编造 |
| 输入要求 | 至少给一段聊天记录或一个明确疑虑，不足先追问 |
| 工作流程 | 保留原话 → 判断疑虑类型（价格/时间/效果/信任/执行成本）→ 给依据 → 心理分析 → 生成话术 → 下一步追问 |
| 必须确认 | 意图不明先提示；要求自动发送则拒绝 |
| 禁止 | 不自动发送、不伪造客户信息、不承诺成交 |
| 输出格式 | 类型判断、依据、客户心理、关键阻碍、建议回复、下一步、风险提示 |

## 读懂 / 验收一个 Skill 的 8 个问题

1. 它什么时候触发　2. 什么时候不触发　3. 接收什么输入　4. 输出什么结果
5. 会读取哪些知识　6. 会调用哪些下游　7. 哪里必须停下来确认　8. 禁止做什么

不看它写得漂不漂亮，看它怎么控制触发、判断、边界。
