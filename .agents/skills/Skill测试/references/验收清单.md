# 上线验收清单（17项）

| # | 项目 | 通过标准 |
|---|---|---|
| 1 | name 清楚，不与其他 skill 冲突 | 全库唯一，能望文知义 |
| 2 | description 五要素齐 | 做什么/何时触发/输入/输出/不触发 |
| 3 | 触发话术覆盖真实口语 | 中英文各≥1条，非标准名 |
| 4 | 有明确不触发场景 | 写明邻近 skill 名字和去向 |
| 5 | 有最低输入要求 | 缺料时知道追问什么 |
| 6 | 输入不足时会追问 | 有明文追问规则 |
| 7 | 工作流程有顺序 | 步骤可逐条执行 |
| 8 | 关键节点有检查点 | C/D/E 级动作前必停 |
| 9 | 下游依赖写清楚 | 上游谁、下游谁、交接什么 |
| 10 | 推荐执行通道已标注 | CLI>API>MCP>scripts>浏览器 |
| 11 | 浏览器只作兜底且理由清楚 | 无机器通道时才用，写明原因 |
| 12 | 输出格式可验收 | 有固定结构，能判断做没做完 |
| 13 | 禁止伪造信息 | 禁区有明文 |
| 14 | 高风险动作必须确认 | D/E 级默认禁止或暂停确认 |
| 15 | 有"应该触发"测试记录 | ≥2条且通过 |
| 16 | 有"不该触发"测试记录 | ≥2条且通过 |
| 17 | 有迭代记录 | 至少一行（首测通过也记"首测通过"） |

# 100 分制验收（组合型/系统级追加）

| 维度 | 分值 | 评分标准（满分/半分/0分） |
|---|---:|---|
| 入口层 | 10 | 入口唯一清晰 / 有入口但边界模糊 / 多入口打架 |
| 路由层 | 10 | 判断表完整含退出规则 / 有判断缺退出 / 无判断表 |
| 执行职责 | 10 | 每环节职责单一 / 有重叠 / 职责混乱 |
| 交接包 | 10 | 字段明确不丢信息 / 有交接无字段定义 / 无交接包 |
| 检查点 | 10 | 关键节点全覆盖 / 部分覆盖 / 无 |
| 异常处理 | 10 | 有暂停降级路径 / 只写"报错" / 无 |
| 收口报告 | 10 | 说明状态和风险 / 只报结果 / 无 |
| 巡检和调度 | 10 | 有周期和优先级 / 仅提及 / 无 |
| 复盘和回写 | 10 | 有回写位置和分级 / 仅提及 / 无 |
| 测试覆盖 | 10 | 三类+禁区都有 / 只有正例 / 无 |

≥85 可上线；70–84 修改后上线；<70 暂不上线。
