# 月度经营复盘

## 触发方式

- 用户说"经营复盘""看看这个月怎么样""月度复盘""战略复盘"
- 每月1号启动协议中的"战略脉搏"提醒后，用户确认执行
- 用户说"回顾一下上个月"

## 前置条件

- 确认当前日期，确定复盘的是哪个月
- 如果财务仪表板当月数据为空，先引导用户口述填写，再开始分析

## 执行流程

### 第一步：数据加载（全部读完再分析）

1. Read `财务仪表板.md` — 提取本月实际收入、各产品线数据、成本
2. Read `决策日志.md` — 筛选本月及上月的决策条目，重点看"待回填"的
3. Read `风险雷达.md` — 筛选"活跃"状态的风险项
4. Read `产品体系总览.md` — 对照年度目标
5. Read `MEMORY.md` 战略区块 — 获取核心战略方向

**如果财务仪表板本月数据为空**：暂停分析，直接问用户——

> "这个月的收入数据还没填。大概说一下：总共进了多少钱？主要来自哪几个产品？我帮你记到仪表板里，然后再分析。"

用户回答后，Edit 写入财务仪表板，再继续。

### 第二步：四维度分析

#### 2.1 营收健康度

```
本月收入：X万 / 年目标：300万
年度进度：X%（应该到 X%）
差距：领先/落后 X万
```

- 哪个产品线贡献最大
- 哪个产品线低于预期
- 转化漏斗有没有明显卡点（曝光够但转化低？还是曝光就不够？）

#### 2.2 决策回顾

- 本月做了几个决策
- 上月的决策，结果出来了吗？
  - 结果已出 → 引导用户口述结果，Edit 回填决策日志的"结果"列
  - 还没出 → 检查是否超期（超过截止日期的标红提醒）
- 有没有决策被证明是错的？如果有，记录教训

#### 2.3 风险扫描

- 活跃风险有几个
- 哪些风险的状态变了（恶化/好转/已解决）
- 有没有新风险信号（结合本月对话中观察到的）
- 引导用户确认每个风险的最新状态，Edit 更新风险雷达

#### 2.4 关键假设验证

- 从财务仪表板的"关键假设清单"中，检查有没有可以验证的
- 有数据支撑了 → 标记"已验证"或"已证伪"
- 还不够数据 → 说明还需要什么数据、预计什么时候能验证

### 第三步：输出经营判断

用以下格式输出，语气像合伙人之间的月度碰头，不要像报告：

```markdown
## X月经营复盘

### 一句话判断
（这个月整体是 好/一般/有风险，为什么）

### 钱的情况
- 本月进账 X万，年度累计 X万（目标300万的X%）
- 主力产品线：XXX
- 拖后腿的：XXX
- 漏斗卡点：XXX

### 决策追踪
- X个决策已回填结果
- X个决策待验证
- 需要注意的：XXX

### 风险变化
- 新增X个 / 解决X个 / 恶化X个
- 最需要盯的：XXX

### 下月三件事
1. （最重要的一件）
2. （第二重要的）
3. （第三重要的）
```

### 第四步：写回系统

1. **周工作区**：将"下月三件事"写入当前周工作区的战略区块
2. **当下每时每刻**：如果经营判断导致战略方向调整，更新当下每时每刻的相关段落
3. **决策日志**：回填本月已有结果的决策
4. **风险雷达**：更新风险状态、关闭已解决的风险
5. **MEMORY.md**：如果发现重要的经营模式/教训（如"99元产品转化率远超预期"），写入战略区块

所有写入操作完成后，末尾汇总通知：
```
[经营复盘] X月完成
- 财务仪表板：已更新
- 决策日志：回填X条
- 风险雷达：更新X条，关闭X条
- 下月重点：1.XXX 2.XXX 3.XXX
```

## 重要规则

1. **数据说话，不编数字**。财务仪表板没填的，问用户要，不猜
2. **不回避坏消息**。如果落后目标，直说，别包装
3. **"下月三件事"必须具体可执行**，不要写"加强内容产出"这种废话，要写"每周发3篇公众号，重点测试教知识类选题"
4. **每个决策的结果必须追到底**。超过截止日期未回填的，每次复盘都提醒，不让它沉没
5. **复盘不是汇报，是碰头**。语气像两个合伙人月底坐下来聊，不是下属给上级写报告
