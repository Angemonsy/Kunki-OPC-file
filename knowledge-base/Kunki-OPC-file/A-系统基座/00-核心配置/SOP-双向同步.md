# SOP：飞书 ↔ 本地知识库双向同步

## 基本原则

1. **结构不变原则**：本地 `01~12` 编号文件夹结构保持不变，只更新内容不改动结构
2. **对应关系原则**：飞书云端文档 → 本地按**主题相符**原则放入对应文件夹
3. **分层查询原则**：
   - **快速查询**：用户只是问飞书内容 → 直接导出读内容回答，**不保存到本地**，节省时间和空间
   - **全量同步**：用户说「同步飞书」或**每日定时23:30自动同步** → 拉取所有更新到本地
4. **增量更新原则**：只同步飞书上修改时间比本地新的文件，不重复下载没变的文件
5. **重要结果存档**：任何同步、整理结果都要保存到本地知识库

## 调用规范（记住！）

| 操作 | 正确命令 |
|------|----------|
| 列出文件夹文件 | `lark-cli drive files list --params '{"folder_token":"TOKEN"}' --as user` |
| 删除文件 | `lark-cli drive +delete --file-token TOKEN --as user --yes --type docx` |
| 导出文件 | `lark-cli drive +export --file-token TOKEN --type docx --as user` |
| 下载导出文件 | `lark-cli drive +export-download --task-id ID --output ./path --as user` |
| 上传文件 | `lark-cli drive +import --folder-token FOLDER_TOKEN --local ./local-file.md --as user` |

## 权限要点

- 大部分操作需要**用户身份**：`--as user`
- bot身份权限不足，删除/修改操作通常失败
- 删除必须指定 `--type`：`docx`/`folder`/`sheet`/`bitable`
- 参数名必须正确：`--file-token` **不是** `--token`

---

## 处理重复文件流程（用户要求删除重复时执行）

1. 获取文件夹所有文件列表
2. 按文件名分组（通常按日期+类型分组）
3. 同一组内比较 `modified_time` 时间戳
4. **只保留时间戳最大的版本**（最新修改）
5. 删除其他重复版本
6. 删除后列出剩余文件验证结果

## 记住

用户要求"一个日期有多个文件重复，保留时间最晚的" → 就是按上面这个流程做
