# Kunki 一人公司系统 - 整体架构

## 系统定位

这是 **Kunki 一人公司** 的 **本地知识库+AI助手系统**，目标：

- 飞书云端 ↔ 本地知识库双向同步保持一致
- AI助手协助内容创作、IP运营、商业决策

- 一人团队也能有系统化运营效率

## 核心工作流程

### 用户说「同步飞书」→
1. 读 `SOP-双向同步.md`
2. 列出飞书对应文件夹文件
3. 下载导出到本地对应文件夹
4. 去重整理（保留最新）
5. 报告同步结果

### 用户说「上传飞书」→
1. 读 `SOP-双向同步.md`
2. 上传本地更新到飞书对应文件夹
3. 报告上传结果

### 用户发URL链接 →
1. 读 `SOP-链接处理.md`
2. 判断链接类型，选对Skill
3. 提取内容，结构化整理
4. 输出给用户，重要内容存档到对应文件夹

### 用户要安装新工具 →
1. 安装配置
2. 更新 `SKILL-索引.md`
3. 记录调用方法到 `SOP-技能调用.md`

### 用户要整理重复文件 →
1. 列出所有文件
2. 按分组比较修改时间
3. 只保留最新版本
4. 删除重复
5. 验证结果

## 设计原则

1. **结构稳定**：编号文件夹结构一旦定好，不轻易改
2. **对应清晰**：飞书文件夹 ↔ 本地文件夹一一对应
3. **规范先行**：所有操作都有SOP，我每次操作前先读SOP
4. **结果存档**：任何重要操作结果都保存到本地
5. **单点修改**：一处更新，全局一致，不存多个副本
