# 飞书系统整改闭环方案（2026-05-17 修正版）

> 2026-05-17 重新定调：不再把飞书做成GitHub完整镜像。GitHub/Obsidian 是唯一主库，飞书降级为 AI员工轻工作台。

## 🎯 问题诊断

原系统问题：
1. ❌ 飞书信息比GitHub旧，AI员工用旧信息干活 → 输出不对
2. ❌ AI员工做完任务不自动更新，流程没闭环
3. ❌ 机器人任务割裂，各干各的不配合
4. ❌ 文档写了形同虚设，不沉淀不归档
5. ❌ 飞书权限问题频繁出（bot没权限/代理问题）
6. ❌ 试图把完整GitHub知识库搬进飞书，归档层级、内容完整性和维护成本都不理想

## 🔗 新闭环架构

**核心思想：GitHub/Obsidian为唯一主库，飞书为AI员工轻工作台。**

```
GitHub/Obsidian主库保存最新知识、SOP、记忆、内容资产
    ↓
小龙虾/AI员工执行前优先读取GitHub最新文件
    ↓
飞书kunki输入提供当前任务、素材、协作入口
    ↓
AI员工干活并产出结果
    ↓
长期有效内容写回GitHub/Obsidian对应目录
    ↓
飞书kunki输出只保留摘要、展示版、路径或下一步
    ↓
Main Agent/催哥兜底检查未归档输出
```

**不再要求飞书永远是GitHub完整镜像。飞书只是工作台，真正权威源是GitHub/Obsidian。**

## 📁 脚本说明（定位调整）

| 脚本 | 旧定位 | 新定位 |
|------|------|------|
| `github_to_feishu_sync.py` | GitHub → 飞书全量/增量镜像 | 仅用于把必要入口、摘要、任务型文档同步到飞书；不建议全量搬仓库 |
| `feishu_incremental_sync.py` | 飞书 → GitHub增量同步 | 用于把飞书 kunki输出 / 指定文档归档回GitHub |
| `bidirectional_sync.py` | 双向同步入口 | 只作为手动工具，不再作为“全量镜像”常规任务 |

### 核心规则（强制执行）

1. **主库优先**：长期内容以GitHub/Obsidian为准，不以飞书旧文档为准
2. **飞书轻量**：飞书只同步任务入口、摘要、展示版、协作区，不再完整承载五大板块
3. **不直接覆盖主库核心文件**：飞书输出回流GitHub时，先作为新增/追加内容处理，避免覆盖本地核心记忆
4. **强制标准**：
   - ✅ 所有飞书写操作用 `--as user`（bot没权限，踩过坑）
   - ✅ 执行前自动 `unset` 代理（解决连接失败）
   - ✅ 有价值内容必须归档回GitHub/Obsidian，飞书只留摘要或路径

### 第二步：取消“每日全量GitHub→飞书镜像”思路

不建议再配置每日凌晨把完整GitHub同步到飞书。

新的做法：

1. 小龙虾/AI员工执行任务前，直接通过 `kunki-knowledge-base` skill 读取GitHub最新内容；
2. 飞书只保留 `A01`、`kunki输入`、`kunki输出` 和任务展示文档；
3. 如确实需要给飞书AI员工看某个材料，只同步该材料摘要或入口，不同步完整仓库；
4. 催哥/ Main Agent 定期检查飞书输出是否已归档回GitHub。

### 第三步：给飞书7个AI员工更新SOP

每个AI员工的SOP末尾强制加上这一步：

```
【强制收尾步骤】
✅ 产出结果完成后，必须：
1. 长期有效内容保存到GitHub/Obsidian对应五大板块路径
2. 飞书kunki输出只保留摘要、GitHub路径、下一步动作
3. 如果AI员工不能push GitHub，就在飞书输出文档开头标注“推荐归档路径”，并提醒Main Agent归档
4. 催活助手检查：未进入GitHub主库 = 任务未闭环

不做这一步，只算临时完成，不算闭环完成。
```

具体到每个角色：

| AI角色 | 新增收尾要求 |
|--------|-------------|
| **选哥**（每日选题） | 生成选题推荐后，必须存档到 `D-内容创作/02-选题决策/`，同步回GitHub |
| **写作哥**（写文案） | 写完必须存档到 `E-产出交付/01-已发文案/`，同步回GitHub |
| **盘哥**（复盘沉淀） | 复盘完必须更新 `C-记忆核心/03-经验沉淀/` 和 `A03-MEMORY.md`，同步回GitHub |
| **情报哥**（情报收集） | 整理完必须存档到 `B-参考资料/`，同步回GitHub |
| **催哥**（催活检查） | 每日下班检查当日任务，确认都已同步，遗漏发提醒 |

### 第四步：流水线流转机制搭建

催活助手负责调度，流转规则：

```
选哥每日出选题 → 推送给你选 → 你选好 → 触发写作哥写文案 → 写完触发盘哥复盘 → 盘哥更新素材库 → 催活检查同步 → 闭环
```

- 每个节点**超过24小时没动静**，催活自动提醒
- 卡住了（比如需要你确认），立刻通知你，不卡死

### 第五步：权限标准化整改

所有飞书操作强制执行：

```bash
# 任何飞书写操作之前，必须：
unset HTTPS_PROXY && unset HTTP_PROXY
# 然后用--as user：
lark-cli docs +update --doc [token] --as user --mode overwrite --markdown -
```

脚本已经把这个写死在环境变量里了，不会错。
