## 第一课：AI产品经理Skills——从商业分析到PRD全流程

### 核心命题
为什么直接问AI写PRD效果差？如何用Skills解决？

### 直接问AI的四个致命坑
1. **方向跑偏**：AI不知道用户是谁，会编造数据，功能像购物清单，分不清MVP优先级
2. **AI产品维度漏项**：不会主动考虑幻觉处理、兜底方案、人工介入时机
3. **只有正面论证**：AI天然附和，不会主动说方案可能死在哪
4. **没有后续验证**：文档写完就结束，缺少自检和验证计划

### Skills的本质
Skills不是一个提示词，而是把经验、脚本、格式模板放在skill文件夹，让AI按需加载。相当于给AI塞了一本工作手册，不用重新教，不用担心漏东西。

- **Skills = 系统级能力插件**
- **普通prompt = 一次性消耗品**

### Skills技术架构
**文件结构**：
- `skill.md`：核心指令文件
- `reference/`：模板文件夹（用户画像、MRD、BRD、PRD、竞品分析）

**skill.md内部模块**：
- **Front Matter**：Skills的身份证（名称、描述），决定什么时候匹配
- **Role/Goals/Constraints 三件套**：
  - Role：岗位说明书
  - Goals：产出什么结果（KPI）
  - Constraints：不能做什么（底线红线）

### Constraints关键设计原则
| 原则 | 核心思想 |
|------|---------|
| **矛盾驱动原则** | 分析核心矛盾，牵牛要牵牛鼻子，分清主次 |
| **模板驱动原则** | 调用reference模板填充，不让AI自由发挥 |
| **事实优先原则** | 市场数据必须联网搜索，禁止编造 |
| **反面验证原则** | 强制魔鬼代言人检验，搜索失败案例 |
| **轻量化原则** | 输出1-2页核心内容，避免冗长 |

### 六步工作流（严格按顺序）
1. **项目信息收集与核心矛盾识别** → 输出主次矛盾+转化方向，等待确认
2. **用户画像定义** → 从真实矛盾出发，输出用户矛盾映射表
   - B端关注：决策链、安全合规
   - C端关注：口碑传播、付费意愿、价格敏感度、使用频率
3. **市场与竞品分析** → 必须搜索同赛道失败案例，验证核心假设
4. **商业分析** → 填充商业目标、价值主张、盈利模式、风险依赖、成功标准
5. **PRD撰写** → 核心输出：
   - P0功能不超过3个（MVP快速验证）
   - AI能力需求（模型选型、效果指标）
   - 数据需求（训练/评测数据来源）
   - Prompt/Agent架构选型
   - **人机协作边界**（AI做什么、人做什么）
   - **兜底策略**（模型失败降级方案）
   - AI特有关注点：模型选型、成本控制、安全合规、数据飞轮设计
6. **需求自检与魔鬼代言人检验** → 13项完整性检查，最强反驳核心结论，输出假设验证跟踪表

### 三种执行模式
- **快速模式**：早期探索，跳过联网，快速出草稿
- **完整模式**：包含搜索、反面验证、魔鬼代言人
- **单文档模式**：只需要补一份文档时直接跳转对应步骤

### 硬性禁止规则
- 禁止编造数据
- 必须搜索失败案例
- 竞品分析超过3个
- 必须定义兜底策略

### 关键洞察（实操演示案例）
在"AI家庭一周菜谱助手"案例中：
- 主要矛盾识别：**不是不会做菜，而是想菜太消耗精力**
- 风险发现：同赛道失败案例显示"用户不愿意为膳食规划付费" → 直接影响商业模式从订阅制转为"工具免费+交易抽佣+CPS广告"

### 从PRD到原型落地路径
Skills生成详细PRD → 秒搭（字节低代码）快速生成前端原型 → Claude Code二次修改框架 → 部署到自己服务器 → **从构想到可用原型约2小时**

## 第二课：AI知识库如何落到业务上

### 讲者背景
马克，林杰老师关门弟子，给杨哥从0到1操盘IP，单月100万GMV，16000+付费订单，月产出130条营销文案。

### 核心观点一：你收藏的都不是你的
大量收藏本质是"保存触发多巴胺，制造已完成幻觉"。只有经过大脑加工——提炼核心观点、验证论据、结合自身写出评价结论——**这个输出才是你的**。

### 核心观点二：知识库只放自己的输入
知识库分两半：
- **给人看的**：日记、文章、判断、故事、思考
- **给AI看的**：人格总结、决策模型、认知体系、审美参考（AI自动读取，你不用看）

所有输入渠道（微信收藏、抖音、飞书、备忘录）最终汇入同一个本地知识库。

### 核心观点三：不要再整理了，那是AI的事
不用纠结分类体系，你只负责**输入思考判断灵感故事**，AI负责整理分层总结。你是领导，AI是私人秘书。

### AI四象限模型（李继刚）
| 象限 | 描述 | 是否入库 |
|------|------|---------|
| 第一象限 | AI知道你也知道（公开常识） | ❌ 不需要 |
| 第二象限 | AI知道你不知道（专业知识） | 🔄 向AI学习 |
| **第三象限** | **你知道AI不知道**（你的判断、故事、失败、经验、洞察） | ✅ **最关键，全部入库** |
| 第四象限 | 双方都不知道（想象力创造力） | 🌟 自发涌现 |

### 第三象限深度理解
马克给杨哥做100万GMV，靠的是**对用户的深度理解**（触发时机、决策方式、为什么今天买）——这些AI搜不到，只有和真实用户聊出来才有。沉淀后AI能直接调用。

第三象限积累足够深厚，**第四象限可能自发涌现**——AI站在更高视角给你意想不到的洞见。

### 进化路径：从手搓到知识库+AI
1. **手搓文案**：月产五六条，拆解对标，建立认知
2. **结构化提示词**：框架沉淀为骨骼，装入风格案例信息，但有大文件上传不了的卡点
3. **Claude项目化**：网页端建项目，但知识库太满放不下
4. **本地知识库+Skills**：素材分类存放，AI自动加载，效率提升**20倍以上**，月产130条

### 技能如何变成Skills
第一次完整跑通流程后，把**步骤、判断标准、模板、方法论**写成Skills，AI以后自动按流程引导。可以拆分更细——选题Skills、内容Skills、标题Skills，独立复用。

### AI选型务实建议
不要在各个模型之间反复横跳。基于你的业务，让多个模型同时跑结果，**你自己判断哪个适合**。模型随便迭代，你的知识库不变，换模型只是换引擎。

知识库+AI组合能**抵抗工具焦虑**——不管外面怎么变，核心资产永远是你的。

### 保持主体性对策（AI会不会让人变蠢？）
确实存在风险。核心对策：**写完文案必须自己读三遍**——用户角度、自己角度、第三视角。
- 你懂的领域：你是骑手，AI是马（你牵着走）
- 你不懂的领域：你是包工头，AI是施工队（你只验收结果）

### 关于"一定要本地"
所有工具尽量装本地。本地AI能读所有本地文件，真正有了"手脚"。云端限制太多（大小、延迟、VIP、网络）。

## 第三课：一人公司——从经验到产品化的系统搭建

### 一人公司三个判断标准
1. 你停止工作后，**系统能否自动产出内容和产生价值**？不能→只是自由职业者
2. 你的交付能否复用**？每次从零开始→卖手工的；交付模板/SOP/系统→一人公司
3. 增加收入是否需要加人？传统公司需要招人，一人公司通过AI优化增长，加人只在几十倍增效时考虑

### 经验不值钱，产品化的经验才值钱
"会用AI写公众号"你的经验一文不值，林杰老师的经验能卖上万——区别在于**他把经验写成Skills、做成SOP、打包成系统，写一次卖无数次**。这就是产品化。

### 一人公司搭建四步法

#### 第一步：找定位
最简单方法：**别人高频请教你的问题就是你的定位**。
- 你积累了什么别人短时间学不会的？
- 别人经常夸你什么？
- 你做什么比别人快？
- 周围人认为什么话对你有启发？

#### 第二步：做产品
- 最小可售产品：PPT模板、付费诊断PDF、资料包，哪怕9.9元也行→**关键是先有**
- 产品好坏判断：交付的是**系统而不是知识**，够简单拿到就能出结果，快速让用户得到小成果
- 产品设计公式：**我帮谁 + 解决什么问题 + 交付什么结果**
- 验证方法：先做预售，有人付费说明需求成立，没人要立刻换方向→**不要做100%再卖**

#### 第三步：找客户
第一批用户是**聊出来的**，不是引流来的。从身边信任你的人开始。
- 一人公司不追求大流量，追求**高信任**
- 所有内容都围绕产品写，每篇都是获客，每条都是软广

#### 第四步：跑闭环
能力→产品→获客→交付→收款→复盘→循环。一定要**自己手动跑通第一遍**，不要一开始追求自动化。跑通后再让AI把流程做成Skills。

### MVP验证案例
用40亿TOKEN摸清OpenClaw能力边界，打包三个核心能力：精准化起标题、框架化写作、一键排版。单篇12万阅读，0成本生成书单号视频，99元卖了50多份，15天变现5000+→验证最小闭环。

### 从闭环到系统：放大的关键——多Agent协同
不是一个AI做工作流，而是**多个Agent之间能内部沟通、主动思考、主动帮你工作**。

案例：朋友圈留言→截图发给Agent→营销冠军判断信任度→给出话术→引导成交→客户状态判断→维护关系→完成后自动更新用户画像给内容运营→晚上战略咨询官发现问题→主动优化追单系统。

这才是一人公司——**系统在替你干活，不是帮你干活**。

### 持续维护
- 每天定时整理当天聊天产出，有用的写入记忆
- 满意的AI回复立刻写入知识库，不等结束
- 养熟的OpenClaw会越来越像你——说话方式、思考逻辑、行为模式都趋同

### 语料质量决定输出质量
- AI喂AI→输出AI味重
- 人工喂AI→输出人味强
- 降AI率最简单方法：把文章对着语音软件念一遍，转文字再用

### Skills的本质（主讲人视角）
Skills是**结果的复现**。拿到好结果，立刻让AI把"如何复现"打包成Skills——不是你自己写，让AI根据成功路径自动生成。

## 三节课共同底层逻辑

### 关于Skills/SOP
三位一致认为：Skills不是凭空设计，**你先手动跑通完整流程，验证有效后，再让AI固化为可复用的Skills**。
- 第一课：产品需求Skills来自实战方法论
- 第二课：营销文案Skills来自130条实战积累
- 第三课：一人公司Skills来自15天变现验证

### 关于知识库
核心资产是**你自己的判断、经验、思考（第三象限）**，不是收藏别人的内容。知识库+AI抵抗工具焦虑——模型随便换，你的知识库不变。**本地优先，安全可控**。

### 关于AI协作
不要把AI当搜索引擎或机器人，要**建立关系**：老师（向它学）→战友（并肩作战）→团队（替你干活）。现在的OpenClaw/Claude Code会主动思考、主动提建议、主动发现问题，和之前聊天式AI完全不同。

### 关于验证优先
- 第一课：PRD要有魔鬼代言人检验和假设验证表
- 第二课：内容要站在用户角度反复审视
- 第三课：产品先预售验证需求再打磨
- 共识：不想清楚再动手，先动手再边做边想清楚

## 对现有系统的启发
1. **Skills设计方法论**：我们现有的29个Skills可以按"矛盾驱动、模板驱动、事实优先、反面验证、轻量化"这套框架进一步优化
2. **产品化方向**：rank1+AI实践经验，可以把"经济学生如何用AI做跨学科研究"这类经验打包成可交付产品
3. **知识库第三象限**：强化"只放自己加工输出"原则，清理纯收藏未加工内容
4. **多Agent协同**：我们飞书端已经有六人分工，符合这个方向，可以进一步强化Agent间自动流转
