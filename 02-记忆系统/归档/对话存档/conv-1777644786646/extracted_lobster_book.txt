本书内容非常丰富，涵盖了 OpenClaw 在自动化办公、金融分析与销售增长中的广泛应用，分章节探讨了 AI Agent 赋能生产力的具体实践。具体来说，它讲解了如何通过 OpenClaw 解决“AI 只说不做”的痛点、重构日常工作流、实现 7x24 小时无人值守，同时还提供了对云端与本地部署模式的深度分析，并结合案例演示了在 Excel 自动化、研报深度复盘以及客户画像生成等场景下的商业化路径。

书中还展示了如何通过技能（Skills）扩展实现网页浏览、文档速读以及跨平台数据抓取等策略，并强调了 AI 智能体在提升运营效率、精确成本控制以及保障数据安全方面的关键作用。无论是希望摆脱繁琐碎事的职场人，还是追求高效开发的极客，都能通过本书掌握从零构建“数字龙虾”的核心技术，实现从传统创作到智能自动化的跨越。
前    言
随着 AI 2.0 时代的到来，人工智能已不再仅仅是屏幕另一端的聊天对象，而是能够深入真实工作场景、执行复杂任务的“行动派”。然而，在琳琅满目的技术概念面前，如何让 AI 真正落地，化为可操作的生产力工具，成为广大职场人与开发者共同面临的难题。本书《我的第一只数字龙虾：OpenClaw从入门到精通》旨在为读者提供一份全方位、零门槛的 AI Agent 实战指南，重点介绍OpenClaw框架如何驱动个人与企业的效率革命。

本书从“动手派”AI 的核心理念谈起，深度剖析了OpenClaw在自动化办公、金融实战、销售分析以及私人助理等多个维度的智能化应用。通过结合云端与本地化部署的灵活策略，本书详细阐述了如何为 AI 装上“手脚”——即通过技能（Skills）扩展与内存管理，实现 7x24 小时的全天候自动值守。这不仅重构了传统的工作流，更有力地推动了从“人机对话”向“智能代理”的范式转型。

本书内容从实战出发，涵盖了保姆级的环境搭建、神级插件的应用技巧以及三大高价值商业场景的深度拆解。无论你是希望利用AI实现副业变现的斜杠青年，还是渴望通过技术降本增效的企业管理者，本书都将为你提供系统化的解决方案与避坑指南。

我们坚信，未来的竞争力不取决于你是否拥有AI，而取决于你是否拥有一只“会干活的龙虾”。希望本书能成为你驾驭智能体时代的得力工具，助力你在数字浪潮中实现个人价值的指数级跃迁。

所以你看，它从头到尾都在强调同一件事：这不是一个只会聊天的 AI，它是一个真正长了“钳子”、能替你抓活儿的家伙。

场景一：打工人的终极外挂——办公文档处理
不管你是做行政、策划还是财务，微软 Office 绝对是你逃不掉的宿命。想想那个让你抓狂的月底：各个部门交上来几十个格式完全混乱的 Excel 表格，里面全是错位的数据和多余的空格。以前你得一个个单元格去清洗，绞尽脑汁写公式，最后手动拉图表。干半天眼睛都花了。
但有了龙虾，它简直就是个“Excel 噩梦终结者”。下达指令后，它能在后台瞬间完成脏数据清洗、公式生成和自动做图表。书里后面会给你看个真实的“小白案例”：行政小张以前花一整天搞定的表格汇总，用它十分钟就能全自动跑完。
文字工作它也是一把尖刀。明天要汇报还没做 PPT？输入主题，龙虾自动为你生成逻辑严密的 PPT 大纲和初稿。写报告没词儿？给个提纲，龙虾帮你调动全网资料写出全文。 最绝的是处理合同。甲方发来上百页的修改版 PDF 合同，靠肉眼找不同简直是反人类的酷刑。现在把两份合同丢给龙虾，它一秒钟就能精准标出所有极其隐蔽的差异陷阱。
场景二：你的私人“炒股小能手”——情报搜集与深度复盘
很多朋友业余时间喜欢在股市里翻腾两下，但散户最大的劣势就是信息差和精力不足。你不可能 24 小时盯着大盘。这时候，数字龙虾就摇身一变，成了你最冷酷的金融助理。
散户炒股最怕后知后觉。设置个定时任务，龙虾每天凌晨全网搜集炒股信息，剔除垃圾水文，在你早晨睁眼前生成一份专属的“开盘内参”。想研究公司又嫌财报太厚？“龙虾读年报”技能瞬间读完厚厚的 PDF，一眼看穿背后的公司底牌。有了数据，直接把行情表丢给它，让它帮你计算炒股专业指标。最狠的一招是，导入券商流水，让龙虾来复盘。它会用极其客观的数据，让你看清在股市冲动的操作中，到底交了多少惨痛的“学费”。它就是一个绝对理性、没有感情的复盘机器。

两种养虾模式：养在自家电脑（免费/隐私）vs. 养在云端（24小时在线）
模式一：本地部署——把龙虾养在自家鱼缸里
所谓的“本地部署”，通俗地说，就是让 OpenClaw 直接运行在你现有的电脑上，可以是你现在工作的这台电脑，也可以是手头其他闲置电脑。这只“龙虾”将在你的电脑上“遨游”，还能配合你解决各类问题，这正是“养虾”的乐趣所在。
核心优势：省钱与安全
完全免费
这是本地部署最大的优势。无需花费一分钱租用服务器，只要拥有一台能上网的电脑——无论是 Windows 笔记本、MacBook，还是闲置的旧台式机，都能成为 OpenClaw 的“家”。
隐私安全
所有聊天记录、处理的文件、运行的数据均存储在你自己的硬盘中。就好比在家里说的悄悄话，只有你自己知晓，完全无需担心数据泄露给第三方云服务商。
断网也能运行
   若你的 OpenClaw 配合了本地大模型（如 Ollama），即便家里断网，它依然能帮你整理本地文件、处理数据，虽无法联网查询资料，但基础功能不受影响。

核心优势：省心与全天候
7×24小时在线：
这是云端部署最大的亮点。云服务器始终保持开机状态，无论你在公司上班、地铁通勤，还是半夜躺在床上，只要有网络，就能通过手机或电脑随时呼唤你的“数字管家”，它永远在线待命。
性能稳定：
云服务器由专业团队维护，网络稳定，无需担心家里停电、断网等问题影响使用。
一键部署，上手简单：
    目前阿里云、腾讯云等主流云厂商，均提供 OpenClaw 官方镜像。这就相当于一套“精装房”，服务商已配齐所有运行环境，你只需点击几下鼠标，几分钟就能完成部署，完全无需掌握复杂代码。

所有计算任务均在云端完成，不会占用本地电脑的任何内存和 CPU，不影响电脑正常使用。

什么是API Key？——一张让你免费试用各大AI的“门票”
在之前的准备工作中，我们提到需要“申请 API Key”，不少读者看到这个英文缩写词会感到困惑，不清楚它的具体含义，也不明白为何部署OpenClaw必须用到它。
别担心，本节将为你彻底拆解这个概念，弄明白它，你就掌握了打开人工智能服务大门的关键钥匙。
通俗理解：API Key 就是你的“数字门票”
应用程序编程接口(Application Programming Interface, API)，这个术语看似专业，我们无需深究复杂的技术细节，只需记住核心作用：API是不同软件程序之间实现信息沟通、功能调用的桥梁。

而在这座沟通桥梁上，API Key（API 密钥）同时扮演着“数字身份证”和“服务门票”的双重角色。

我们可以做一个形象的比喻：把各大AI服务商（如DeepSeek、ChatGPT）看作高端的会员制俱乐部，俱乐部里的AI模型是身怀绝技的专业大师，能帮你完成写文案、编代码、做分析等各类工作。但俱乐部并非随意进出，门口有专门的身份核验环节，而API Key，就是你进入俱乐部的“专属会员卡”。

这张“会员卡”的核心作用有三点：
身份识别：API Key是一串专属的字符组合，服务商可通过它精准识别，确认调用服务的用户身份。
权限控制：API Key关联着你的账户权限，决定你能使用的AI服务类型、功能上限，区分普通试用与高级会员的服务边界。
计费凭证：若使用AI服务产生了算力消耗，服务商会依据API Key记录你的使用量，以此结算费用或扣除免费额度。
简单来说，API Key就是一串由字母和数字组成的长字符串，将它配置到OpenClaw中，OpenClaw就能凭借这串字符，代表你向各大AI服务商发起服务调用，获取对应的AI能力支持。

为什么它是“免费试用”的门票？
很多读者会有疑问：既然是高端的AI服务，使用成本会不会很高？只是想体验OpenClaw的功能，不想花费额外资金该怎么办？

好消息是，目前市面上绝大多数AI服务商，为了吸引新用户尝试，都会推出非常实惠的“新手福利”：只要完成账号注册并成功申请API Key，就能获得一定额度的免费使用权限，具体福利如下：
- DeepSeek：注册成功后即赠送一定数量的token（可理解为使用AI服务的代币），足够完成数十万文字的交互需求。
- Kimi (Moonshot AI)：新用户注册后通常赠送15元左右的使用额度，完全能满足个人测试、日常轻量使用的需求。
- OpenAI (ChatGPT)：虽政策会适时调整，但新注册并完成绑卡的用户，通常能获得一定金额的免费试用金。
这就像俱乐部为招揽客源，给每位新办卡用户赠送代金券，只要你的使用量在免费额度范围内，使用这些顶级的AI服务就是完全免费的。
这也是我们称API Key为“免费试用”门票的原因，只要合理规划使用量，无需花费一分钱，就能让OpenClaw充分调用各类AI服务，实现丰富的功能。

安全警示：像保护银行卡密码一样保护 Key
API Key虽是免费体验AI服务的“门票”，但它直接关联着你的服务商账户，包含账户的身份信息、使用额度等关键内容。若API Key不慎泄露，别有用心之人可冒充你的身份调用AI服务，直至耗尽你的免费额度，若账户绑定了支付方式，还可能产生不必要的费用。

因此，保护API Key需遵守以下**“三不”原则**：
不泄露：切勿将API Key截图发布到朋友圈、微博、公共群聊等公开平台，也不要随意告知非信任人员。
不上传：若有编写代码的需求，不要将包含API Key的代码文件上传到GitHub等公共代码仓库，避免被爬虫抓取或他人查看。
不混用：建议为不同的应用场景申请独立的API Key，例如给OpenClaw单独配置一个，其他AI工具单独配置一个。若某一个密钥泄露，只需删除该密钥即可，不会影响其他应用的正常使用。
若发现API Key可能已泄露，请立即登录对应的AI服务商开放平台，在API密钥管理页面找到该密钥，点击“删除”或“Revoke”按钮将其作废，随后重新创建新的API Key并更新到对应应用中。
至此，你已全面了解API Key的含义、作用，掌握了获取方法和安全保护要点。手握这张“AI服务门票”，OpenClaw就能充分调用各类人工智能能力，接下来，我们就正式开始动手操作，完成OpenClaw的部署与配置吧！

安全第一课：如何保护你的“门票”不被偷的建议
在上一节中，我们已经获取了通往AI世界的“门票”——应用程序编程接口密钥(Application Programming Interface Key, API Key)。这串简短的字符，既是调用各类顶级AI能力的核心凭证，也是直接关联个人账户资产的“数字银行卡”。

若这张“数字银行卡”被不法分子获取（即API Key泄露），将引发严重后果：账户内的免费使用额度会被瞬间耗尽，甚至可能因超额使用产生高额账单。更严重的是，若黑客利用泄露的Key生成违规内容，作为Key的所有者，你可能面临账号封禁，甚至需要承担相应的连带责任。
因此，在正式部署OpenClaw之前，我们必须先掌握关键的安全防护知识：学会像保护银行卡密码一样，妥善守护你的API Key。

泄露的风险：你的“门票”是如何被偷的？
做好安全防护，首先要明确泄露的风险场景。API Key的泄露，大多发生在以下看似平常的操作中：

成果分享时的疏忽。
当你在朋友圈、微博或技术交流群分享操作成果截图时，若不慎将包含API Key的代码界面一同截取，无异于将银行卡密码写在公共区域。黑客会通过专用爬虫程序，24小时扫描各类社交平台，一旦识别出API Key，会立即进行盗用。

代码上传时未做脱敏。
不少新手会将编写的代码上传至GitHub等代码托管平台，方便保存或分享。但如果直接将API Key以硬编码的方式写在代码文件中（如apiKey = "sk-xxxxxx"），并上传至公共代码仓库，会直接将Key暴露给所有访问者，这是API Key被盗的高频原因。
存储与传输时的不规范。
将API Key随手保存在桌面命名为“密码.txt”的文件中，或通过微信、QQ等社交软件将Key发送给他人，均存在极高风险。若电脑中病毒、社交账号被盗，存储或传输的API Key会同步被不法分子获取。
对于我们“养虾”用户来说其实没有这么复杂，我们主要的泄露场景就是自己主动复制泄露或者截图泄露。
防御术之一：不要给任何人明文分享API Key       
有些分享欲爆棚的朋友或者像我一样需要给读者们做教程需要截图或者录屏，这个时候要记得给API Key打码，或者事后立马删掉，自己需要用的时候重新创建一个API Key，反正创建API Key又不收费。

防御术之二：用免费API Key额度
 初期“养虾”各种模型送的免费算力已经足够体验，以后涉及到收费的采用包月形式，如表2-2所示。
表2-2 各大大模型平台新注册用户免费api key 额度
防御术之二：设置用量限额——给钱包加把锁
     除了安全存储API Key不泄露外，还可为账户设置“止损锁”——用量限额功能。目前主流的AI服务商（如OpenAI、DeepSeek），均提供了该功能，具体操作要点如下：
设置月度消费预算。
登录AI服务商的官方后台，找到“Billing”（账单）或“Usage limits”（用量限制）功能入口，设置每月最高消费金额（如5美元）。一旦账户的使用费用达到该限额，API服务会自动停止，避免产生高额超额账单。
配置消费预警阈值。
在用量限制设置界面，可同时配置消费预警线（如月度预算的60%）。当账户消费达到预警阈值时，服务商会通过注册邮箱发送提醒通知，让你及时发现账户的异常使用情况。

防御术之三：定期轮换与最小权限
做好API Key的日常防护，还需遵循定期轮换和最小权限原则，进一步降低泄露风险，具体要求如下：

避免“一钥多用”，按场景分设Key。
若你的OpenClaw需要同时调用DeepSeek、Kimi等多个AI服务商的接口，建议为每个服务商单独申请API Key；若在公司和家庭场景分别部署OpenClaw，也应各自申请独立的Key。这样即便其中一个Key泄露，也不会影响其他场景的正常使用，减少损失范围。
定期轮换Key，杜绝长期隐患。
如同定期更换银行卡密码一样，养成定期轮换API Key的习惯：每隔3-6个月，在服务商后台重新生成新的API Key，同时删除旧的Key并在对应程序中更新。该操作能有效切断可能已悄悄泄露的Key的使用权限，消除潜在风险。
发现异常立即止损，删除泄露Key。
若收到服务商的莫名扣费通知，或在后台的API调用记录中，发现非本人操作的异常调用时段（如凌晨3点的高频调用），请立即登录服务商后台，点击**删除（Revoke）**当前的API Key，这是最快、最有效的止损方式，随后重新申请新的Key并更新配置。
做好以上安全防护措施，就能有效规避API Key泄露的风险，放心地部署并使用OpenClaw，让它成为高效的工作助手，而非账户的安全隐患。下一章，我们将正式动手，搭建OpenClaw的运行环境！

那些年新手踩过的坑：网络代理、权限不够、依赖冲突
安装失败通常不是你做错了什么，而是电脑的"环境"没有说实话，比如某个工具没装、某个配置有冲突、某个网络请求超时了。
坑一：安装时卡住了，一直不动或超时
问题：运行 npm install -g openclaw 之后，屏幕一直没有变化，或者出现ETIMEDOUT、ECONNRESET、network request failed 等"超时"或"网络错误"之类的提示。
解法：我们先测试网络，
npm ping
返回 pong 说明网络正常，问题可能不在网络，翻到其它“坑”继续排查。若超时或报错，如图4-38所示，依次尝试下面三个解法：

图4-38 npm ping返回报错
清理代理残留
npm config delete proxy
npm config delete https-proxy
清理后切换国内镜像源，运行如下命令，确认输出镜像地址后再重新安装
npm config set registry https://registry.npmmirror.com
npm config get registry
坑二：报错说"没有权限"（EACCES）
问题：npm install 运行到一半，突然停下来，报了一大串红色错误，里面有"permission denied"或"EACCES"。
解法：关终端或Powershell窗口重开运行。如果关了重开还是报权限错，运行以下命令把全局安装目录改到你自己的文件夹下：
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
 
# macOS 用户：
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
 
# Windows用户：
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
 
# 修改后重新安装
npm install -g openclaw
坑三：Node.js 版本不对，装完就报奇怪的错
问题：openclaw --version 可以运行，但openclaw启动时报错，或者提示 engine not satisfied、spawn ENOENT、spawn EINVAL之类的。
解法：电脑上可能同时安装了多个 Node.js，当前终端用的是错误的那个。
nvm install --lts
nvm use --lts
nvm alias default node    # 让新终端也默认用这个版本
重新打开终端后，验证：
node --version            # 应显示 > v22.x.x
which node                # 应显示 ~/.nvm 开头的路径
坑四：openclaw命令找不到
问题：npm install -g openclaw 明明运行成功了，但输入 openclaw 却提示"command not found"或"openclaw: not found"。
解法：找到 OpenClaw 装在哪里，把路径加到运行环境下。
# 查询全局安装目录
npm prefix -g
# 示例输出：/home/yourname/.npm-global
# 确认 openclaw 在不在那里
ls "$(npm prefix -g)/bin" | grep openclaw
# 把路径加进去
# macOS 用户：
echo 'export PATH="$(npm prefix -g)/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
# Windows用户：
echo 'export PATH="$(npm prefix -g)/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
# 验证
openclaw --version
坑五：打开浏览器是白屏或"502 Bad Gateway"
问题：按照步骤安装完了，也运行了 openclaw gateway start，但浏览器打开 localhost:18789 却是白屏、空白页，或者显示"502 Bad Gateway"。
解法：
重启Gateway，一般都能解决问题
openclaw gateway restart
如果 Gateway 显示 running 但还是 502，很可能 18789 端口被另一个程序占用，我们修改openclaw端口来解决
openclaw config set gateway.port 18790

本地 vs 云端，到底选哪个？一张表帮你做决定
装完本地版，你可能会有这个疑问：折腾了这么久才装好，云端版好像更简单——到底该用哪种？
在回答这个问题之前，先理解一件关键的事：OpenClaw不是普通的聊天软件，它是一个需要 24 小时持续运行的 AI Agent。它要实时维持与消息平台的连接，要执行定时任务，要在你睡觉时继续工作。这意味着"电脑关机之后它还能不能跑"，是选择本地还是云端最核心的问题。

五个问题，帮你快速决策
不想逐条看表格？用下面五个问题快速定位你的选择：

问题 1：你需要 OpenClaw 24/7 在线吗？
想一想你准备怎么用它，只要有一条符合，强烈推荐云端部署。
接入飞书/QQ/企业微信，让它随时自动回复消息？
设置凌晨跑的定时任务（自动汇报、定时提醒）？
团队协作，同事随时可能需要找它？

问题 2：你对数据隐私的要求有多高？
涉及商业机密、客户隐私、医疗法律等敏感内容，强烈推荐本地部署。数据不离本机，零外泄风险。
普通开发者、创业者，数据已经存在云上，云端可接受，选择阿里云、腾讯云等国内合规服务商即可。
个人娱乐、学习体验，没有敏感内容，两种方案都行。

		问题 3：你的预算是多少？
有电脑，无预算，本地部署，完全免费。
¥20–50/月（可以接受基础配置的服务器费用），选择阿里云/腾讯云最低配即可。
¥50–100/月（追求稳定性，愿意为省心付费），阿里云2核4G配置，内存更充裕，运行更流畅。
不管哪种部署方式，调用 AI 大模型的API费用是额外的，两种方案都要付。

问题 4：你的技术水平如何？
零基础，从没用过命令行，云端的一键镜像更友好。阿里云/腾讯云有 OpenClaw专属镜像，几次点击就能部署完成。
开发者，熟悉 Linux / Docker / SSH，两种方案都能玩出花样。本地还能改源码、接本地模型，自由度更高。

		问题 5：你需要调用本地AI模型吗？
如果你有配置足够的设备，且想彻底告别 API费用,本地部署 + 本地模型（如Ollama + Llama/Qwen）是终极方案。优势是完全离线，不花大模型API费用，且数据100%不离机。代价就是对硬件要求较高（7B 模型建议 8GB 显存，16GB 内存），响应速度比云端 API 慢。

给龙虾装上“手脚”——技能（Skills）是个好东西
本章将揭秘OpenClaw如何从“只会聊天”进化为“能干活的助理”。与市面上多数止步于对话的AI不同，OpenClaw不仅是对话窗口，更是任务调度中枢。它以“技能”为核心，将理解力与执行力结合，让AI从“告诉你该怎么做”变为真正动手执行——从整理周报到发送邮件，一气呵成。核心就在于“技能”这一模块化能力包，为AI赋予标准化流程与可执行的“手脚”。接下来，我们将深入解读其“大脑+骨架+手脚”三层架构，探索它如何通过“技能”进化为全能助理。
普通AI只会聊天，我的龙虾为什么能干活？秘密就   在“技能”
你你是否也有这样的体验：让AI“帮我订杯咖啡”，它却只告诉你步骤；问它“今天有什么安排”，它只教你如何查日历——像个只会动嘴皮子的理论大师，从不亲自动手。但我的OpenClaw龙虾不一样。在微信上对它说：“小龙，整理上周项目周报，用Markdown格式发我邮箱”，它真的会去执行：翻找文档、提炼信息、排版、发邮件，一气呵成。为什么它能从“聊天机器人”进化为“能干活的助理”？要回答这个问题，得先搞清楚OpenClaw与普通AI大模型的本质区别，如图6-1所示。

图6-1 普通大模型与OpenClaw的区别
大脑 vs 骨架 vs 手脚
想象一下，如果把一个能干活的人拆解开来：
大模型，是大脑。它能思考、能分析、能理解你“订咖啡”这句话背后的意图。但光有大脑，它是瘫痪的——它知道该怎么做，但身体动不了。
OpenClaw，是骨架。它不负责深度思考，但它负责协调和调度。大脑下达指令后，骨架开始运作：先调用哪个器官？下一步做什么？遇到问题怎么办？
各种Skill技能包，就是手脚。查天气的手、发邮件的手、写代码的手、打开浏览器的手。
大脑 + 骨架 + 手脚 = 一支真正能支棱起来的牛马。如图6-2所示。

图6-2 大脑 vs 骨架 vs 手脚
普通AI只有大脑，所以它只能告诉你“该怎么做”。而OpenClaw有了骨架（协调调度）和手脚（技能包），所以它能直接动手把事干了。而这一切的核心，就在于那个连接“骨架”和“手脚”的关键——技能（Skills）。
Skill，就是AI的“肌肉记忆”
简单来说，技能（Skill） 就是给AI Agent准备的模块化“能力包”或“工作手册”。它包含了指令、模板乃至可执行脚本，让AI不再依赖每次重复的提示词（Prompt）。
打个比方：提示词像你每次给新人口头交代任务，而技能则像递给他一本内部《标准化作业手册》——需要什么流程、模板、脚本，他随手就能用，不用你再唠叨。

痛点：只会动嘴的AI，干不了活
“技能”的出现，是为了解决传统AI交互中几个根深蒂固的“老大难”问题：
告别“车轱辘话”：每次开启新任务，都得把同样的规则、格式、要求对AI重复一遍。这不仅烦人，还低效。
拯救“金鱼记忆”：AI的上下文窗口是有限的。如果一次性把几十页的公司规范、十几个工具的用法都塞给它，还没开始干活，它的“内存”就快满了，导致后续对话变“笨”、遗忘重要信息。
终结“薛定谔的输出”：同一个任务，今天AI给你输出表格，明天给你输出段落，风格飘忽不定，难以形成稳定、可靠的生产力。
打破“个人经验孤岛”：团队里，高手写的提示词无法有效共享，新手总得从头摸索。优秀的做事方法无法沉淀为组织的集体资产。
“技能”的诞生，正是为了把AI从“只会即时聊天”的单细胞生物，进化为“掌握十八般武艺”的专业人士。如图6-4所示。

图6-4 技能的出现，解决交互的问题
以前：每次干活，都要重新教一遍
在“技能”普及之前，我们主要依赖两种方式让AI干活：
狂堆提示词（Prompt Engineering）：在每一次对话中，把任务背景、执行步骤、输出格式事无巨细地写进提示词里。这就像每次给实习生派活，都要重新编一本一次性的“小抄”，用完就扔。
使用工具调用（Function Calling / MCP）：这给了AI“手脚”，让它能调用外部API（查天气、发邮件）。但AI依然不知道“什么时候该用这些手脚”、“用了之后怎么组合信息来生成一份报告”。它有了工具，但没有使用工具的流程和规范。
提示词是临时的口头指令，MCP/工具是零散的锤子、扳手，而技能，则是把锤子、扳手和操作手册整合在一起的“标准化作业包”。 如图6-5所示。
图6-5 狂堆提示词 VS 使用工具调用
秘密：OpenClaw的“三层功夫”
OpenClaw的“技能”之所以强大，是因为它采用了一种叫 “渐进式披露” 的精巧设计，这完美地解决了AI的“内存”（上下文窗口）问题。整个过程分三步走，如图6-6所示。
图6-6 OpeClaw的“三层功夫”
第1层：元数据（Metadata）- 只看目录
OpenClaw启动时，只会把每个技能的“名片”（名称和一句话描述）加载到AI的上下文里。这几乎不占什么“内存”，即使安装了上百个技能，AI也知道自己“会什么”。
第2层：指令（Instructions）- 按需阅读
当我在微信上说“龙虾，帮我生成上周周报”，AI会立即扫描所有技能的“名片”，匹配到名为 weekly-report-generator 的技能。随后，AI读取该技能文件夹中的核心文件 SKILL.md 并载入“内存”，从而掌握生成周报的具体步骤、格式要求和注意事项。
第3层：资源（Resources）- 随时查阅
在执行周报任务时，如果 SKILL.md 引用模板文件（如templates/report-template.md），AI会按需读取；如需统计数据，则直接运行脚本（如scripts/analyze.py），只将运行结果载入“内存”，脚本本身不占用空间。
正是这种“先看目录、再看章节、最后查附录”的按需加载机制，让OpenClaw既能掌握海量技能，又不会因“内存”过载而变得迟钝。
所以，你的AI会干活了吗？
现在你应该明白了：OpenClaw能干活，正是因为“大模型”给了它思考的大脑，“OpenClaw”骨架给了它协调的能力，而“技能”则赋予它专业的手脚和标准作业流程。
正是这种 “大脑 + 骨架 + 手脚” 的三位一体，让OpenClaw从“只会聊天”进化成“真正能支棱起来的牛马”。
我们用一句话总结这套机制的价值：如果说MCP是AI连接世界的“手脚”，那么“技能”就是AI的“工作记忆和专业训练”——它让AI不仅“想得到”，更能“做得到、做得好”。
所以，你的AI今天学会“干活”了吗？

场景三：销售信息与分析
在上一章中，我们探讨了OpenClaw如何在金融场景中帮助用户跨越信息差。本章我们将聚焦另一大高频的商业化应用场景——销售信息与客情分析。借助 OpenClaw 强大的自然语言处理与cron功能，业务人员可以轻松洞察客户真实的购买心理，揭示碎片化记录背后的商业秘密，从而实现精准的客情营销与业绩增长。
销售数据自动整理：把杂乱的客户跟进记录丢给龙虾，自动生成结构化表格
销售跟进记录通常繁杂且缺乏结构，人工清洗耗时且易遗漏线索。借助 OpenClaw 的自然语言处理能力，可轻松搭建自动化整理工作流。为避免模型输出结果混乱，开发者需使用标准化的“三段式”指令，严格约束任务目标与输出格式，从而大幅提高数据整理的准确率。
步骤1：准备原始数据。打开记事本或聊天记录，选中需要处理的混乱销售记录，按【Ctrl+C】键复制文本。如图9-1所示。

1 张代码截图经 OCR 后 ≈ 数百至数千 Token
费用 = 输入 Token 数 × 输入单价 + 输出 Token 数 × 输出单价

模型分层策略
好的成本控制不是"永远用最便宜的"，而是让每一分钱花在刀刃上。推荐按任务类型分层：
第一层：日常闲聊与快速问答 → Haiku
用户：今天适合出门吗？
用户：帮我写一句生日祝福语
用户：这个词的英文是什么？
这类任务对推理深度要求低，用 Haiku 完全够用，成本可降低 90% 以上。
第二层：常规开发与写作任务 → Sonnet
用户：帮我写一个 Python 爬虫
用户：总结这篇 3000 字的文章
用户：优化这段 SQL 查询
Sonnet 在性价比和能力之间取得了极好的平衡，是大多数团队的主力模型。
第三层：高难度任务 → Opus
用户：分析这个复杂的分布式系统架构，找出潜在瓶颈
用户：从零设计一套微服务拆分方案
用户：完成这道需要多步数学推导的题目
Opus 用于真正需要深度推理的场景，不要浪费在简单任务上。

在 OpenClaw 中配置模型路由
OpenClaw 支持在配置文件中设置默认模型，也支持在对话中动态切换：
yaml
# openclaw.config.yaml
models:
  default: claude-sonnet-4-6        # 默认使用 Sonnet
  fallback: claude-haiku-4-5        # 超出预算时降级

  - pattern: "架构|设计|分析复杂"

记忆管理：防止"话太多"导致 Token 消耗过快
为什么"话太多"会变贵
Claude 是一个无状态的 API——它本身不记得上一次对话。每次你发送消息，OpenClaw 都会把完整的历史对话一起打包发给模型，让它理解上下文。
这意味着：
第 1 轮：发送 100 Token
第 2 轮：发送 100 + 200 = 300 Token（包含第 1 轮历史）
第 3 轮：发送 100 + 200 + 300 = 600 Token
……
第 N 轮：发送前面所有轮次之和
一个持续进行的长对话，Token 消耗会呈二次方增长。这就是为什么聊到后期会越来越慢、越来越贵。
上下文窗口：龙虾的"工作记忆"
每个 Claude 模型都有上下文窗口上限（Context Window），超出后模型将无法处理更早的内容：
表10-3 不同模型的上下文窗口限度

200K Token 听起来很大，但如果你在对话中粘贴了大量代码、日志或文档，很快就会逼近上限。
四种记忆管理策略
策略一：定期开新对话（最简单）
养成习惯：每完成一个独立任务，就开一个新的对话窗口。不要把所有事情塞进同一个对话。
✅ 好习惯：每个功能模块开一个独立对话
❌ 坏习惯：一个对话从需求分析聊到上线运维
策略二：使用 /compact 命令压缩历史
OpenClaw 提供 /compact 命令，会让模型将历史对话压缩成摘要，释放上下文空间：
bash
/compact          # 压缩历史，保留关键信息
/compact --ratio 0.3   # 压缩至原来的 30%
压缩后，模型会保留关键决策、代码片段和结论，丢弃冗余的中间过程。
策略三：使用外部记忆文件（CLAUDE.md）
对于需要长期记住的信息（如项目规范、个人偏好），不要放在对话里，而是写入 CLAUDE.md：
markdown
# CLAUDE.md — 项目记忆

## 技术栈
- 后端：FastAPI + PostgreSQL
- 前端：React + TypeScript
- 部署：Docker + Nginx

## 代码规范
- 函数命名使用 snake_case
- 所有 API 接口必须有 docstring
- 禁止直接 commit 到 main 分支
每次对话启动时，OpenClaw 会自动读取 CLAUDE.md，无需重复说明背景。
策略四：只传必要内容
不要整段粘贴文件，而是只传相关部分：
bash
# ❌ 低效做法：把整个 10000 行文件丢进去
cat huge_file.py | openclaw "帮我优化"

# ✅ 高效做法：只传相关函数
sed -n '150,200p' huge_file.py | openclaw "帮我优化第 150-200 行的这个函数"

权限锁：哪些敏感操作必须经过你的授权？
为什么需要权限边界？
AI 龙虾爪子很强，但强大意味着风险。一个不小心，它可能：
删除你还没备份的文件
向错误的服务器推送代码
执行了一条你没仔细看的SQL 
DROP TABLE
发送了一封你以为只是"草稿"的邮件
OpenClaw 的权限系统设计原则是：默认安全，明确授权。
权限分级体系
OpenClaw 将操作分为四个安全等级：
等级 0：只读操作（自动允许）
读取文件、查看目录结构
搜索代码、查询文档
生成文本、分析内容
运行只读 SQL（SELECT）
等级 1：本地写操作（需一次性确认）
创建新文件
修改现有文件（有 diff 预览）
安装本地依赖包
创建本地 git 分支
等级 2：影响共享资源（需每次确认）
git push / git force push
发送 HTTP 请求到外部 API
写入数据库（INSERT / UPDATE / DELETE）
发送邮件或消息通知
等级 3：不可逆高危操作（需二次确认 + 输入确认词）
删除文件或目录（rm -rf 类操作）
DROP TABLE / DROP DATABASE
关闭或重启生产服务
修改生产环境配置
配置你的权限策略
在 settings.json 中自定义权限规则：
json

{
  "permissions": {
    "allow": [
      "Read",
      "Glob",
      "Grep",
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(npm test)"
    ],
    "deny": [
      "Bash(rm -rf*)",
      "Bash(git push --force)",
      "Bash(DROP*)"
    ],
    "confirm_required": [
      "Write",
      "Edit",
      "Bash(git push)",
      "Bash(git commit)"
    ]
  }
}


规则解读：
allow：无需询问，直接执行
deny：永远拒绝，不管用户怎么说
confirm_required：执行前展示操作详情，等待你的确认

定期自动备份
不要依赖手动备份。配置自动备份到本地或云存储：
方案 A：本地定时备份（cron）

0 2 * * * openclaw backup export --output ~/openclaw_backups/backup_$(date +\%Y\%m\%d).zip

无损升级：三步走
OpenClaw 更新可能带来配置格式变化。遵循以下步骤，确保升级不丢失任何数据：
Step 1：升级前备份
bash
# 创建带版本号的备份
openclaw --version > /tmp/current_version.txt
openclaw backup export --output ./pre_upgrade_backup.zip
echo "升级前版本：$(cat /tmp/current_version.txt)"
Step 2：执行升级
bash
# 通过包管理器升级
npm update -g openclaw
# 或
pip install --upgrade openclaw
Step 3：恢复并验证
bash
# 如果升级后配置丢失，从备份恢复
openclaw backup restore --input ./pre_upgrade_backup.zip

# 验证关键配置是否正常
openclaw config check
openclaw doctor    # 运行健康检查
从备份恢复
当你更换电脑或遭遇数据丢失时：
bash
# 1. 安装 OpenClaw
npm install -g openclaw

# 2. 恢复备份
openclaw backup restore --input ./openclaw_backup_20250101.zip

# 3. 重新配置 API Key（出于安全，Key 不会包含在备份中）
export ANTHROPIC_API_KEY="your-key-here"

# 4. 验证恢复结果
openclaw doctor
安全提醒： API Key 等敏感凭证不应该包含在备份文件中。备份恢复后需要手动重新配置密钥。
版本回滚
如果新版本出现问题，可以快速回滚：
bash
# 查看可用版本
npm view openclaw versions

# 回滚到指定版本
npm install -g openclaw@1.2.3

# 恢复升级前的备份
openclaw backup restore --input ./pre_upgrade_backup.zip
