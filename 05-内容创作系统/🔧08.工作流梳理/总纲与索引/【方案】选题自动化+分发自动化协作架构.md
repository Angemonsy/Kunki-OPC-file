## 方案A：选题自动化

### 现状痛点
- 选题bot已部署但没有主动运行，每次都是你手动去想选题
- 热点追踪skill存在但需要手动触发
- 选题评估完成后没有自动流转到下一步

### 目标状态
> 早上打开Obsidian，小林说："昨晚选题bot追到3个热点，评估完了，最强的是XXX，85分。要不要开始写？"

### 实现方式

**两条路径，可叠加使用：**

#### 路径1：Claudian本地选题（推荐先做）

不依赖飞书bot，Claudian自己用热点追踪skill完成：

```
你说"今天有什么热点"或打开Obsidian时小林主动汇报
  → Claudian 调用 /热点追踪 skill（联网搜索3天热点）
  → 用13大爆款元素评分
  → 匹配6大内容方向
  → 输出TOP 5选题清单（带评分+推荐理由）
  → 你选一个
  → 自动写入灵感点子表
  → 问你"要不要现在开始写？用哪条生产线？"
```

**落地方式**：在启动协议里加一步——每天第一次对话时，小林主动跑一次热点追踪，把结果连同周工作区状态一起汇报。

**改动量**：只改 CLAUDE.md 的启动协议，加3行逻辑。

#### 路径2：飞书选题bot定时巡逻（进阶）

OpenClaw cron定时驱动选题bot自动巡逻：

```
每天08:00 OpenClaw cron触发
  → 飞书选题bot自动搜索热点
  → 评估+评分
  → 结果发到飞书AI员工群的选题话题下
  → 你打开Obsidian时，小林通过MCP浏览器去飞书读取选题bot的最新消息
  → 整理后汇报给你
```

**落地方式**：
1. 在OpenClaw配置中给选题bot添加cron定时任务（每日08:00触发）
2. 新建一个Claudian skill叫「飞书消息同步」，打开飞书网页版→定位到选题话题→读取最新消息→整理成选题清单
3. 启动协议里增加：检查飞书是否有新选题

**改动量**：OpenClaw cron配置 + 新skill + 改启动协议。依赖MCP浏览器稳定性。

### 推荐策略

**先做路径1**（改动小、立即可用、零风险），跑顺了再叠加路径2。

路径1今天就能用，路径2需要调试cron+MCP飞书读取的稳定性。

## 方案B：分发自动化

### 现状痛点
- 文案写完后，需要手动复制到各平台
- 小红书需要重新改写、朋友圈需要重新写
- 发布流程繁琐，每次都是重复劳动

### 目标状态
> 文案定稿后，你说"分发"，自动完成：公众号推草稿箱 + 生成小红书图文内容包 + 生成X推特Thread串，全部存到vault里，你只需复制粘贴发出去。视频号/抖音/B站/YouTube走VideoForge出片单独处理。

### 实现方式

**同样两条路径：**

#### 路径1：Claudian本地分发（推荐先做）

不依赖飞书bot，Claudian直接串联现有skills：

```
文案定稿后，你说"分发"或"/分发"
  → Claudian读取当前文案文件
  → 并行执行：
     ├→ /微信公众号发布 → API推送到草稿箱
     ├→ /朋友圈文案生成 → 生成3条朋友圈文案
     └→ （可选）/小红书图文 → 生成6-9张卡片文案+标题+正文+标签
  → 所有结果追加到当前文案文件底部（或新建分发版本文件）
  → 汇报："公众号已到草稿箱，朋友圈3条文案已生成，小红书卡片已准备好。"
```

**落地方式**：新建一个「一键分发」skill，编排调度3个现有skill。

**改动量**：新建1个skill文件。

#### 路径2：飞书分发bot执行（进阶）

Claudian把文案发给飞书分发bot，让它来做平台适配：

```
你说"分发"
  → Claudian通过MCP浏览器打开飞书
  → 在分发话题下@分发bot，发送文案全文
  → 分发bot自动生成各平台版本
  → Claudian等待回复→读取→存入vault
  → 汇报结果
```

**优势**：飞书bot有独立的AGENTS.md和知识库，分发质量可能更好
**劣势**：多一层网络延迟，MCP浏览器操作可能不稳定

### 推荐策略

**先做路径1**（一个skill就搞定，现有skill直接串联，零额外依赖）。

路径2的价值在于：当你不在电脑前时，可以直接在飞书群里@分发bot做分发，不需要Claudian参与。但这是下一步的事。

## 「一键分发」Skill 设计草案

```yaml
名称: 一键分发
触发: /分发, "分发", "发布到全平台"
输入: 当前打开的文案文件（或指定文件路径）
输出:
  - 公众号草稿（API推送）
  - 小红书图文内容包（追加到文件底部）
  - X推特Thread串+金句推文（追加到文件底部）

平台范围:
  - 图文链路（本skill覆盖）：公众号 + 小红书 + X推特
  - 视频链路（不覆盖）：视频号/抖音/B站/YouTube → 用VideoForge出片

流程:
  1. 读取当前文案文件全文
  2. 确认用户要分发到哪些平台（默认：公众号+小红书+X推特全选）
  3. 并行调用：
     - /微信公众号发布 → 推送草稿箱
     - /小红书图文 → 生成标题+6-9张卡片文案+正文+话题标签
     - /推特内容转换 → 生成中文Thread串（7-12条）+单条金句
  4. 将小红书和X推特版本追加到原文件底部，用分隔线隔开
  5. 汇报完成状态，提醒视频平台走VideoForge流程

存档格式（追加到文案文件底部）:
  ---
  ## 📢 多平台分发版本
  ### 微信公众号
  ✅ 已推送草稿箱，请登录后台确认发布
  ### 小红书
  **标题**: ...
  **正文**: ...
  **卡片文案**: ...
  **话题标签**: ...
  ### X/推特
  **Thread串**: 1/n... 2/n...
  **金句推文**: ...
```

## 风险与注意事项

1. **MCP浏览器稳定性**：路径2依赖MCP操控飞书，如果浏览器卡住会阻断流程。路径1不依赖浏览器，更可靠。
2. **飞书API额度**：14个bot + cron定时 = 更多API调用，注意月度50K额度消耗。
3. **选题质量**：自动选题≠好选题，你的审批环节不能省。系统负责"海选"，你负责"终选"。
4. **分发后的数据闭环**：分发完成后应自动记录到「数据监控中心」，24h后采集数据。这是第三步的事。
