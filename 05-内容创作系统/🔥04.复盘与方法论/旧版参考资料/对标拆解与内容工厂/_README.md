## 为什么不新开一个知识库？

建议**不要新开独立知识库**，而是在当前主库 `D-内容创作/09-对标拆解与内容工厂/` 下新增这个内容工厂区。

原因：

1. **主库唯一原则**：GitHub/Obsidian 是唯一权威源，避免对标资料、选题、产品、复盘散落到另一个库里。
2. **内容创作需要上下文**：对标拆解必须和林总的用户画像、文案框架、素材库、产品管理、草稿库、数据反馈联动，放在同一库里效率最高。
3. **便于沉淀Skill**：后续每个资料包、笔记、视频、产品页的生成流程，都可以直接沉淀到本库Skill/方法论里。
4. **避免重复维护**：新开知识库会增加同步、搜索、归档、Git管理成本。

结论：

> **不新开知识库；在D-内容创作里新开内容工厂区。**

## 工作流

### Step 1：找对标

记录：

```text
账号名 / 平台 / 粉丝量 / 定位 / 主要产品 / 代表爆款 / 转化方式 / 可借鉴点 / 不能照抄点
```

### Step 2：拆爆款

拆解维度：

```text
标题钩子
封面结构
正文框架
评论区需求
商品/资料承接
用户痛点/痒点/爽点
可迁移到林总IP的角度
```

### Step 3：拆产品

拆解维度：

```text
产品名称
价格
目标人群
买单时刻
交付形式
目录结构
卖点话术
用户评价
可二创方向
版权风险
```

### Step 4：生成母稿

每个主题先生成一份母稿：

```text
主题母稿
→ 小红书图文
→ 视频号口播
→ 抖音/小红书视频
→ 付费资料包目录
→ 评论区/私域承接话术
```

### Step 5：沉淀Skill

跑通后沉淀：

```text
小红书爆款图文生成Skill
低价虚拟资料包生成Skill
视频号口播生成Skill
用户痛点痒点爽点分析Skill
对标账号拆解Skill
```

## 核心原则

1. **参考爆款结构，不复制具体内容。**
2. **借鉴产品形态，不搬运资料本体。**
3. **每条内容都要从用户痛点、痒点、爽点出发。**
4. **内容不是自嗨，必须承接用户动作：评论、私信、资料包、系统、咨询。**
5. **低价资料是需求探针，中价系统是利润品，高价咨询是壁垒品。**
