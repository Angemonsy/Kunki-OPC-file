# 常见安装报错对照表

> 本文档汇总学员在安装999课程工具时遇到的所有报错，按报错关键词分类，方便快速定位和解决。

---

## 1. spawn UNKNOWN / spawn ENOENT

**报错截图关键词**: `spawn UNKNOWN`、`spawn ENOENT`

**原因**: Windows 系统缺少 Git。Claude Code 在 Windows 上依赖 Git Bash 运行，没装 Git 就会报这个错。

**解决方案**:
1. 安装 Git：去 https://git-scm.com/downloads/win 下载安装
2. 安装过程中一路点 Next，默认选项即可
3. 安装完成后，**关闭所有 PowerShell 窗口**，重新打开
4. 输入 `git --version` 确认安装成功
5. 重启 Obsidian，再试 Claudian

**备注**: 新版一键安装脚本已自带 Git 离线安装包，会自动检测并安装。

## 2. eventTargets / AbortSignal 报错

**报错截图关键词**: `eventTargets`、`AbortSignal`、`The "signal" argument must be an instance of AbortSignal`、`The "eventTargets" argument must be an instance of EventEmitter or EventTarget`

**原因（两种可能）**:

**原因A（最常见）: Git Bash 找不到。** Claude Code 在 Windows 上依赖 Git Bash 运行，如果 Git 没装、或者装在了非默认路径（比如 `D:\Git` 而不是 `C:\Program Files\Git`），CLI 启动就崩溃，Claudian 捕获到的错误显示为 eventTargets/AbortSignal。

**原因B: Node.js 版本不兼容。** Claude Code 需要 Node.js v18 或更高版本，版本过低（v16以下）会报这个错。

**排查步骤**:

**第1步：检查 Git**
1. 打开 PowerShell，输入 `git --version`
2. 如果提示"找不到命令"→ 没装 Git，去 https://git-scm.com/downloads/win 下载安装
3. 如果 Git 已安装，输入 `where.exe git` 查看安装路径
4. 在 PowerShell 里进入知识库目录测试：
```
cd "你的知识库路径"
$env:CLAUDE_CODE_GIT_BASH_PATH="你的Git路径\bin\bash.exe"
claude -p "你好" 2>&1
```
5. 如果能回复，说明就是 Git Bash 路径问题。在 Claudian 设置 → 环境变量里加一行：
```
CLAUDE_CODE_GIT_BASH_PATH=D:\Git\bin\bash.exe
```
（把路径换成你自己的，`where.exe git` 返回的路径把 `cmd\git.exe` 换成 `bin\bash.exe`）

**第2步：检查 Node.js（如果第1步没解决）**
1. 打开 PowerShell，输入 `node -v` 查看当前版本
2. 如果低于 v18，需要升级：
   - **Windows**: 打开「控制面板 → 程序和功能」，找到 Node.js 卸载。然后去 https://nodejs.org 下载最新 LTS 版本安装
   - **Mac**: 运行 `brew install node`
3. 安装完后关闭终端重新打开，`node -v` 确认显示 v18 或更高
4. 重启 Obsidian

**备注**: 一键安装脚本中 installers 文件夹已包含 node.msi 和 Git 离线安装包，可直接双击安装。

## 3. 401 认证错误

**报错截图关键词**: `401`、`Unauthorized`、`authentication`

**原因**: Claudian 设置里的 Environment Variables 有残留配置，覆盖了正常的登录认证。

**解决方案**:
1. 打开 Obsidian → 左下角齿轮 → 左侧找到 Claudian
2. 往下滚到 Environment Variables 区域
3. **如果用的是 Claude 官方订阅（Pro/Max）**: 确保这里完全空白，一行都不填。有任何内容就全部删掉
4. **如果用的是第三方 API**: 确认 `ANTHROPIC_API_KEY` 和 `ANTHROPIC_BASE_URL` 填写正确
5. 保存设置，重启 Obsidian

**补充检查**: 打开 PowerShell/终端，输入 `claude` 回车，看能否正常进入对话。如果 CLI 也报 401，说明需要重新登录：运行 `claude login`。

**⚠️ 隐藏杀手：settings.json 残留配置**

如果 Claudian 环境变量看起来完全正确，但就是 401 或无响应（发消息后一直转圈），**很可能是 `settings.json` 文件里有残留配置在暗中覆盖**。

这个文件在 `C:\Users\你的用户名\.claude\settings.json`，Claude Code 启动时会先读它，里面的环境变量**优先级高于 Claudian 设置里填的环境变量**。

**典型症状**:
- Claudian 环境变量配置正确，但发消息无反应或报 401
- 换了 API 还是不行，好像配置没生效
- 之前用过其他中转 API（如 privnode.com），后来换了但没清理

**排查方法**: 打开 PowerShell，运行：
```
cat "$env:USERPROFILE\.claude\settings.json"
```
如果看到里面有 `ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 等字段，就是它在捣鬼。

**解决方案**: 清空 settings.json 的环境变量（保留文件结构）：
```
Set-Content "$env:USERPROFILE\.claude\settings.json" '{"env":{},"permissions":{"allow":[],"deny":[]}}'
```
然后重启 Obsidian。

**根因**: 有些学员之前跟着其他教程配过 CLI 的 settings.json，里面写了旧的 API 地址和密钥。后来在 Claudian 里改了新配置，但 settings.json 的旧配置优先级更高，导致新配置被静默覆盖。

## 4. Extra usage is required for long context requests

**报错截图关键词**: `Extra usage is required`、`long context`、`not yet available for this subscription`

**原因**: 使用的 AI 模型或订阅计划不支持长上下文。导入知识库模板后，CLAUDE.md 等文件会增加上下文长度，超出了模型限制。

**解决方案**:
- **如果用的是 Claude 官方订阅**: 把模型从 Haiku 切换到 Sonnet（Sonnet 支持长上下文）
- **如果用的是第三方 API 中转**: 联系你的中转服务商，确认是否支持长上下文，或充值升级套餐
- **临时方案**: 在 Claudian 聊天框左下角切换到支持长上下文的模型

## 5. ERR_BAD_REQUEST / 网络连接失败

**报错截图关键词**: `ERR_BAD_REQUEST`、`ETIMEDOUT`、`ECONNREFUSED`、`fetch failed`

**原因**: 网络问题，通常是没开梯子（VPN/代理）或代理配置不正确。

**解决方案**:
1. 确认梯子已开启且正常工作（浏览器能打开 Google）
2. 打开 PowerShell，设置代理后重试：
```
$env:HTTPS_PROXY="http://127.0.0.1:7890"
$env:HTTP_PROXY="http://127.0.0.1:7890"
```
3. 端口号 `7890` 要换成你自己梯子的端口（Clash 默认7890，V2Ray 默认1080）
4. 查看梯子端口的方法：打开你的代理软件，在设置里找「HTTP 端口」或「监听端口」

**备注**: 一键安装脚本会自动检测本地代理端口（7890/7897/7898/1080/1087/8080），如果检测到会自动配置。

## 6. winget 不可用 / winget 卡住

**报错截图关键词**: `winget: command not found`、脚本卡在某一步不动

**原因**:
- **winget 不存在**: Windows 10 老版本没有预装 winget
- **winget 卡住**: 首次运行 winget 会弹出 msstore 源协议确认，但脚本把输出重定向了看不到提示

**解决方案**:
- **winget 不存在**: 去微软应用商店搜索「应用安装程序」安装，或直接用安装包里 installers 文件夹的离线安装包手动安装
- **winget 卡住**: 先单独打开 PowerShell，运行一次 `winget list --accept-source-agreements`，输入 Y 同意协议，然后重新运行脚本

**备注**: 新版脚本已给所有 winget 命令加上 `--accept-source-agreements` 参数，不会再卡住。

## 7. Claude Code 安装失败 / claude 命令找不到

**报错截图关键词**: `claude: command not found`、`claude 不是内部或外部命令`

**原因**: Claude Code 没装上，或装了但环境变量没生效。

**解决方案**:
1. 先确认是否真的没装：
   - Windows: 检查 `C:\Users\你的用户名\.local\bin\claude.exe` 是否存在
   - Mac: 运行 `which claude`
2. 如果文件存在但命令找不到，说明环境变量没生效：**关闭所有终端窗口，重新打开再试**。还不行就重启电脑
3. 如果确实没安装成功，手动安装：
   - 打开 PowerShell/终端
   - 设置代理（见第5条）
   - 运行 `npm install -g @anthropic-ai/claude-code`
   - 全程保持梯子开着

## 8. Playwright MCP 没有 / 眼睛图标问题

**报错截图关键词**: Claudian 设置里看不到 Playwright

**原因**: 脚本运行时 Claude Code 还没装好，跳过了 Playwright MCP 安装步骤；或者装了但没在 Claudian 里启用。

**解决方案**:
1. **手动添加 Playwright MCP**: 打开 PowerShell/终端，运行：
```
claude mcp add playwright -s user -- npx @playwright/mcp@latest
```
2. **在 Claudian 里启用**: 打开 Obsidian 设置 → Claudian → 找到 MCP Servers 区域 → 确认 playwright 旁边的眼睛图标是**睁开**状态（点一下切换）
3. 重启 Obsidian

## 9. BRAT 安装 Claudian 失败

**报错截图关键词**: BRAT 报错、插件安装失败、`Failed to fetch`

**原因**: 网络问题导致 BRAT 无法从 GitHub 下载 Claudian 插件。

**解决方案**:
1. 确认梯子已开启
2. 如果用了一键安装脚本，Claudian 插件已经在安装包里了，不需要通过 BRAT 安装
3. 手动安装方法：把安装包里 `plugins/claudian` 文件夹整个复制到你的知识库路径下的 `.obsidian/plugins/` 文件夹里，重启 Obsidian

## 10. Visual Studio Installer 报错

**报错截图关键词**: Visual Studio Installer、`npm ERR! gyp ERR!`

**原因**: 某些 npm 包需要编译原生模块，依赖 Visual Studio 的 C++ 编译工具。

**解决方案**:
- 这个报错通常不影响 Claude Code 的正常使用，可以忽略
- 如果确实影响了功能，打开 PowerShell 以管理员身份运行：
```
npm install -g windows-build-tools
```

## 11. 403 forbidden / Request not allowed（Claudian 插件）

**报错截图关键词**: `403`、`forbidden`、`Request not allowed`、`Failed to authenticate`

**原因**: Claudian 插件调用 Claude Code 时没走代理。梯子默认只代理浏览器流量，Obsidian 插件和 PowerShell 不会自动走代理。交互模式 `claude` 可能碰巧在设过代理的终端里能用，但 Claudian 插件没有代理就连不上，报 403。

**解决方案**:

**方法1：在 Claudian 环境变量里加代理（推荐）**
1. 打开 Obsidian → 设置 → Claudian → 往下找到「环境」标签页 → 「自定义变量」区域
2. 加入以下两行（端口号换成你自己梯子的，常见端口：Clash 7890、CokePLUS 7897、V2Ray 1080）：
```
HTTPS_PROXY=http://127.0.0.1:7897
HTTP_PROXY=http://127.0.0.1:7897
```
3. 保存，重启 Obsidian
4. 如果还报「Not logged in」，在 PowerShell 里重新登录（同样要先设代理）：
```
$env:HTTPS_PROXY="http://127.0.0.1:7897"
$env:HTTP_PROXY="http://127.0.0.1:7897"
claude /login
```

**方法2：开启梯子的 TUN 模式（一劳永逸）**
1. 打开你的代理软件设置，找到「TUN 模式」开关，打开
2. TUN 模式会让所有软件自动走代理，不用手动配环境变量
3. 开启后重启 Obsidian 即可

**如何确认是不是代理问题？** 在 PowerShell 里运行：
```
$env:HTTPS_PROXY="http://127.0.0.1:你的端口"
$env:HTTP_PROXY="http://127.0.0.1:你的端口"
claude -p "你好"
```
如果设了代理后能正常回复，就确认是代理问题，按上面方法配置即可。

**注意**: 如果用的是 Claude Max 官方订阅，环境变量里只填代理，不要填 ANTHROPIC_API_KEY 等变量，否则会覆盖登录认证导致报错。

## 12. authentication_failed / Not logged in（CLI 路径用 cli.js 的用户）

**报错截图关键词**: `authentication_failed`、`Not logged in`、`Please run /login`

**原因**: 用 npm 安装的 Claude Code，CLI 路径填的是 `cli.js`（而不是 `claude.exe`），Claudian 无法自动找到 `.claude` 配置目录（里面存着登录凭证）。常见于：
- 之前配过第三方 API 环境变量，清掉后自动检测被打乱
- 用户名是 Administrator 或其他非标准路径
- 同一台电脑上装过多个版本的 Claude Code

**解决方案**:
1. CLI 路径填 cli.js 的完整路径（如 `C:\Users\Administrator\AppData\Roaming\npm\node_modules\@anthropic-ai\claude-code\cli.js`）
2. 自定义变量里加一行，指定配置目录：
```
CLAUDE_CONFIG_DIR=C:\Users\你的用户名\.claude
```
3. 把「你的用户名」换成实际的 Windows 用户名（打开 PowerShell 输入 `echo $env:USERNAME` 可以看到）
4. 保存，重启 Obsidian

**注意**: 两个都要填——CLI 路径告诉 Claudian 去哪里运行 Claude Code，CLAUDE_CONFIG_DIR 告诉它去哪里找登录凭证。缺一个都会报错。

## 13. spawn EINVAL（CLI 路径填了 .cmd 文件）

**报错截图关键词**: `spawn EINVAL`

**原因**: Claudian 的 Claude CLI 路径填了 `claude.cmd`，Windows 下 spawn 不支持直接执行 `.cmd` 文件。

**解决方案**:
1. 打开 PowerShell，输入 `where.exe claude`，找到 `.exe` 结尾的路径
2. 把 Claudian 设置里的 CLI 路径改成 `claude.exe` 的路径（如 `C:\Users\你的用户名\.local\bin\claude.exe`）
3. 如果只有 npm 安装的版本（没有 .exe），填 `cli.js` 的路径：`C:\Users\你的用户名\AppData\Roaming\npm\node_modules\@anthropic-ai\claude-code\cli.js`
4. **不要填** `claude.cmd`

## 14. model not exist / no access（模型不可用）

**报错截图关键词**: `issue with the selected model`、`may not exist`、`may not have access`

**原因**: Claudian 选择的模型名和你的订阅等级不匹配。常见情况：
- 选了 Opus 但只有 Pro 订阅（Opus 需要 Max）
- 插件版本较旧，发了一个错误的模型名给 API
- 第三方 API 不支持你选的模型

**解决方案**:
1. 点 Claudian 聊天框底部的**模型选择器**，换一个模型试试（比如 Sonnet 或 Haiku）
2. 如果所有模型都不行，更新 Claudian 插件：设置 → BRAT → Check for updates
3. 如果用第三方 API，确认你的 API 提供商支持哪些模型，在环境变量里用 `ANTHROPIC_MODEL=支持的模型名` 指定

## 15. Sonnet 1M 开关导致 403

**报错截图关键词**: `403`、`forbidden`（但 Claude Code 交互模式正常）

**原因**: Claudian 设置里开了「启用具有 1M 上下文窗口的 Sonnet」，这个功能需要 Claude Max 订阅（$100/月）。Pro 订阅或第三方 API 没有这个权限。

**解决方案**:
1. 打开 Obsidian → 设置 → Claudian → 高级
2. 找到「启用具有 1M 上下文窗口的 Sonnet」，**关掉**这个开关
3. 保存，重新发消息试试

**如何区分**: 如果 PowerShell 里 `claude` 交互模式能正常聊天，但 Claudian 报 403，先检查这个开关。

## 16. Claude Code 多版本冲突

**报错截图关键词**: 版本号不对、升级后还是旧版本、行为不一致

**原因**: 同一台电脑上通过 winget 和 npm 各装了一个 Claude Code，系统 PATH 里 winget 版本排在前面，优先被调用。即使用 npm 升级了最新版，实际运行的还是 winget 的旧版本。

**排查方法**: 打开 PowerShell，输入 `where.exe claude`，如果出现多个路径就是有冲突：
```
C:\Users\...\WinGet\...\claude.exe      ← winget 装的
C:\Users\...\AppData\Roaming\npm\claude  ← npm 装的
```

**解决方案（二选一）**:
- **保留 winget 版本（推荐）**: 卸掉 npm 版本 `npm uninstall -g @anthropic-ai/claude-code`，然后用 winget 升级 `winget upgrade Anthropic.ClaudeCode`
- **保留 npm 版本**: 卸掉 winget 版本 `winget uninstall Anthropic.ClaudeCode`，Claudian CLI 路径填 npm 的 cli.js 路径

卸完后关闭所有终端重新打开，`where.exe claude` 确认只剩一个路径。

## 17. Credit balance is too low（Claudian 报余额不足）

**报错截图关键词**: `Credit balance is too low`

**原因**: 系统环境变量中残留了旧的 `ANTHROPIC_API_KEY`（余额为$0）。Claude Code 的 `-p`（print）模式会优先使用环境变量里的 API Key，而不是 Max 订阅认证。Claudian 底层就是用 `-p` 模式调用的，所以报余额不足。交互模式（直接运行 `claude`）不受影响，因为它走 OAuth 认证。

**典型症状**:
- Claudian 发消息报 "Credit balance is too low"
- PowerShell 里 `claude` 交互模式正常聊天
- PowerShell 里 `claude -p "你好"` 报同样的错

**排查方法**:
1. 打开 PowerShell，运行 `claude auth status`
2. 查看输出中的 `apiKeySource` 字段
3. 如果显示 `"apiKeySource": "ANTHROPIC_API_KEY"`，说明存在残留的 API Key 在覆盖订阅认证

**解决方案**:
1. 运行 `echo $env:ANTHROPIC_API_KEY` 确认存在旧 Key
2. 删除它：
```
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", $null, "User")
```
3. **新开一个 PowerShell 窗口**（旧窗口的环境变量不会刷新）
4. 运行 `claude -p "你好"` 验证正常
5. 重启 Obsidian，Claudian 恢复正常

**根因**: 学员之前跟着其他教程在系统环境变量里配过 API Key，后来订阅了 Claude Max 但忘了清理旧的环境变量。环境变量的优先级高于 OAuth 登录认证，导致 `-p` 模式始终走旧 Key。

## 18. Claudian 插件加载失败 / community-plugins.json 自动移除

**报错截图关键词**: 插件无法启用、`community-plugins.json` 中 `"claudian"` 自动消失、插件面板加载失败

**原因**: `.claude/claudian-settings.json` 中的 `systemPrompt` 字段包含未转义的 ASCII 双引号 `"`，导致 JSON 解析失败。插件 `onload()` 崩溃后，Obsidian 自动将其从启用列表中移除。

**典型症状**:
- 手动把 `"claudian"` 加到 `community-plugins.json`，重启后自动消失
- 插件文件夹完整但无法启用
- 形成「修复→崩溃→还原」死循环

**排查方法**:
打开 PowerShell，进入知识库目录，逐一校验 JSON 文件：
```
node -e "require('.claude/settings.json'); console.log('OK')"
node -e "require('.claude/mcp.json'); console.log('OK')"
node -e "require('.claude/claudian-settings.json'); console.log('OK')"
```
哪个报 `SyntaxError` 就是哪个损坏了。

**解决方案**:
1. **完全关闭 Obsidian**
2. 用文本编辑器打开报错的 JSON 文件，找到未转义的双引号，改为 `\"`
   - 常见损坏位置：`systemPrompt` 字段中的中文引用，如 `说"读取进度"` 应改为 `说\"读取进度\"`
3. 用上面的 `node -e` 命令验证修复后显示 `OK`
4. 将 `"claudian"` 重新加回 `.obsidian/community-plugins.json`
5. 重新打开 Obsidian

**根因**: 用户手动编辑了配置文件，或旧版插件写入时未正确 `JSON.stringify`，导致长文本字段中的双引号未转义。

**预防**: 不要手动编辑 `.claude/` 下的 JSON 文件，通过 Claudian 插件 UI 修改设置。

**通用规律**: 当 `community-plugins.json` 中某插件条目重启后**自动消失**，说明该插件的 `onload()` 抛出了未捕获异常。真正的问题不在 `community-plugins.json`，而在插件依赖的配置文件或初始化逻辑。

## 19. Claudian 插件加载失败 / .claude 文件夹 BOM 污染

**报错截图关键词**: 插件无法启用、Obsidian Developer Console 显示 `failed to read JSON`、`SyntaxError: Unexpected token '﻿'`

**原因**: `.claude/` 目录下的 JSON 文件（`claudian-settings.json`、`settings.json`、`mcp.json` 等）开头被写入了 BOM（Byte Order Mark，`U+FEFF`）隐藏字符。`JSON.parse()` 不认 BOM，解析直接报错，插件 `onload()` 崩溃。

**典型症状**:
- Claudian 插件无法加载，但插件文件夹完整
- Obsidian Developer Console（Ctrl+Shift+I）显示 `Unexpected token '﻿'` 错误
- 把 `.claude` 文件夹剪切出去再粘贴回来，插件就能用了（因为 Obsidian 重新读取了文件，清除了缓存的错误状态）
- 使用安装包/模板导入知识库后出现

**BOM 来源**: 安装包中的 JSON 文件在打包时被编辑器（如 VS Code、记事本）保存为 UTF-8 with BOM 格式，或 BRAT 插件更新时引入。

**排查方法**:
打开 PowerShell，检查文件是否含 BOM：
```
$c = [System.IO.File]::ReadAllText("D:\ObsidianVaults\MyVault\.claude\claudian-settings.json")
if ($c.StartsWith([char]0xFEFF)) { Write-Host "有BOM！" } else { Write-Host "无BOM" }
```

**解决方案**:
1. **完全关闭 Obsidian**
2. 运行以下命令，批量清除 `.claude/` 和 `.obsidian/plugins/` 下所有 JSON 文件的 BOM：
```
Get-ChildItem "你的知识库路径\.claude" -Recurse -Filter "*.json" -Force | ForEach-Object { $c = [System.IO.File]::ReadAllText($_.FullName); if ($c.StartsWith([char]0xFEFF)) { [System.IO.File]::WriteAllText($_.FullName, $c.TrimStart([char]0xFEFF), [System.Text.UTF8Encoding]::new($false)); Write-Host "Fixed: $($_.FullName)" } }
```
```
Get-ChildItem "你的知识库路径\.obsidian\plugins" -Recurse -Filter "*.json" -Force | ForEach-Object { $c = [System.IO.File]::ReadAllText($_.FullName); if ($c.StartsWith([char]0xFEFF)) { [System.IO.File]::WriteAllText($_.FullName, $c.TrimStart([char]0xFEFF), [System.Text.UTF8Encoding]::new($false)); Write-Host "Fixed: $($_.FullName)" } }
```
3. 重新打开 Obsidian

**如果清完BOM重启还是不行**：把 `.claude` 文件夹剪切到桌面 → 打开 Obsidian（此时没有 `.claude`，插件会创建默认配置）→ 关闭 Obsidian → 把剪切出去的 `.claude` 粘贴回来覆盖 → 再打开 Obsidian。这个操作的本质是强制 Obsidian 清除缓存的错误状态。

**与第18条的区别**: 第18条是 JSON 内容语法错误（未转义引号），粘贴回来还是错的；本条是文件开头多了隐藏字符，内容本身正确，清除 BOM 或强制重新读取即可恢复。

## 20. Claudian 插件加载失败 / Mac 文件权限不足（EACCES）

**报错截图关键词**: `EACCES: permission denied, mkdir '/.../.claude/sessions'`、`Plugin failure: claudian`

**原因**: `.claude` 文件夹缺少写入权限，Claudian 启动时需要创建 `sessions` 目录，权限不足导致 `onload()` 崩溃。

**典型症状**:
- Obsidian 开发者控制台（Cmd+Option+I）显示 `EACCES: permission denied`
- 插件文件完整、JSON 无损坏、无 BOM，但就是加载失败
- 仅 Mac 用户出现

**原因分析**: 安装包解压后文件权限丢失，Mac 上解压出来的 `.claude` 目录及文件可能只有只读权限（`rw-r--r--`），没有写和执行权限。

**解决方案**:
打开终端（Terminal），运行：
```
chmod -R 755 "知识库路径/.claude"
```
把"知识库路径"换成实际路径，如：
```
chmod -R 755 "/Users/iamrotor/Documents/我的知识库/.claude"
```
然后重启 Obsidian。

**预防**: Mac 用户安装完知识库后，建议统一执行一次权限修复命令。可加入安装手册的"Mac 安装后检查"步骤中。

## 快速排查流程

遇到问题时，按这个顺序检查：

1. **梯子开了吗？** → 没开就开，开了换个节点试试
2. **Node.js 版本对吗？** → `node -v`，要 v18 或更高
3. **Git 装了吗？**（Windows）→ `git --version`
4. **Claude Code 装了吗？** → `claude --version`
5. **Environment Variables 干净吗？** → Claudian 设置里检查
6. **settings.json 有残留吗？** → `cat "$env:USERPROFILE\.claude\settings.json"` 看有没有旧的 API 配置
7. **系统环境变量有残留 API Key 吗？** → `echo $env:ANTHROPIC_API_KEY`，有值就删掉（见第17条）
8. **重启了吗？** → 关掉 Obsidian 和所有终端，重新打开

以上都没问题还是报错 → 截图发群里，描述你做了什么、报了什么错。
