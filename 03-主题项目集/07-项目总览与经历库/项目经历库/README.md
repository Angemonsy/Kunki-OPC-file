# 06-项目经历库

> 这个区专门存放林总的「项目经历 / 校园经历 / 商业合作 / 进行中项目」。
> 它不是单纯的内容创作区，而是个人履历、简历面试、商业IP、内容素材、项目推进的共同底层资产库。

## 一、为什么单独建这个区

之前知识库里已经有：

- `D-内容创作/07-项目管理/`：更偏内容生产流程中的项目管理；
- `E-产出交付/05-合作管理/`：更偏合作结果、客户运营、成交交付；
- `projects/`：偏长期放养项目工具自动生成的项目目录。

但林总接下来会持续补充：

1. 即将推进的新项目；
2. 过去做过的校园项目、竞赛项目、科研项目；
3. 商业合作、AI项目、线下资源项目；
4. 可用于简历、面试、个人履历、申请材料、IP内容的真实故事。

这些内容既不是单纯文案，也不是单纯任务管理，所以单独放在 `C-记忆核心/06-项目经历库/`，作为长期个人上下文的一部分。

一句话：

> 项目经历库 = 林总真实经历的结构化资产库。

## 二、目录结构

```text
06-项目经历库/
├── 00-项目总览台账/          # 所有项目的一张总表，方便检索和调用
├── 01-进行中项目/            # 现在正在推进、需要跟进的项目
├── 02-过往项目/              # 已经完成或阶段性结束的项目
├── 03-校园经历/              # 校园组织、竞赛、科研、活动、课程项目等
├── 04-商业项目与合作/        # 明安科技、OPC、BNI、智能体、SaaS、分销等商业相关项目
├── 05-简历面试素材/          # STAR案例、项目亮点、面试话术、申请材料素材
├── 06-内容转化素材/          # 从项目中提炼出来的选题、故事、金句、系列内容
└── 99-归档/                  # 暂时不用但需要保留的旧项目资料
```

## 三、每个项目建议用统一模板

每个项目尽量单独建一个 `.md` 文件，文件名建议：

```text
YYYY-MM-项目名称.md
```

例如：

```text
2026-05-OPC线下资源共创项目.md
2025-11-亚太AI大赛项目.md
2024-科研SCI二区论文项目.md
```

## 四、项目记录最小字段

每个项目至少记录这些内容：

```text
项目名称：
项目时间：
项目状态：进行中 / 已完成 / 暂停 / 归档
项目类型：校园 / 科研 / 竞赛 / 商业 / 内容 / 产品 / 合作 / 其他
我的角色：
项目背景：
核心目标：
关键动作：
最终结果：
可量化成果：
我学到了什么：
可用于简历的一句话：
可用于面试的STAR故事：
可转化成内容的选题：
相关资料链接/文件：
下一步动作：
```

## 五、和其他区的关系

- 如果项目还在推进，放 `01-进行中项目/`；
- 如果项目已经结束，放 `02-过往项目/` 或 `03-校园经历/`；
- 如果是商业合作项目，同时可以在 `E-产出交付/05-合作管理/` 保存合作记录，但这里保存「个人经历视角」；
- 如果项目沉淀出文案选题，再复制/转化到 `D-内容创作/02-选题决策/` 或 `D-内容创作/08-草稿库/`；
- 如果项目最终形成已发布内容，再归档到 `E-产出交付/01-已发文案/`。

## 六、使用原则

1. 先记录事实，不急着包装。
2. 先把项目讲清楚，再提炼简历和内容。
3. 一个项目可以同时服务三件事：履历、面试、内容。
4. 进行中项目要写「下一步动作」，避免变成死资料。
5. 过往项目要写「我做了什么」和「结果是什么」，方便后续做简历。
