# AI员工启动

AI员工角色加载器。每个窗口新对话时调用，一键加载角色卡+记忆+公告板，让AI知道自己是谁、该做什么。

触发方式：`/启动 角色名` 或用户说"你是XX"
支持的角色名：内容工厂、营销获客、产品交付、数据参谋、团队管家、系统研发

## 执行流程

### 第1步：识别角色

从用户输入中提取角色名。支持以下匹配：

| 用户可能说的 | 匹配角色 |
|-------------|---------|
| 内容工厂 / 内容 / 写文案 / 写文章 / 选题 | 内容工厂 |
| 营销获客 / 营销 / 分发 / 发布 / 引流 / 朋友圈 | 营销获客 |
| 产品交付 / 交付 / 课程 / 直播 / 手册 | 产品交付 |
| 数据参谋 / 数据 / 复盘 / 分析 / 对标 | 数据参谋 |
| 团队管家 / 团队 / 招聘 / HR / 薪资 / 提成 | 团队管家 |
| 系统研发 / 研发 / 开发 / 代码 / bot / OpenClaw | 系统研发 |

如果无法识别，列出6个角色让用户选择。

### 第2步：加载角色卡

读取 `02.领域/1.团队管理/📋05.AI员工/角色卡/{角色名}.md`

从角色卡中获取：
- 身份定位
- 工作边界
- 可用Skills清单
- 输出规范

### 第3步：加载记忆系统（三文件）

依次读取 `02.领域/1.团队管理/📋05.AI员工/记忆/{角色名}/` 下的三个文件：

1. **ROLE.md**（角色定义）：职责范围、行为准则、知识文档路径
2. **MEMORY.md**（经验记忆）：积累的经验、踩坑记录、老板的偏好
3. **STATUS.md**（当前状态）：进行中的事务、待办、最近动作

⚠️ 三个文件必须全部读取，不能跳过。ROLE.md定义你是谁，MEMORY.md是你的长期经验，STATUS.md是你的工作台。

### 第4步：加载启动必读文件

按角色卡中"启动必读"表格，**逐个读取**所有必读文件。这些文件提供该角色工作所需的完整上下文。

⚠️ 必须实际读取每个文件内容，不能跳过。这是角色能正常工作的基础。

### 第5步：扫描公告板

读取 `02.领域/1.团队管理/📋05.AI员工/公告板.md`

检查"待处理"区有没有发给自己的消息（`→ @{角色名}`）。有的话告知用户。

### 第6步：就绪汇报

用简短的语气汇报：

```
✅ {角色名}已就绪

上次进度：{从记忆文件提取}
公告板：{有无待处理消息}

有什么要做的？
```

## 收尾协议（每次对话结束前必须执行，不可跳过）

每次对话结束前，该角色必须执行：

1. **更新STATUS.md**：把本次对话中的进展、新待办、状态变化写入 `02.领域/1.团队管理/📋05.AI员工/记忆/{角色名}/STATUS.md`
2. **追加MEMORY.md**（如有）：本次对话中发现的新经验、踩坑记录、老板的偏好反馈，追加到 `02.领域/1.团队管理/📋05.AI员工/记忆/{角色名}/MEMORY.md`
3. **公告板**：有跨窗口价值的信息写入 `02.领域/1.团队管理/📋05.AI员工/公告板.md`

⚠️ STATUS.md每次必更新，MEMORY.md有新经验才追加，不要等老板提醒。这是你的长期记忆，主动维护。

## 自动角色识别（兜底）

如果用户没有调用本skill就直接开始说话（比如直接说"帮我写篇文案"），AI应该：
1. 根据用户意图判断属于哪个角色
2. 自动执行本skill的加载流程
3. 加载完毕后再回应用户的具体需求

这样即使用户忘记打 /启动，也不会裸奔。
