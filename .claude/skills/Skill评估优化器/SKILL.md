# Skill 评估优化器

> 对vault中的skill进行系统性评估和优化：触发准确率测试、质量基准测试、描述调优、冲突检测。帮你搞清楚每个skill到底好不好用、该不该触发、有没有跟别的skill打架。

## 触发场景

当用户需要评估skill质量、优化skill触发、检测skill冲突、测试skill表现时自动调用。

**关键词**：评估skill、优化skill、skill测试、skill评估、触发测试、触发冲突、skill打架、skill质量、检查skill、skill体检、skill诊断、测一下skill、skill好不好用、skill准不准、优化触发、调优skill、skill冲突、技能评估、技能优化、技能测试、技能冲突、skill评分、skill基准测试

**快速启动**：用户说"帮我评估一下skill"或"检查skill有没有冲突"即可启动。

## 四大功能模块

### 模块A：触发准确率评估

**目标**：测试一个skill的描述，是否能让模型在该触发时触发、不该触发时不触发。

**流程**：

1. **读取目标skill**：Read SKILL.md，提取触发场景、关键词、不触发场景
2. **自动生成测试查询**（各10条）：
   - **应触发组**：模拟用户真实说法，覆盖关键词变体、口语化表达、模糊边界
   - **不应触发组**：设计容易混淆的近似查询，测试是否会误触发
3. **展示测试集给用户确认**：列出20条查询，用户可调整
4. **执行测试**：对每条查询，分析当前所有skill的描述，判断模型会触发哪个skill
5. **输出评分卡**：

```
触发准确率评估 - [skill名]
━━━━━━━━━━━━━━━━━━━━━━━
应触发（10条）：✅ 8/10（80%）
  ❌ "帮我看看这个选题行不行" → 误触发: 爆款内容选题策划师
  ❌ "分析一下选题" → 误触发: 爆款内容选题策划师

不应触发（10条）：✅ 9/10（90%）
  ❌ "帮我写个标题" → 误触发了本skill

综合准确率：85%
建议：描述中增加"⚠️ 不触发场景"段落，明确区分边界
```

### 模块B：描述调优

**目标**：基于触发测试结果，自动优化skill描述，提升触发准确率。

**流程**：

1. 基于模块A的测试结果，定位问题：
   - 漏触发 → 关键词覆盖不足
   - 误触发 → 描述边界不清晰，缺少"不触发场景"
   - 与其他skill冲突 → 需要互相补充排斥规则
2. **生成优化版描述**：
   - 补充缺失的关键词变体
   - 增加"⚠️ 不触发场景"段落
   - 在冲突skill双方都加排斥说明
3. **对比展示**：新旧描述并排对比，标注改了什么
4. **用户确认后写入**：Edit更新SKILL.md
5. **回归测试**：用同一测试集重新跑一遍，对比优化前后的准确率

### 模块C：质量基准测试

**目标**：测试一个skill在实际任务上的表现质量。

**流程**：

1. **读取目标skill**，理解它的核心功能和输出要求
2. **设计测试用例**（3-5个），覆盖：
   - 典型场景（最常见的使用方式）
   - 边界场景（输入格式不标准、内容很短/很长）
   - 压力场景（复杂输入、多条件组合）
3. **展示测试方案给用户确认**
4. **用subagent并行执行测试**：
   - 每个测试用例启动一个独立subagent
   - subagent加载skill后执行任务，记录输出
   - 记录token用量和耗时
5. **输出基准报告**：

```
质量基准测试 - [skill名]
━━━━━━━━━━━━━━━━━━━━━━━
测试用例      通过   耗时    tokens
典型-短文案    ✅    45s    3200
典型-长文案    ✅    82s    5800
边界-无标题    ❌    30s    2100  ← 缺少标题时直接跳过了
压力-混合语言  ✅    65s    4500

通过率：3/4（75%）
主要问题：输入缺少标题时skill没有容错处理
建议：在skill中增加"输入不完整时的默认行为"说明
```

### 模块D：全局冲突扫描

**目标**：扫描所有skill，找出关键词重叠、触发条件冲突的skill对。

**流程**：

1. **读取所有skill的SKILL.md**，提取：
   - 触发关键词列表
   - 触发场景描述
   - 不触发场景（如果有）
2. **交叉比对**：
   - 关键词完全重叠 → 高风险冲突
   - 关键词部分重叠 → 中风险冲突
   - 场景描述语义相似 → 低风险冲突
3. **输出冲突报告**：

```
Skill冲突扫描报告
━━━━━━━━━━━━━━━━━
🔴 高风险冲突（关键词完全重叠）：
  选题匹配爆款模板 ↔ 选题匹配爆款模板（重复skill！）

🟡 中风险冲突（关键词部分重叠）：
  爆款复盘分析 ↔ 内容复盘
    重叠词：复盘、分析爆款、数据分析
    建议：在两个skill中互相标注不触发场景

  热点分析 ↔ 热点追踪
    重叠词：热点
    建议：热点分析=深挖单个热点，热点追踪=扫描式发现

  选题生成 ↔ 爆款内容选题策划师
    重叠词：选题
    建议：已有区分但可强化

🟢 低风险（语义相似但已做区分）：
  教知识文案 ↔ 聊观点文案 ↔ 讲故事文案
    状态：已有类型路由机制，无需处理

共扫描 52 个skill，发现 1 个高风险、3 个中风险、2 个低风险
```

4. **可选**：对中/高风险冲突自动生成修复方案

## 执行入口

用户可以用以下方式启动：

| 说法 | 执行模块 |
|------|---------|
| "评估一下选题生成这个skill" | A+B（触发测试+质量测试） |
| "skill有没有冲突" | D（全局冲突扫描） |
| "优化一下这个skill的触发" | A+B（测试+调优） |
| "全面评估所有skill" | D先扫冲突，再对高风险的逐个跑A |
| "这两个skill会不会打架" | A（对两个skill分别测触发） |

## 技术实现

### 触发判断逻辑

判断"用户说X时会触发哪个skill"的方法：

```python
# 1. 读取所有skill的描述
# 2. 对每条测试查询，模拟匹配：
#    - 关键词精确匹配（权重最高）
#    - 触发场景语义匹配（权重中）
#    - 不触发场景排斥（一票否决）
# 3. 输出最可能触发的skill及置信度
```

实际执行时用自然语言推理：读完所有相关skill的描述后，对测试查询做判断。

### 并行测试（模块C）

```
用 Agent subagent 并行跑测试：
- 每个subagent独立加载skill
- 执行一个测试用例
- 返回：通过/失败 + 输出内容 + token用量
- 主agent汇总结果
```

### 关键词提取与比对（模块D）

```python
import os, re

skills_base = '.claude/skills'
keyword_map = {}  # {skill_name: set(keywords)}

for d in os.listdir(skills_base):
    skill_file = os.path.join(skills_base, d, 'SKILL.md')
    if not os.path.isfile(skill_file):
        continue
    with open(skill_file, 'r', encoding='utf-8') as f:
        content = f.read()
    # 提取关键词行
    for line in content.split('\n'):
        if '关键词' in line:
            # 提取中文逗号或英文逗号分隔的关键词
            kw_text = re.split(r'[：:]', line, 1)[-1]
            keywords = set(re.split(r'[,，、]', kw_text.strip()))
            keyword_map[d] = {k.strip() for k in keywords if k.strip()}
            break

# 交叉比对
skills = list(keyword_map.keys())
for i in range(len(skills)):
    for j in range(i+1, len(skills)):
        overlap = keyword_map[skills[i]] & keyword_map[skills[j]]
        if overlap:
            ratio = len(overlap) / min(len(keyword_map[skills[i]]), len(keyword_map[skills[j]]))
            level = '🔴高' if ratio > 0.5 else '🟡中' if ratio > 0.2 else '🟢低'
            print(f'{level} {skills[i]} ↔ {skills[j]}: {overlap}')
```

## 输出规范

- 所有报告用表格或代码块格式，清晰可读
- 修改skill前必须展示对比，用户确认后再写入
- 每次评估结束后，汇总一句话结论（如"52个skill中3个有冲突风险，建议优先处理"）

## 限制说明

- **触发测试是模拟推理**，不是真正启动skill执行。判断的是"模型看到这句话最可能触发哪个skill"
- **质量测试用subagent**，能做到上下文隔离，但token计数是估算值
- **优化后需要人工确认**，不会自动覆盖SKILL.md
