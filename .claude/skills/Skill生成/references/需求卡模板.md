# Skill 需求卡（11 项）

| # | 项目 | 填写 |
|---|------|------|
| 01 | 任务名称 | |
| 02 | 使用场景 | |
| 03 | 是否反复出现 | |
| 04 | 用户输入是什么 | |
| 05 | 想要什么结果 | |
| 06 | 固定步骤是什么 | |
| 07 | 判断标准是什么 | |
| 08 | 什么地方必须确认 | |
| 09 | 哪些事情不能做 | |
| 10 | 输出长什么样 | |
| 11 | 初步判断类型 | 原子 / 路由 / 流水线 / 系统级（新手一律先做原子） |

## 填好的示例：客户咨询回复 Skill

| 项目 | 内容 |
|------|------|
| 使用场景 | 客户在微信问适不适合、有没有时间、贵不贵、有没有效果 |
| 输入 | 一段聊天记录或一个疑虑 |
| 步骤 | 判断疑虑类型 → 共情 → 说明降低学习成本 → 匹配真实卖点 → 给轻量下一步 |
| 必须确认 | 不知道哪门课先问清；涉及退款/优惠承诺先确认政策 |
| 不能做 | 不承诺收益、不编案例、不自动发送、不高压逼单 |
| 输出 | 120–200 字自然口语微信回复 |
| 类型 | 原子 Skill |

## 最常见的错：把需求卡写成愿望

✕ "帮我做一个能自动成交客户的 Skill"

✓ "做一个客户疑虑回复 Skill：输入聊天记录，先判断卡在价格、时间、效果、信任还是执行成本，再生成一段能发微信的回复；不承诺收益、不编案例、不替我发送。"

## 常见 4 类错误对照

| 错误 | 表现 | 怎么改 |
|------|------|--------|
| 任务太大 | 想一次做完整个系统 | 先拆成一个具体动作 |
| 输入不清 | 没说用户给什么 | 写清是聊天记录、问题还是表格 |
| 标准不清 | 只说"要好、要高级" | 改成可判断的标准 |
| 边界不清 | 没写不能做什么 | 补上禁止承诺、编造、自动发布 |
