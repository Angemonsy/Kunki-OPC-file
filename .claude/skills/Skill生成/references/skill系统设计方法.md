# Skill 系统设计方法论

本文件提炼自《Skill 从入门到大师：从单个 skill 到 AI 工作流系统》，供 `Skill生成` 在设计复杂 skill 时按需读取。

## 1. 四类 skill 判断表

| 类型 | 判断问题 | 典型产物 |
|---|---|---|
| 原子 skill | 这个任务是否只完成一个明确动作 | 单点工作说明书 |
| 路由 skill | 是否需要先判断类型，再分给不同下游 | 判断表、退出规则 |
| 流水线 skill | 是否要串联多个环节完成一次交付 | 交接包、检查点、收口报告 |
| 系统级 skill | 是否长期管理一组对象和状态 | 对象表、巡检规则、调度规则、复盘回写 |

判断顺序：

1. 如果只是一个稳定动作，做原子 skill。
2. 如果核心难点是判断分流，做路由 skill。
3. 如果核心难点是多个环节不丢信息，做流水线 skill。
4. 如果核心难点是长期状态、积压、巡检和复盘，做系统级 skill。

## 9. 系统级 skill 对象表

```markdown
| 对象 | 用来管理什么 | 关键状态字段 | 常见问题 | 可调用 skill |
|---|---|---|---|---|
```

常见状态字段：

| 字段类型 | 例子 |
|---|---|
| 进度状态 | 待写、草稿中、待发布、已复盘 |
| 时间状态 | 创建时间、最后更新、积压天数 |
| 质量状态 | 是否检测、是否排版、是否通过验收 |
| 来源状态 | 灵感、录音、社群、外部素材 |
| 优先级状态 | P0、P1、P2、P3 |
| 风险状态 | 敏感、事实不确定、需确认 |

## 11. 复盘回写表

```markdown
| 复盘发现 | 类型 | 证据 | 建议回写位置 | 风险等级 | 是否自动 |
|---|---|---|---|---|---|
```

回写风险：

| 风险等级 | 可回写内容 | 是否确认 |
|---|---|---|
| 低风险 | 新增测试、迭代记录、异常案例、复盘报告 | 通常可自动 |
| 中风险 | 修改触发、路由、检查点、默认流程 | 需要确认 |
| 高风险 | 删除规则、改变职责边界、改变外部发布策略 | 必须确认 |

## 13. 核心判断

- skill 不是一句提示词，而是一套让 AI 稳定处理某类任务的工作说明书。
- description 不是简介，而是 skill 的触发入口和边界说明。
- 原子做单点，路由做判断，流水线做串联，系统级做长期运营。
- 路由 skill 一旦判断错，后面所有下游 skill 都会跟着错。
- 测试流水线，不是测它会不会完成，而是测它会不会按正确路径完成。
- 复盘让系统知道哪里变了，回写让系统下一次真的变好。
