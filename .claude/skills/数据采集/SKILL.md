# 数据采集

## 核心定位

一句话：自动打开各平台创作者后台，按发布时间节奏采集内容数据，写入数据监控中心，标记爆款和低互动内容，形成数据反馈闭环。

## 采集节奏

| 时间点 | 目的 | 说明 |
|--------|------|------|
| 发布后24小时 | 首轮数据 | 判断初始表现，是否需要追加推广 |
| 发布后7天 | 中期数据 | 内容进入稳定期，可判断是否为爆款 |
| 发布后30天 | 终期数据 | 最终定性，归档为爆款/一般/低互动 |

## 数据来源与平台

| 平台 | 采集入口 | 备注 |
|------|---------|------|
| 小红书 | 创作者中心 `https://creator.xiaohongshu.com` 或个人主页 | 优先用创作者后台，数据更全 |
| 公众号 | 微信公众平台 `https://mp.weixin.qq.com` | 登录后进入内容分析页面 |
| 抖音 | 创作者服务中心（待接入） | 后续扩展 |
| 视频号 | 视频号助手（待接入） | 后续扩展 |

## 采集字段

| 字段 | 说明 |
|------|------|
| 发布日期 | 内容发布的日期 |
| 选题 | 内容的标题/主题 |
| 平台 | 小红书/公众号/抖音/视频号 |
| 内容类型 | 图文/视频/文章 |
| 点赞 | 点赞数 |
| 收藏 | 收藏数 |
| 评论 | 评论数 |
| 转发 | 转发/分享数 |
| 互动率 | (点赞+收藏+评论+转发)/曝光量 |
| 收藏率 | 收藏/点赞 |
| 状态 | 24h/7d/30d + 爆款/优秀/一般/较差 |

## 数据写入位置

- **数据监控表**：`02.领域/0.内容创作系统/🔥03.数据反馈/📊 数据反馈汇总.md`
- **转化追踪表**：`02.领域/0.内容创作系统/🔥03.数据反馈/变现转化追踪.md`

## 爆款判断标准

### 互动率 = (点赞+收藏+评论+转发) / 曝光量

| 等级 | 范围 | 标记 |
|------|------|------|
| 爆款 | >5% | 标记为"爆款待复盘" |
| 优秀 | 3-5% | 标记为"优秀" |
| 一般 | 1-3% | 标记为"一般" |
| 较差 | <1% | 标记为"低互动待分析" |

### 收藏率 = 收藏 / 点赞

| 等级 | 范围 | 标记 |
|------|------|------|
| 爆款 | >50% | 标记为"爆款待复盘" |
| 优秀 | 30-50% | 标记为"优秀" |
| 一般 | 10-30% | 标记为"一般" |
| 较差 | <10% | 标记为"低互动待分析" |

### 讨论度 = 评论 / 点赞

| 等级 | 范围 |
|------|------|
| 爆款 | >10% |
| 优秀 | 5-10% |
| 一般 | 2-5% |
| 较差 | <2% |

### 传播力 = 转发 / 点赞

| 等级 | 范围 |
|------|------|
| 爆款 | >10% |
| 优秀 | 5-10% |
| 一般 | 2-5% |
| 较差 | <2% |

**综合判定规则**：互动率>5% **或** 收藏率>50% 满足任一即标记为爆款。

## 执行流程

### 第一步：读取数据监控中心，确认采集任务

1. 读取 `02.领域/0.内容创作系统/🔥03.数据反馈/📊 数据反馈汇总.md`
2. 扫描数据追踪表中已有记录，根据发布日期和当前日期计算：
   - 距今约24小时（1天前发布）→ 需采集24h数据
   - 距今约7天（6-8天前发布）→ 需采集7d数据
   - 距今约30天（28-32天前发布）→ 需采集30d数据
3. 列出需要采集的内容清单，告知用户

### 第二步：读取最近发布文件，确认新发布内容

1. 扫描 `02.领域/0.内容创作系统/🔥02.发布文案/2026年/` 下最近修改的文件
2. 对比数据监控中心，找出已发布但尚未录入监控表的新内容
3. 如有新内容，先在数据追踪表中新增一行（数据字段留空，等采集后填入）

### 第三步：通过Claude in Chrome打开平台

1. 使用 `mcp__claude-in-chrome__tabs_context_mcp` 获取当前标签页状态
2. 使用 `mcp__claude-in-chrome__navigate` 打开对应平台：
   - 小红书创作者中心：`https://creator.xiaohongshu.com`
   - 公众号后台：`https://mp.weixin.qq.com`
3. **每次导航后必须截图确认页面状态**

### 第四步：截图确认页面状态

1. 使用 `mcp__claude-in-chrome__computer` 的 `screenshot` 动作截图
2. 确认是否已登录：
   - 如果看到登录页面 → **立即暂停，提示用户手动登录**，等用户确认后再继续
   - 如果已登录 → 继续采集
3. 确认是否在正确的页面（数据分析/内容管理页面）

### 第五步：逐条采集数据

1. 在创作者后台找到对应内容的数据面板
2. 通过截图 + 页面读取获取数据：
   - 使用 `mcp__claude-in-chrome__read_page` 读取页面数据
   - 使用 `mcp__claude-in-chrome__computer` 的 `screenshot` 确认数据
3. 记录每条内容的：点赞、收藏、评论、转发、曝光量（如有）
4. 计算互动率和收藏率
5. **每采集一条内容，口头确认数据，避免错误**

### 第六步：写入数据监控中心

1. 读取当前数据监控中心文件
2. 在数据追踪表中更新/新增数据行
3. 格式严格按照表格结构：

```markdown
| 发布日期 | 选题 | 平台 | 内容类型 | 点赞 | 收藏 | 评论 | 转发 | 互动率 | 收藏率 | 状态 |
```

4. 状态字段格式：`24h-优秀` / `7d-爆款` / `30d-一般` 等

### 第七步：爆款/低互动标记

**如果互动率>5% 或 收藏率>50%**：
1. 在状态字段追加"爆款待复盘"
2. 在数据监控中心的「本月爆款」表格中新增一行
3. 复盘状态设为"待复盘"

**如果互动率<1%**：
1. 在状态字段追加"低互动待分析"
2. 在数据监控中心的「本月低互动内容」表格中新增一行
3. 记录状态设为"待分析"

### 第八步：汇报采集结果

采集完成后输出简洁摘要：

```markdown
## 数据采集完成

**采集时间**：YYYY-MM-DD HH:MM
**采集内容数**：X条

| 选题 | 平台 | 采集点 | 互动率 | 收藏率 | 判定 |
|------|------|--------|--------|--------|------|
| xxx  | 小红书 | 24h   | 3.2%  | 45%   | 优秀  |
| xxx  | 公众号 | 7d    | 6.1%  | 52%   | 爆款  |

**发现**：
- 爆款X条：{选题列表}
- 低互动X条：{选题列表}
- 建议：{一句话建议}
```

## 安全规则（不可违反）

1. **截图先行**：每一步操作浏览器前，必须先截图确认当前页面状态
2. **登录安全**：如果平台需要登录，立即暂停并提示用户手动登录，**绝不自动输入账号密码**
3. **异常暂停**：发现页面异常（验证码、弹窗、报错）立即暂停，询问用户如何处理
4. **不处理敏感信息**：不输入密码、不操作支付、不修改账号设置
5. **数据确认**：采集到的数据在写入前口头确认，避免误写
6. **只读不改**：在平台后台只读取数据，不做任何修改操作（不删内容、不改设置）

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 平台未登录 | 暂停，提示用户手动登录后说"继续" |
| 出现验证码 | 暂停，提示用户手动完成验证 |
| 页面加载失败 | 等待5秒重试一次，仍失败则报告用户 |
| 数据字段缺失 | 用"-"标记缺失字段，备注说明 |
| 平台改版找不到数据 | 截图当前页面，询问用户指引 |
| 曝光量不可见 | 互动率标记为"-"，只计算收藏率 |

## 执行规则

1. **按平台分批采集**：先完成一个平台的所有内容，再切换下一个平台，减少来回切换
2. **优先采集到期内容**：24h > 7d > 30d 的优先级顺序
3. **新内容先建行**：发现未录入的新发布内容，先在表中建好空行再采集
4. **数据不猜测**：看不到的数据就标"-"，绝不编造数字
5. **采集完整性**：所有需采集的内容都完成后再汇报，不要采一条报一条
6. **与周工作区联动**：采集完成后，如果发现爆款，在周工作区记录一笔，提醒复盘

## 禁止行为

1. **绝不编造数据** — 看不到就标"-"，不猜测不估算
2. **绝不自动登录** — 需要登录时必须让用户手动操作
3. **绝不修改平台内容** — 只看不动，不删帖不改设置
4. **绝不跳过截图确认** — 每步操作前都要截图
5. **绝不在未确认时写入** — 采集数据先口头确认再写文件
