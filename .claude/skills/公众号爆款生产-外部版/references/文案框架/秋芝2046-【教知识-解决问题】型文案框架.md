## 一、核心选题公式

选题模型： `大众痛点 + 完整解决方案 + 门槛承诺`

公式：【痛点关键词】+ 【产品/方法】+ 【教程级别定位】

|变量|可选值示例|
|---|---|
|痛点关键词|摆脱卡顿 / 用不好 / 太复杂 / 被困扰|
|产品/方法|DeepSeek渠道 / API接入 / Flux本地部署 / MCP配置 / TRAE开发|
|教程级别|小白教程 / 幼儿园级 / 草履虫教程 / 实用技巧 / 全流程|

底层驱动力： 即时解决焦虑（"我现在就需要解决这个问题"）+ 从众安全感（"大家都在用"）

选题筛选条件：

- 必须是当下热门且多人遇到的同一痛点（DeepSeek卡顿、不会用API等）
- 必须能给出完整可执行的解决路径（非碎片技巧）
- 痛点越普遍 × 方案越完整 = 收藏越高（S2收藏19万、S5收藏13万）

## 三、论证过程设计

### 推荐论证结构："痛点→概念科普→分步教学→总结"四段式

|段落|功能|占比|
|---|---|---|
|段1-痛点锚定|精准描述用户困境|10%|
|段2-概念科普|用通俗类比讲清原理|20%|
|段3-分步教学|手把手操作演示|60%|
|段4-总结+延伸|复盘核心步骤+场景发散|10%|

概念科普的核心手法——"类比工厂法"（S2原创，25.1万赞验证）：

- 将抽象技术概念映射到日常场景
- 示例：API = 工厂窗口、HTTP = 传纸条规则、API Key = 手牌
- 原则：一个技术概念对应一个生活类比，不超过3层嵌套

分步教学的节奏控制：

- 每个步骤必须有屏幕录制/实操画面
- 在关键步骤后插入一句"请把简单打在公屏上"类互动（S2验证）
- 复杂教程需要中间休息点（"点赞收藏关注吧，干的有点受不了了"）
