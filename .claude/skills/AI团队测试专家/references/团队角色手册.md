# 序与光内容创作团队 — 角色手册

> 本手册定义各 bot 的角色职责和测试标准，供测试专家读取使用。

## 团队概览

**团队名称**：序与光-内容创作组
**平台**：Telegram 群组
**框架**：OpenClaw AI 智能体
**模型**：google/gemini-3.1-pro-preview-h (via api2.qiandao.mom)

---

## 各 Bot 角色定义

### 1. 管家

**职责**：统筹全局，接收主任务后拆解分工、协调各角色有序执行
**核心能力**：任务理解、工作分配、进度跟踪、问题升级
**测试标准**：收到综合任务后，能拆解成子任务并 @call 对应 bot 执行
**测试消息模板**：给完整的内容生产任务，观察它如何调度团队

---

### 2. 方案

**职责**：制定内容策略、课程大纲、运营方案
**核心能力**：结构化思考、课程设计、策略规划
**测试标准**：能根据业务目标输出结构清晰、可执行的方案
**测试消息模板**：给业务目标，要一个具体的执行方案

---

### 3. 助教

**职责**：解答学员学习问题，辅导课程实践
**核心能力**：知识讲解、问题诊断、学习引导
**测试标准**：能准确理解学员问题，给出有帮助的解答
**测试消息模板**：提一个课程相关的实际学习问题

---

### 4. 顾问

**职责**：1v1 咨询，了解潜在客户需求，建立信任
**核心能力**：需求挖掘、痛点共情、价值引导
**测试标准**：能针对用户痛点给出有共鸣的回应，并自然引导到解决方案
**测试消息模板**：提一个真实的学习或变现痛点

---

### 5. 销售

**职责**：跟进意向客户，处理异议，促成成交
**核心能力**：异议处理、价值塑造、促单话术
**测试标准**：能有效处理价格异议或效果疑虑，给出有说服力的回应
**测试消息模板**：提一个典型的购买异议（价格贵、效果不确定等）

---

### 6. 案例

**职责**：收集、整理、提炼学员成功案例，形成可复用的案例库
**核心能力**：案例结构化、亮点提炼、传播包装
**测试标准**：能把零散的学员反馈整理成有说服力的标准案例
**测试消息模板**：给一段学员的真实反馈，要求整理成案例

---

### 7. 督导

**职责**：监督团队执行情况，把控内容质量，处理例外情况
**核心能力**：流程管理、质量检查、问题处理
**测试标准**：能对执行问题给出明确的处理建议
**测试消息模板**：提一个团队执行中的实际问题

---

### 8. 增长

**职责**：设计涨粉策略，优化流量渠道，推动账号增长
**核心能力**：增长分析、渠道策略、内容复制
**测试标准**：能根据现有基础给出具体可执行的增粉方案
**测试消息模板**：给当前粉丝数和目标，要增长方案

---

### 9. 选题

**职责**：发现爆款选题方向，评估选题潜力
**核心能力**：热点捕捉、爆款要素分析、选题包装
**测试标准**：能给出有爆款潜力的选题，并说明理由
**测试消息模板**：要求给出本周的爆款选题方向

---

### 10. 编辑

**职责**：审核文章质量，优化标题，排版改进
**核心能力**：内容审核、标题优化、排版建议
**测试标准**：能识别文章的问题并给出具体的改进建议
**测试消息模板**：给一篇有明显可改进空间的文章草稿

---

### 11. 私信

**职责**：处理粉丝私信，提供标准化回复话术，引导关注和转化
**核心能力**：私信分类、话术生成、转化引导
**测试标准**：能识别私信类型并给出自然、有效的回复话术
**测试消息模板**：给一条真实的粉丝私信场景

---

### 12. 写手

**职责**：根据选题撰写完整的公众号文章
**核心能力**：内容创作、故事化写作、结构设计
**测试标准**：能写出1500字左右、有具体细节、符合平台调性的文章
**测试消息模板**：给选题和风格要求，要完整文章

---

### 13. 分发

**职责**：将内容适配并分发到多个平台
**核心能力**：内容改编、平台适配、发布节奏规划
**测试标准**：能给出完整的多平台分发方案，包含时间节奏和内容改编要点
**测试消息模板**：给一篇已发布的文章，要多平台分发方案

---

### 14. 数据

**职责**：分析内容数据，复盘效果，提供优化建议
**核心能力**：数据解读、效果归因、优化建议
**测试标准**：能准确分析数据指标，找出真正的问题所在，给出有价值的优化方向
**测试消息模板**：给几篇文章的数据，要分析和优化建议

---

## 协作链路说明

OpenClaw 框架支持 bot 之间通过 `@call` 指令触发协作：

```
@call writer    → 触发写手 bot
@call editor    → 触发编辑 bot
@call selector  → 触发选题 bot
@call growth    → 触发增长 bot
@call sales     → 触发销售 bot
@call advisor   → 触发顾问 bot
@call data      → 触发数据 bot
@call publisher → 触发分发 bot
```

**协作测试重点链路：**
1. 选题 → 写手（内容生产链路）
2. 写手 → 编辑（质量把控链路）
3. 顾问 → 销售（转化链路）
4. 数据 → 增长（优化链路）
5. 管家 → 全队（综合调度链路）

## 常见故障与处理

| 错误码 | 含义 | 处理方式 |
|--------|------|---------|
| HTTP 429 | API 限流（Too Many Requests） | 等 2-5 分钟，减少并发 |
| HTTP 503 | API 服务不可用（No available channel） | 检查 API key 余额；重启 gateway |
| 无响应超 2 分钟 | Gateway 崩溃 | 执行 `openclaw gateway --force` |
| 回复内容完全偏题 | Prompt 丢失或模型配置错误 | 检查 openclaw.json |

## 测试评分标准

| 评分 | 说明 |
|------|------|
| ✅ 优秀 | 回复符合角色，内容专业，能直接使用 |
| ⚠️ 一般 | 有回复但质量不达标（偏题、太简单、没有实质内容）|
| ❌ 失败 | 无回复、报错、或回复完全不相关 |
