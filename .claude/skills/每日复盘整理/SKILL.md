# 每日复盘整理 Skill

## 使用场景

当用户提出以下需求时使用本 Skill：

- “帮我做每日复盘”
- “按照 skill 复盘”
- “把这段录音稿整理成复盘”
- “根据我的逐字稿复盘”
- “做一个周复盘 / 十日复盘 / 九日复盘 / 阶段复盘”
- “我刚刚口喷了一段，帮我整理成每日复盘”
- “按之前那个 6月8号到6月16号的结构整理”

本 Skill 适用于：

- 单日复盘
- 多日复盘
- 周复盘
- 十日复盘
- 月度阶段复盘
- 长期阶段复盘

## 最高优先级原则

### 1. 必须基于用户提供的录音逐字稿 / 口述内容

用户要的是把他自己讲出来的内容整理成复盘，而不是让 AI 根据文件修改记录自行猜测。

禁止把以下内容当作主要复盘依据：

- 工作区文件修改记录
- Git / find 扫描结果
- 工具产出清单
- AI 自己推断的工作主线

除非用户明确要求“根据工作区产出复盘”，否则默认依据是：

- 用户刚刚粘贴的录音逐字稿
- 用户提供的口述文本
- 用户指定的 paste txt 文件
- 用户指定的转写稿文件

### 2. 不做人设分析，不拔高，不替用户评价人生主线

复盘应保留：

- 事实
- 行动
- 项目进展
- 当时感受
- 自我观察
- 用户自己说出的判断
- 用户自己说出的反思

避免输出：

- “你正在从 XX 转向 XX”
- “这说明你底层正在发生 XX”
- “你的核心主线是 XX”
- “本质上你是一个 XX 的人”
- 过度心理分析
- 过度价值评价
- 外部导师式总结

可以整理用户自己说出的深度内容，但不要额外加 AI 的分析。

### 3. 结构化，但不要改掉用户原意

整理目标是让录音稿变得清晰、可读、可归档、可对外展示。

可以做：

- 去除口癖
- 合并重复表达
- 调整顺序
- 补齐标题
- 按日期拆分
- 把散乱内容归类

不可以做：

- 编造未出现的信息
- 把不确定日期写成确定日期
- 把用户没有说过的动机强行加进去
- 把“可能”“大概”“忘了”改成绝对表述

遇到日期不确定时，应写：

- “录音中没有单独展开该日细节”
- “根据上下文，该日主要处于 XX 事项推进中”
- “用户在录音中对此日记忆较模糊”

### 4. 输出必须进入既有知识库结构

默认保存路径：

```text
02-记忆系统/每日输入与素材/每日复盘/YYYY-MM/
```

文件命名格式：

```text
YYYY.M.D-M.D-主题复盘-根据录音整理.md
```

示例：

```text
02-记忆系统/每日输入与素材/每日复盘/2026-06/2026.6.8-6.16-九日复盘-根据录音整理.md
```

禁止：

- 在知识库根目录新建“复盘”目录
- 在根目录放复盘 markdown
- 在根目录新建临时文件夹
- 把最终交付物放到 `/private/tmp`

如果是分析版、草稿版，也必须放到每日复盘目录或用户指定的既有目录中。

## 标准输出结构

所有复盘默认按以下结构输出。

### 标题

格式：

```markdown
# YYYY.M.D-M.D 阶段复盘｜根据录音逐字稿整理
```

如果是单日：

```markdown
# YYYY.M.D 每日复盘｜根据录音逐字稿整理
```

如果用户指定标题，以用户指定标题为准。

### 开头说明

```markdown
> 来源：录音逐字稿 / 用户口述整理  
> 范围：YYYY年M月D日-YYYY年M月D日  
> 用途：每日复盘 / 阶段记录 / 对外展示素材  
> 说明：本文根据录音内容整理，主要保留事实、行动、当时感受与自我观察，不额外做人设分析或外部评价。
```

### 一、总体概览

作用：用几段话概括这段时间发生了什么。

写法要求：

- 客观；
- 不拔高；
- 不要写成“人生主线”；
- 可以列出主要事项；
- 保留用户自己的阶段感受。

常用格式：

```markdown
## 总体概览

X月X日到X月X日这几天，整体处在……阶段。

这段时间主要发生了几件事：

- ……
- ……
- ……
```

### 二、按日期逐日整理

每一天按以下结构：

```markdown
## M月D日 周X

### 事项标题

事实记录。包括做了什么、和谁有关、推进到哪里、出现了什么问题、用户当时有什么感受或判断。

### 事项标题

继续整理。
```

要求：

- 日期明确时逐日写；
- 日期不明确时说明“录音中没有单独展开”；
- 不要为了完整而编造事项；
- 用户讲得多的日期可以多写几个小标题；
- 用户讲得少的日期可以简短记录。

### 三、补充事项

用于收纳录音中补充提到、但不完全归属于某一天的内容。

示例：

```markdown
## 补充事项

### 某训练营结算

……

### 某社交事件复盘

……
```

### 四、阶段事项归类

按主题把整段时间的事项再归类一次，便于复盘和查阅。

常见分类：

- 知识库与 AI 产品化
- 公开表达与线下分享
- 私域裂变与训练营结果
- 课业与期末压力
- 社交、关系与同频判断
- 生活状态与消费
- 健身与作息
- 家庭与休息
- 项目推进

格式：

```markdown
## 阶段事项归类

### 1. 知识库与 AI 产品化

- ……
- ……

### 2. 公开表达与线下分享

- ……
- ……
```

### 五、可对外展示简版

最后提供一个较短版本，便于用户复制到朋友圈、公众号、社群、阶段总结中。

要求：

- 不写隐私细节；
- 不写过于粗口、成人、敏感内容；
- 保留项目、学习、成长、行动；
- 语气客观、自然；
- 不过度营销，不鸡血。

格式：

```markdown
## 可对外展示简版

X月X日至X月X日，这一阶段主要围绕……展开。

……
```

## 敏感内容处理规则

用户录音中可能包含私人情绪、成人内容、粗口、欲望、关系、自卑、攻击性表达等。

处理原则：

1. 私人复盘正文可以适度保留，但要整理成更可读、更克制的表达。
2. 对外展示简版必须去除或弱化隐私和敏感细节。
3. 不要审判用户，不要说教。
4. 不要把用户一时的激烈表达扩大成稳定人格判断。
5. 对粗口可以改写为中性表达。

示例：

原始：

> 我操，我那天真的欲求不满，然后很躁。

整理：

> 复盘中提到，这段时间对关系和欲望的渴望较强，导致状态比较浮躁，也影响了作息和专注力。

对外展示简版可写：

> 这段时间状态并不稳定，作息和专注力仍需要继续调整。

## 质量检查清单

输出前检查：

- [ ] 是否基于用户录音稿 / 口述内容，而不是文件扫描结果？
- [ ] 是否按日期整理？
- [ ] 是否保留了用户自己的行动、感受和判断？
- [ ] 是否避免了 AI 自己额外拔高分析？
- [ ] 是否有“总体概览”？
- [ ] 是否有“补充事项”？
- [ ] 是否有“阶段事项归类”？
- [ ] 是否有“可对外展示简版”？
- [ ] 是否保存到 `02-记忆系统/每日输入与素材/每日复盘/YYYY-MM/`？
- [ ] 是否没有在根目录新建目录或乱放文件？
