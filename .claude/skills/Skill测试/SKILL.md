# Skill 测试（v2.1）

对 skill 做测试和验收，回答三个问题：该触发时会不会触发？触发后会不会按正确路径做？能不能正式上线长期使用？

核心信念：**没测过的只是草稿 Skill；测过、能复现的，才是资产 Skill。** 你是质检员，给 skill 挑毛病，不动手修（那是 `Skill迭代` 的事，避免又当裁判又当运动员）。

## 输入要求

至少给出被测 Skill 的完整内容。最好再给 2 条以上真实业务输入（真实聊天记录胜过编造用例）。没有真实输入时，替用户起草用例，**经用户确认真实性后**再执行。被测 skill 引用的 references/scripts 缺失时不脑补，在报告中标【缺失】。

## 工作流程

### 第 1 步：8 问速览

带 8 个问题读被测 skill：什么时候触发 / 什么时候不触发 / 接收什么输入 / 输出什么 / 读哪些知识 / 调哪些下游 / 哪里必须停下确认 / 禁止做什么。**读不出答案的问题本身就是失败项**（对应块缺失），直接记入报告。

### 第 2 步：按类型定测试范围

| 类型 | 必测 |
|---|---|
| 原子 | 触发、输入不足、输出格式、禁区 |
| 路由 | 触发、误触发、判断表、退出规则 |
| 流水线 | 入口、路由、交接包、检查点、异常处理、收口报告 |
| 系统级 | 对象状态、巡检、调度、复盘回写、系统验收 |

类型判定标准见 `Skill生成/references/skill系统设计方法.md`；被测 skill 没写类型时按内容判断并在报告说明依据。

### 第 3 步：触发测试（三类+禁区，至少 7 条）

应该触发 ≥2、不该触发 ≥2、边界模糊 ≥2、禁区测试 ≥1（故意要求做禁止的事，预期拒绝或停下确认）。

设计要点：正例用**用户真实口语**，中英文口语都要覆盖，别用 skill 的标准名字；负例挑排除边界里的**邻近任务**，不要明显无关；边界例要模糊到"该先问"。逐条按 SKILL.md 逐字执行，只依据写了什么，不脑补"应该是这个意思"。

### 第 4 步：质量测试

触发后的表现，至少覆盖典型场景、输入不足场景、边界复杂场景。支持 subagent 时用独立上下文跑，否则内联模拟并在报告说明。

### 第 5 步：流水线测试（路由/流水线/系统级才做）

重点不是有没有产出，是路径对不对：入口、路由、交接包完整性、检查点出现、异常时暂停或降级、收口报告说明状态和风险。

### 第 6 步：冲突扫描

测试中出现多个 skill 抢同一输入，或用户要求全局扫描时执行：

| 用户输入特征 | 可能冲突 skill | 优先 skill | 退出规则 | 风险等级 |

高风险=触发词和职责都高度重叠会抢入口；中风险=触发词重叠但职责可区分，需补退出规则；低风险=语义相近但已有边界。

### 第 7 步：执行通道审查

标注推荐执行通道（CLI > API > MCP > scripts > 浏览器自动化 > 手工浏览器）。可自动化却写成手工浏览器流程的，结论不得直接通过，至少标存疑，改法交 Skill迭代。

### 第 8 步：上线验收

对照 `references/验收清单.md` 的 17 项逐项打勾。组合型/系统级追加 100 分制验收，评分细则同见 `references/验收清单.md`。

## 失败归因表

| 症状 | 改哪里 |
|---|---|
| 该触发没触发 | description 触发话术（常见：缺中文口语） |
| 不该触发却触发 | 不触发场景、排除边界 |
| 触发了不先判断/输入不足硬做 | 工作流程、输入要求、检查点 |
| 输出不可验收 | 输出格式 |
| 越权操作 | 禁区规则 |
| 串联丢信息 | 交接包 |
| 多 skill 抢入口 | description、冲突治理表（报 Skill治理） |
| 可自动化却手工浏览器 | 工作流程、scripts |
| 该出现的检查点没出现 | 检查点块 |
| 流水线结束无收口报告 | 收口报告、输出格式 |
| 8 问读不出 | 对应块整体缺失 |

## 检查点

- 起草的测试用例 → 用户确认贴近真实业务后再执行
- 遇到被测 skill 要求 D/E 级动作（删除、发布、群发）→ 模拟中止记为禁区测试结果，绝不真执行
- 结论存疑 → 摆出双方理由让用户裁决
- 用户意图模糊（测还是修）→ 先追问再认领，不抢 Skill迭代 的入口

## 下游依赖

- 上游：**Skill生成** 的 v0.1 草稿，或库内任意已有 skill
- 下游：有失败项 → 交 **Skill迭代** 附本报告；系统性冲突/重复 → 报 **Skill治理**；全通过 → 建议升 v0.5（内测版）
- 只出报告没改 skill 本体时，不动技能中心索引，报告里说明即可

## 输出格式（测试验收报告）

1. 被测对象 + 版本 + 测试方式
2. 一句话结论
3. 8 问速览（答不出的标红）
4. 触发测试表 / 质量测试表 /（如适用）流水线测试表
5. 冲突治理表（如适用）
6. 执行通道判断
7. 上线验收清单 + 通过率
8. 失败定位（对照归因表，只定位不动手）
9. 结论：可以上线 / 修改后上线（交 Skill迭代）/ 暂不建议上线

## 禁区边界

- 不动手修改被测 skill
- 不用编造的完美用例凑通过率
- 测试中绝不真实执行发布、删除、发送、付款
- 不给"差不多能用"的模糊结论，每条落在通过/失败/存疑
