# lobster-output-sync

> Kunki 一人公司系统 - 小龙虾产出写入、总控日报与 New Drive 回流 Skill。纯 New Drive 原生架构。

## 作用

这个 Skill 解决的问题是：

> 小龙虾在 New Drive 完成任务后，必须按标准目录写入 New Drive 对应位置，生成总控日报，让林总打开 New Drive 或本地同步后能直接看到成果。New Drive 自动备份到 GitHub，不需要小龙虾操作 Git。

`kunki-knowledge-base` 负责读（从 New Drive）；本 Skill 负责写（写回 New Drive）。

## 最高规则（纯 New Drive 原生）

1. **New Drive 云端知识库是唯一权威归档**：所有产出直接写回 New Drive。
2. **GitHub 自动备份**：由 New Drive 处理，不需要小龙虾操作 Git。
3. 所有小龙虾产出必须写入：

```text
01-记忆系统/每日输入与复盘/lobster_input/
```

4. 每个智能体只能写入自己的目录，避免混乱。
5. 每天必须生成或更新总控日报。
6. 如果同名文件已存在，优先追加版本号，不要直接覆盖林总人工修改。

## 标准输出路径（都在 New Drive 上）

普通智能体按日期建目录：

```text
01-记忆系统/每日输入与复盘/lobster_input/[智能体目录]/YYYY-MM-DD/[产出标题].md
```

示例：

```text
01-记忆系统/每日输入与复盘/lobster_input/01-xuange-选哥/2026-05-24/每日选题推荐.md
01-记忆系统/每日输入与复盘/lobster_input/02-contenthelper-内容助手/2026-05-24/港科广AI商业IP选题初稿.md
01-记忆系统/每日输入与复盘/lobster_input/08-yasige-雅思哥/2026-05-24/雅思学习记录.md
```

总控虾日报路径：

```text
01-记忆系统/每日输入与复盘/lobster_input/09-zongkongxia-总控虾/YYYY-MM-DD-小龙虾每日总控日报.md
```

## 文件命名规则

1. 文件名要短、清晰、可检索。
2. 禁止使用 `/ \ : * ? " < > |` 等非法字符。
3. 草稿类文件名建议带"初稿"；复盘类文件名建议带"复盘"；日报类文件名固定带"日报"。
4. 如果同名文件已存在，优先追加版本号：`-v2.md`，不要直接覆盖，除非任务明确要求更新同一文件。

## 标准写入流程（纯 New Drive）

1. 识别智能体身份
2. 确认输出路径：`01-记忆系统/每日输入与复盘/lobster_input/[智能体目录]/YYYY-MM-DD/`
3. 按模板生成 Markdown 文件
4. 在 New Drive 中创建路径并写入文件
5. 如果是每日任务，生成或更新总控日报
6. 列出所有写入的文件路径，报告给林总

**不需要小龙虾操作 Git**：New Drive 会自动同步和备份到 GitHub。

## 冲突处理

如果路径已存在且有林总人工修改：

1. 不要覆盖。
2. 小龙虾产出改成新文件或新版本（加 `-v2`）。
3. 报告冲突给林总。

## 安全边界

禁止写入或提交以下内容：

```text
.env
*.key
credentials.json
任何 API Key、Token、Cookie、账号密码
```

如果发现敏感信息，停止写入并报告林总。

## 最小闭环

一次标准小龙虾任务必须完成：

```text
读取 New Drive → 按任务类型读取对应上下文
→ 生成任务产出
→ 写入 New Drive 的 lobster_input 对应智能体目录
→ 更新或生成总控日报
→ 报告给林总：哪些文件已写入
```

GitHub 备份由 New Drive 自动处理。

## 给小龙虾的短指令

> 产出直接写回 New Drive。按智能体身份写入 `01-记忆系统/每日输入与复盘/lobster_input/` 对应目录，更新总控日报。New Drive 会自动备份到 GitHub，不需要你操作 Git。
