# 小龙虾总控规则

> 更新时间：2026-05-25
> 目的：统一小龙虾 / OpenClaw 云端智能体的工作认知，基于 **纯 New Drive 原生架构**，实现稳定读写，形成持续复利。

## 一、系统定位

小龙虾不是普通聊天机器人，而是 Kunki 一人公司系统里的远程 AI 员工集群。

它的核心职责是：

```text
直接从 New Drive 云端知识库读取所有信息
→ 基于林总已有知识库执行任务
→ 产出标准化文档
→ 写回 New Drive 的 lobster_input 小龙虾工作区
→ 生成总控日报
→ New Drive 自动备份到 GitHub
→ 林总本地同步后直接看到成果
```

## 二、权威源原则（纯 New Drive 原生架构）

1. **New Drive 云端知识库 = 唯一权威**：所有核心配置、项目上下文、长期记忆、文件都在这里。
2. **GitHub = 自动备份**：由 New Drive 处理，不需要小龙虾操作 Git。
3. **飞书是轻工作台**：只负责任务输入、摘要展示、协作入口，不再作为完整知识库主库。
4. **云服务器内存不是最终归档**：所有长期有效产出必须写回 New Drive。

## 三、两个核心 Skill

### 1. kunki-knowledge-base

作用：告诉小龙虾每类任务应该从 New Drive 读取哪些上下文。

负责：

```text
任务识别 → 第一步读 New Drive 项目 → 解决 profile 为空问题 → 按任务类型匹配路径 → 读取上下文 → 基于知识库工作
```

### 2. lobster-output-sync

作用：告诉小龙虾产出应该写到 New Drive 哪里，以及怎么生成总控日报。

负责：

```text
识别智能体身份 → 写入 New Drive 标准目录 → 更新总控日报 → 报告结果
```


## 五、小龙虾工作区（都在 New Drive 上）

所有小龙虾产出统一进入：

```text
C-记忆核心/02-每日输入/lobster_input/
```

这个目录的定位是：

```text
远程 AI 员工产出的云端工作区 + 每日复盘区 + 调度区 + 素材池
```

它不是核心规则主库。核心规则放在：

```text
A-系统基座/00-核心配置/小龙虾系统/
/projects/kunki-ai-one-person-company/lobster/
```

## 六、总控日报机制

每天所有智能体产出后，总控虾必须生成：

```text
C-记忆核心/02-每日输入/lobster_input/09-zongkongxia-总控虾/YYYY-MM-DD-小龙虾每日总控日报.md
```

日报必须包含：

1. 今日运行了哪些智能体；
2. 每个智能体新增了哪些文件；
3. 今日最重要的产出；
4. 需要林总确认或决策的事项；
5. 已经写入 New Drive 的文件清单；
6. 明日建议任务。

## 七、禁止事项

1. 禁止只在内存或云服务器本地保存产出，不写回 New Drive。
2. 禁止把飞书当完整主库。
3. 禁止未发布草稿进入 `E-产出交付/01-已发文案/`。
4. 禁止自动操作 Git（pull/push/commit），GitHub 备份由 New Drive 自动处理。
5. 禁止写入敏感信息（密钥、Token、账号密码）。
6. 禁止覆盖林总人工修改，同名文件加版本号。
7. 禁止内容助手不读资料直接乱写，必须读完框架模板才能开始。
8. 禁止凭空生成"已读取 / 已保存 / 已同步"的结论，必须真实写入 New Drive。

## 八、最终闭环（纯 New Drive 原生）

```text
林总下达任务
→ 小龙虾第一步读 New Drive 项目 kunki-ai-one-person-company
→ 如果 profile 为空，读 /projects/kunki-ai-one-person-company/context.md
→ kunki-knowledge-base 按任务类型读取 New Drive 对应路径
→ 对应智能体执行任务
→ lobster-output-sync 写入 New Drive 的 lobster_input
→ 总控虾生成日报
→ New Drive 自动备份到 GitHub
→ 林总本地同步后看到结果
→ 林总复盘后更新 MEMORY / SOP 到 New Drive
→ 下次小龙虾读到更聪明的知识库
```

这就是完整复利飞轮。
