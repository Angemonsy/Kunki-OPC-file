# 飞书轻工作台整改方案

> 更新日期：2026-05-17  
> 目标：停止把飞书当完整知识库主库，改为“AI员工轻工作台”。

---

## 1. 架构结论

### 1.1 不再做什么

不再尝试把 GitHub/Obsidian 的完整知识库全量搬进飞书。

原因：

- 飞书文档系统不适合做完整文件系统镜像；
- Markdown、脚本、Skill、图片、隐藏目录无法稳定完整映射；
- 批量创建、移动、归档和覆盖更新成本高；
- 飞书内容容易滞后，AI员工容易读旧信息；
- lark-cli 在文件夹层级、权限、限流、代理方面存在实际维护成本。

### 1.2 以后怎么做

采用：

```text
GitHub/Obsidian = 唯一主库
飞书 = AI员工轻工作台
小龙虾/AI员工 = 优先读GitHub，必要时读写飞书输入输出
Main Agent = 归档兜底与系统维护
```

## 2. 飞书保留结构

飞书根目录建议只保留以下核心入口：

```text
飞书根目录
├── A01-AI bot设定与工作交付
├── kunki输入
├── kunki输出
├── 当前任务区（可选）
└── 归档区（可选）
```

### 2.1 A01-AI bot设定与工作交付

保留内容：

- 选哥、盘哥、写作哥、情报哥、催哥、学习搭子的系统提示词；
- 每个AI员工的任务边界；
- 每个AI员工的读GitHub主库规则；
- 每个AI员工的归档规则。

必须新增一句：

```text
执行任何任务前，必须优先读取 GitHub/Obsidian 主库最新内容；飞书历史文档不得作为唯一依据。
```

### 2.2 kunki输入

用途：

- 林总临时想法；
- 今日任务；
- 待处理素材；
- 录音/文字转写后的待整理内容；
- 需要AI员工处理的指令。

归档规则：

| 输入类型 | 最终归档位置 |
|---|---|
| 临时碎片 | `00_Inbox/` |
| 每日思考 | `C-记忆核心/02-每日输入/` |
| 长期洞见 | `C-记忆核心/01-个人上下文/A03-MEMORY.md` |
| 内容素材 | `D-内容创作/03-素材库/` |
| 合作信息 | `E-产出交付/05-合作管理/` |

### 2.3 kunki输出

用途：

- AI员工产出结果；
- 任务摘要；
- 今日选题；
- 复盘报告；
- 临时草稿。

归档规则：

| 输出类型 | 最终归档位置 |
|---|---|
| 选题推荐 | `D-内容创作/02-选题决策/` |
| 内容草稿 | `E-产出交付/01-已发文案/` |
| 复盘沉淀 | `C-记忆核心/03-经验沉淀/` |
| 数据记录 | `E-产出交付/03-数据反馈/` |
| 产品方案 | `D-内容创作/06-产品管理/` |
| 合作方案 | `E-产出交付/05-合作管理/` |
| 临时文件 | `E-产出交付/06-临时文件/` |

## 3. 飞书旧内容处理策略

### 3.1 暂不立刻删除

飞书旧文档先不要直接全部删除，避免误删历史上下文。

按三步处理：

1. **识别**：列出旧文档，判断是否已经在GitHub/Obsidian存在；
2. **归档**：有价值但未入库的内容，导出到本地对应目录；
3. **降级**：已入库或过时文档，移入飞书归档区或删除。

### 3.2 删除标准

满足以下条件可以删除或移入归档区：

- GitHub/Obsidian已有同内容或更新版本；
- AI员工SOP已改为读取GitHub，不再依赖该飞书文档；
- 文档明显过期、重复、低价值；
- 删除前已确认不影响现有自动化。

### 3.3 保留标准

满足以下条件应保留：

- A01里的AI员工设定；
- 当前正在运行的任务文档；
- 飞书自动化仍然引用的文档；
- 人类查看体验明显优于Markdown的展示版文档。

## 4. AI员工新工作流

```text
任务开始
  ↓
读取GitHub主库：CLAUDE.md / A03-MEMORY / 最新每日输入 / 任务相关文件
  ↓
读取飞书kunki输入中的当前任务
  ↓
执行任务
  ↓
长期内容写入GitHub对应目录
  ↓
飞书kunki输出留下摘要、路径、下一步
  ↓
Main Agent或催哥检查是否闭环
```

---

## 5. Main Agent兜底动作

Main Agent 每次处理飞书相关任务时：

1. 优先确认任务是否需要写入GitHub主库；
2. 如果飞书有新输出，按主题归档回本地五大板块；
3. 归档后用 Read 验证关键文件；
4. 用户要求时再 git add/commit/push；
5. 不再默认全量同步飞书旧知识库。

---

## 6. 小龙虾侧要求

小龙虾必须安装/使用 `kunki-knowledge-base` skill。

执行任务前固定话术/规则：

```text
我将先读取林总 GitHub/Obsidian 主库最新内容，再处理飞书当前任务输入。飞书只作为工作台，不作为最终知识来源。
```

如果小龙虾可以push GitHub：

- 结果直接写回GitHub；
- 飞书只留摘要。

如果小龙虾不能push GitHub：

- 结果写入飞书kunki输出；
- 标注推荐归档路径；
- 通知Main Agent归档。

---

## 7. 后续清理建议

### 第一阶段：立即生效

- 更新CLAUDE.md；
- 更新kunki-knowledge-base skill；
- 新建AI员工GitHub主库工作SOP；
- 所有新任务按新规则执行。

### 第二阶段：迁移A01

- 把A01所有AI员工提示词加上“先读GitHub主库”规则；
- 把旧的“飞书为主库”描述删除或改写。

### 第三阶段：清理旧飞书文档

- 先列出所有飞书文档；
- 对照GitHub是否已有；
- 未入库的导出归档；
- 已过时的移入归档区或删除。

### 第四阶段：建立巡检

催哥每日/每周检查：

- 飞书kunki输出是否有未归档内容；
- GitHub是否有最新提交；
- A03-MEMORY是否需要更新；
- 旧飞书文档是否仍被AI员工误读。

---

## 8. 一句话标准

> 飞书可以用来“干活和展示”，但不能再用来“记住一切”。真正记住一切的是 GitHub/Obsidian 主库。
