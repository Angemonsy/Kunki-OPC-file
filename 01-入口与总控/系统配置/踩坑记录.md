## 2026-05-08 Git同步GitHub问题

### 问题现象

- Windows上执行 `git pull` 报错：`git: 'remote-https' is not a git command`
- 有两个Git安装，路径冲突导致调用了有问题的Git版本
- 代理配置重复导致连接失败：系统已经全局走VPN代理，Git又配了一次代理，连不上

### 根本原因

1. **多个Git版本冲突**：newmax自带了一个Git在 `C:\Users\Administrator\AppData\Local\newmax\git\mingw64\bin\git.exe`，系统又安装了一个Git在 `C:\Program Files\Git\cmd\git.exe`，环境变量PATH中newmax排在前面，默认调用了自带的Git，但这个版本有问题。

2. **代理重复配置**：用户系统已经开了VPN全局代理，Git不需要再单独配置http/https代理，重复配置会导致连接失败。

### 正确解法

**方案：使用完整路径调用系统Git**

拉取：
```bash
"C:\Program Files\Git\cmd\git.exe" pull origin main
```

推送：
```bash
"C:\Program Files\Git\cmd\git.exe" add .
"C:\Program Files\Git\cmd\git.exe" commit -m "更新说明"
"C:\Program Files\Git\cmd\git.exe" push origin main
```

**可选优化：修改环境变量让系统Git优先**（如果想直接用 `git` 简化命令）：
- 在Windows系统环境变量中，把 `C:\Program Files\Git\cmd` 移到 `C:\Users\Administrator\AppData\Local\newmax\git\mingw64\bin` 前面
- 或者去掉newmax自带Git的路径

### 代理配置原则

| 系统全局VPN | Git应该 |
|------------|---------|
| 已开启 | **不要**给Git配置额外代理，Git直接走系统全局代理 |
| 未开启 | 需要代理时才给Git配置 `http.proxy` 和 `https.proxy` |

## 2026-05-14 定时任务设置问题

### 问题现象

- 用户让AI帮忙设置定时任务，AI说"做不了"、"系统没开放权限"
- AI不知道牛马AI已经内置了 `mcp__scheduled-tasks__create_scheduled_task` 工具可以直接创建定时任务
- 影响用户体验，用户本来可以一句话搞定，结果折腾半天

### 根本原因

1. **AI不知道自己有这个能力**：有些AI模型不知道系统提供了定时任务MCP服务，误以为做不了
2. **没有养成调用习惯**：遇到用户要设置提醒/定时推送，第一反应应该是直接调用工具，而不是拒绝

### 正确解法

**当用户要求设置定时任务/定时提醒时，必须：**

1. 直接使用 `mcp__scheduled-tasks__create_scheduled_task` 工具创建
2. 问清楚四个信息：
   - 任务名称
   - 执行时间（HH:MM 格式）
   - 重复类型（once/daily/weekly）
   - 要执行的任务内容（prompt）
3. 创建完成后告诉用户任务ID和触发时间，确认成功

**关键规则：**
> ✅ 用户说"帮我设置定时任务" → 直接创建，不要说做不了  
> ✅ 牛马AI原生支持定时任务，随时可用，不需要权限  
> ❌ 严禁说"系统没开放权限"、"我做不了"这种话

## 沉淀经验

1. 遇到Git奇怪错误，先检查 `where git` 看看是不是多个版本冲突
2. Windows上newmax环境自带Git，但有问题，优先调用系统Git
3. 系统已经全局VPN代理，Git不要再重复配置代理
4. **用户要求设置定时任务，直接调用 `mcp__scheduled-tasks__create_scheduled_task` 创建，严禁说做不了**
