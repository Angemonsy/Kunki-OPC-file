# AI员工 GitHub主库 + 飞书轻工作台 工作SOP

> 更新日期：2026-05-17  
> 核心结论：GitHub/Obsidian 是唯一主库；飞书只做轻工作台。

---

## 1. 总原则

### 1.1 主库唯一原则

- `D:/ObsidianVaults/MyVault/` 本地 Obsidian 知识库 + GitHub `main` 分支，是 Kunki 一人公司系统的唯一权威主库。
- 所有长期有效的记忆、SOP、内容资产、产品方案、合作记录、复盘沉淀，最终都必须进入 GitHub/Obsidian。
- 飞书不再承担完整知识库主库职责，不再强求全量镜像本地仓库。

### 1.2 飞书轻工作台原则

飞书只保留以下用途：

1. `A01`：AI员工设定、任务提示词、工作交付说明。
2. `kunki输入`：林总临时输入、任务指令、待处理素材。
3. `kunki输出`：AI员工任务结果、摘要、可视化展示、待归档产物。
4. 少量任务型文档：每日选题、日报、复盘、学习计划等。

飞书里的内容如果具有长期价值，必须回流到 GitHub/Obsidian；否则只视为临时工作区内容。

## 3. AI员工执行任务后：归档规则

### 3.1 长期有效内容必须写回 GitHub

| 产出类型 | GitHub/Obsidian归档位置 | 飞书处理 |
|---|---|---|
| 每日思考/复盘 | `C-记忆核心/02-每日输入/`，必要时提炼进 `A03-MEMORY.md` | kunki输出留摘要 |
| 选题推荐 | `D-内容创作/02-选题决策/` | 飞书展示Top3 |
| 文案草稿/发布稿 | `E-产出交付/01-已发文案/` | kunki输出留标题和路径 |
| 爆款复盘/方法论 | `C-记忆核心/03-经验沉淀/` | kunki输出留摘要 |
| 产品方案 | `D-内容创作/06-产品管理/` 或 `E-产出交付/02-变现路径/` | 飞书留展示版 |
| 商业合作记录 | `E-产出交付/05-合作管理/` | 飞书留协作记录 |
| 客户/社群运营 | `E-产出交付/04-客户运营/` | 飞书留执行摘要 |
| 临时文件 | `E-产出交付/06-临时文件/` | 非必要不写飞书 |

### 3.2 GitHub写回命令模板

如果小龙虾/云端AI有GitHub写权限：

```bash
cd /path/to/Kunki-OPC-file
git pull origin main
# 创建或修改对应文件
git add "具体文件路径"
git commit -m "[AI员工] 任务说明：YYYY-MM-DD"
git push origin main
```

注意：

- 不要随意 `git add .`，优先添加具体文件，避免提交缓存/敏感文件。
- 不要改动 `.env`、凭证、Obsidian本地状态文件。
- 如果 push 失败，先 `git pull --rebase origin main`，仍失败则通知 Main Agent 处理。

### 3.3 没有GitHub权限时

如果小龙虾暂时不能 push GitHub：

1. 先写到飞书 `kunki输出`；
2. 在文档开头标注推荐归档路径，例如：
   ```text
   推荐归档路径：E-产出交付/01-已发文案/2026-05-17-xxx.md
   ```
3. 通知 Main Agent：该结果需要归档回 GitHub；
4. 未归档前，该内容只算“临时完成”，不算长期闭环完成。

## 4. 各AI员工专项规则

### 4.1 选哥：每日选题推荐官

执行前：

1. 读 GitHub `CLAUDE.md`、`A03-MEMORY.md`、最新每日输入；
2. 读 `D-内容创作/02-选题决策/`；
3. 读 `C-记忆核心/03-经验沉淀/爆款方法论/`；
4. 再读飞书 `kunki输入` 的今日任务。

执行后：

- 选题推荐归档到 `D-内容创作/02-选题决策/`；
- 飞书 `kunki输出` 只放Top3摘要和GitHub路径。

### 4.2 写作哥：内容初稿写作

执行前：

1. 读系统定位和最新记忆；
2. 读文案框架、开篇模板、风格样本；
3. 读对应选题和素材。

执行后：

- 草稿归档到 `E-产出交付/01-已发文案/` 或对应内容项目文件夹；
- 飞书只展示摘要、标题候选、下一步修改建议。

### 4.3 盘哥：复盘沉淀官

执行前：

1. 读已发布文案；
2. 读数据反馈；
3. 读历史爆款方法论；
4. 读最新A03-MEMORY。

执行后：

- 数据进入 `E-产出交付/03-数据反馈/`；
- 复盘进入 `C-记忆核心/03-经验沉淀/`；
- 重要洞见追加到 `A03-MEMORY.md`；
- 飞书只留复盘摘要。

### 4.4 情报哥：信息情报收集

执行前：

1. 读系统定位；
2. 读任务相关目录；
3. 使用网络搜索获取最新外部信息。

执行后：

- 研究报告归档到 `B-参考资料/02-研究报告/`；
- 外部数据归档到 `B-参考资料/03-外部数据/`；
- 飞书留摘要和关键结论。

### 4.5 催哥：进度催促与闭环检查

每日检查：

1. 飞书 `kunki输出` 是否有未归档结果；
2. GitHub最近提交是否包含AI员工当天产出；
3. `C-记忆核心/02-每日输入/` 是否有当天记录；
4. A03-MEMORY是否需要追加长期洞见；
5. 未闭环任务提醒 Main Agent 或林总。

### 4.6 学习搭子 / 保研助手

执行前：

1. 读最新保研/学习目标；
2. 读每日输入；
3. 读相关参考资料。

执行后：

- 学习计划、资料整理进入 `B-参考资料/` 或 `C-记忆核心/02-每日输入/`；
- 阶段性总结进入 `C-记忆核心/03-经验沉淀/`。

## 5. 飞书清理与保留规则

### 5.1 保留

- A01 AI bot设定与工作交付；
- kunki输入；
- kunki输出；
- 当前正在执行的任务文档；
- 需要给人类快速查看的摘要型文档。

### 5.2 不再强求保留

- 本地知识库所有Markdown完整镜像；
- 重复旧版A02/A03/B01等历史文档；
- 已经归档到GitHub的飞书临时输出全文。

### 5.3 删除前规则

飞书旧文档不要立刻大规模删除。先确认：

1. 内容是否已经在GitHub/Obsidian存在；
2. 是否有AI员工仍依赖该飞书文档；
3. 是否需要保留为历史快照。

确认无价值后，再分批删除或移入飞书归档区。

---

## 6. 任务完成定义

AI员工任务只有同时满足以下条件，才算真正完成：

1. 读取了 GitHub 最新主库；
2. 读取了必要的飞书任务输入；
3. 产出内容质量达标；
4. 长期有效内容已归档到GitHub/Obsidian；
5. 飞书 `kunki输出` 已留下摘要/路径/下一步；
6. 如有关键洞见，已追加到 `A03-MEMORY.md` 或经验沉淀目录。

少任何一步，都只是“临时完成”，不算闭环完成。
