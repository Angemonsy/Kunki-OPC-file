# 从聊天框到 AI 工作区：方法论总结

## 一句话总结

这节课的核心不是“把文件夹整理漂亮”，而是把 AI 从聊天框升级成能持续工作的数字员工：给它入口文件、索引、用户画像、沟通风格、程序性记忆、日志系统，再用 Skill 把固定工作流程封装起来。

## 核心认知

很多人感受不到 AI 的革命性，是因为还在用“网页聊天框”模式。大模型只有通用脑力，但不知道你是谁、你做什么、资料在哪、工具怎么用。知识库的价值，是给 AI 做入职培训，让它拥有上下文、工具路径、执行规则和记忆。

课程里用了一个很清楚的比喻：

| 组件 | 比喻 | 作用 |
|---|---|---|
| 大模型 | 发动机 | 提供通用智慧 |
| Cursor / Claude Code / Codex | 机甲和外壳 | 让 AI 操作电脑、文件、代码、工具 |
| 知识库 | 入职手册和公司档案 | 让 AI 理解用户、业务、流程和语气 |

## 六个核心组件

1. 入口文件  
   AGENTS.md / CLAUDE.md 是 AI 每次启动时读的入职说明，告诉 AI 先读什么、怎么协作、怎么写日志、怎么控制版本。

2. 索引  
   INDEX.md 是全库地图。知识库有很多文件时，AI 不会天然知道每个文件的用途，索引要告诉它资料在哪、什么场景读什么。

3. 用户画像  
   USER 类文件解决“我是谁”的问题，包括身份、业务、阶段、偏好、表达习惯。

4. 沟通风格  
   SOUL 类文件解决“AI 怎么和我说话”的问题，包括语气、格式、禁忌和协作边界。

5. 程序性记忆  
   PROCEDURES.md 解决“遇到 X 就做 Y”的问题，把反复纠正过的动作固化成默认规则。

6. 日志系统  
   system log 记录 AI 做过什么、改过什么、系统发生过哪些变化。日志的价值不只是追溯，也能从错误和重复动作里提炼新 Skill。

## Skill 的价值

Skill 本质是可复用的 SOP。它把一件事拆成稳定步骤，让 AI 不用每次重新理解流程。

课程里区分了两类 Skill：

| 类型 | 适合任务 | 例子 |
|---|---|---|
| 大模型驱动型 | 需要理解、创作、判断 | 文案、咨询诊断、PPT 大纲 |
| 代码驱动型 | 程序化、格式化、抓取、转换 | 数据抓取、海报排版、文件转换 |

这对 Kunki 的启发是：不是所有工作都要靠大模型“想”。能标准化的部分要封装成 Skill，能程序化的部分让代码执行，AI 负责判断、调度和复盘。

## 典型应用场景

- PPT 生成：读取大纲，提炼观点，重组结构，定义视觉风格，输出 HTML 或 PPT。
- 数据抓取：定时抓取对标账号，整理互动数据，推送到飞书多维表格。
- 竞品调研：跨平台采集内容、评论、互动数，生成调研报告。
- 私域客户管理：建档、跟进、生成诊断报告。
- 内容生产流水线：文案、海报、朋友圈、视频剪辑逐步自动化。

## Obsidian 与 Codex / Claude Code 的分工

| 工具 | 本质 | 作用 |
|---|---|---|
| Obsidian | 图书馆和阅读器 | 存资料、做链接、沉淀知识 |
| Codex / Claude Code | AI 工作区和执行者 | 操作文件、运行代码、调用工具、执行任务 |

关键不是二选一，而是配合：Obsidian 负责沉淀，Codex / Claude Code 负责执行。

## 对当前知识库的吸收

这节课和余生姜样板对我们最有价值的点有五个：

1. 全库地图：补 [[01-入口与总控/知识库总索引.md]]，让 AI 先知道资料在哪。
2. 程序性规则：补 [[02-记忆系统/规则与偏好/程序性规则.md]]，把固定动作显性化。
3. 当前状态与本周重点：并入 [[02-记忆系统/当下每时每刻（持续更新）.md]]，让 AI 判断当前优先级。
4. 系统日志：补 [[01-入口与总控/系统配置/系统变更日志.md]]，追踪结构和规则变化。
5. 业务区升级条件：不照搬对方业务区，但写清什么时候才值得从主题项目升级为根目录业务工作区。

## 不照搬的地方

余生姜知识库里有 `system/`、多个业务区、项目交付档案等结构，但 Kunki 当前知识库已经形成了自己的体系：

- [[02-记忆系统]] 已经承担 USER、SOUL、长期记忆和当前事实的功能。
- [[05-内容创作系统]] 已经是内容生产母版，不需要拆成外部样板的输出区。
- [[03-主题项目集]] 已经能承接 AI 学习、商业变现、学业求职等长期主题。
- 业务区可以作为未来升级方向，但现在不应该为了参考样板而提前新建。

## 对 Kunki 的行动建议

1. 先用新增的 [[01-入口与总控/知识库总索引.md]]、[[02-记忆系统/规则与偏好/程序性规则.md]]、[[02-记忆系统/当下每时每刻（持续更新）.md]]、[[01-入口与总控/系统配置/系统变更日志.md]] 跑一段时间。
2. 每次系统结构变更都写入 [[01-入口与总控/系统配置/系统变更日志.md]]，避免知识库改着改着失忆。
3. 当某条业务线开始有稳定客户、产品、SOP 和交付资产，再考虑升级根目录业务工作区。
4. 把知识库治理过程本身沉淀成内容和课程，这是 Kunki 当前最真实、最有说服力的案例。

## 可复用金句

- AI 不是聊天框，而是需要入职培训的数字员工。
- 大模型是发动机，AI 工作区是机甲，知识库是驾驶手册。
- Obsidian 是图书馆，Codex / Claude Code 是能进图书馆干活的人。
- 先跑起来，再追求完美。
- 能标准化的工作，最终都应该沉淀成 Skill。
