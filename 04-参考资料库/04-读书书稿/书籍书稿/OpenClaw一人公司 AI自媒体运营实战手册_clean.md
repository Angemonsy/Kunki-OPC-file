2.2 核心概念速通：Skills技能生态、Agent、USER.md/SOUL.md

很多人第一次接触 OpenClaw，看到一堆新概念就晕了。别急，这一节我用大白话给你把最核心的几个概念讲明白，你看懂这几个，后面配置起来就一点不晕。

第一个概念：Agent（智能体）

Agent 就是你招聘进来的"员工"。一个 Agent 对应一个具体岗位，比如你招一个"选题官"专门找选题，招一个"文案助手"专门写初稿，这两个就是两个不同的 Agent。

在 OpenClaw 里，每个 Agent 都有自己独立的工作区、独立的记忆、独立的配置，互不干扰——就像公司里每个员工有自己的办公室一样。

我自己现在就跑了六个 Agent：选哥（选题）、内容助手（写初稿）、催活助手（进度提醒）、公众号监控（抓热点）、学习搭子（数字经济保研学习）、素材整理大师（整理素材）——一人公司，六个员工，这就是我的团队。我的账号定位是「一边准备保研一边做 AI 一人公司的成长型博主」，六个智能体分别支撑内容运营和我的保研学习，两不误。如图2-2就是我团队配置示例。

第二个概念：Skills（技能）

技能就是给员工配上"工具"。一个员工再聪明，没有工具也干不了活。选题官需要上网搜热点，就得给它配"网页浏览"技能；数据分析师需要抓平台数据，就得配"数据抓取"技能。

第三个概念：USER.md / SOUL.md

这两个文件是给 Agent 定规矩定人设的地方，我给你讲清楚区别：

USER.md：告诉 Agent「我是谁，我的习惯是什么，你要怎么配合我」——这是用户侧的说明书

SOUL.md：告诉 Agent「你是谁，你的岗位职责是什么，你要怎么干活」——这是岗位侧的说明书

比如我的"选哥"Agent，SOUL.md 里就写清楚了：你是「我是林kunki」账号的选题官，每天要做什么，选题标准是什么，输出格式是什么——都写得明明白白。Agent 一上来就读到，它就知道自己该干什么了。

这两个文件是你调教 Agent 的核心，把这两个写清楚，Agent 就八九不离十能干对活。我后面第3章会给你看我实际配置的例子。

标准使用四步法：怎么让Agent用技能干活

很多人装完技能就不知道下一步该干嘛了。其实非常简单，就四步：

第一步：明确任务，告诉Agent你要干什么

不要说"帮我找选题"——太模糊。要说清楚："帮我找今天小红书上AI副业方向的5个热点选题，整理成表格给我"。

第二步：Agent会自动匹配需要的技能

OpenClaw 设计得很聪明，它知道找选题需要上网，它自己就会去调用 browser-use 技能，不用你手动指定。

第三步：技能执行，拿到结果

技能自动执行，比如打开浏览器去搜了，把内容抓回来，交给 Agent。

第四步：Agent整理结果，输出给你

Agent 把技能拿到的 raw data 整理成你要的格式，比如表格、清单，发给你。

整个过程你就只需要说清楚第一步，剩下三步 Agent 自己搞定。这就是它比别的框架好用的地方——你不用指挥它"先调用这个工具再调用那个"，它自己知道该怎么走流程。

举个真实例子，我让选哥找选题，对话大概是这样的：

    我：选哥，今天是2026年5月1日，帮我找一下AI副业、大学生赚钱这个方向的5个热点选题，参考小红书热点榜和已订阅公众号的最新文章，筛选出符合我们账号定位的，给我每个选题写一句推荐理由。

    选哥：（自动调用browser-use去刷热点榜）→（自动调用wechat-watch读公众号新文章）→（整理分析）→ 输出选题表...

你看，我就说了一句话，剩下它自己全干了。这就是技能生态的威力。

飞书双向同步怎么实现？

很多人问我，飞书双向同步有没有现成 skill？答案是：没有现成独立 skill，这是 Main Agent 的核心逻辑。

核心规则就是：飞书云文档是唯一权威，所有AI员工的人设、配置、规则全部存在飞书，本地只保留入口缓存。

双向同步逻辑很简单：

    本地配置变更 → 推飞书多维表格（用 feishu-bitable skill 写）

    飞书表格被人工改了 → 飞书回调事件触发 Agent → Agent 拉取更新覆盖本地

    一致性靠 version 字段 + 最后修改时间戳兜底，冲突时弹通知让我人工判断

好处就是：不怕服务器丢数据，重新装完拉飞书就能 10 分钟恢复全套配置，非常安心。

服务器配置要求与成本

很多人问我，到底什么配置够用？给你一个明确答案：

最低配置：2核4G内存，带宽1M → 完全够用，跑五六个Agent没问题

一键部署方式（推荐新手）

云端部署其实比你想象的简单很多，现在有官方一键脚本，十分钟就能搞定：

第一步：买云服务器

推荐腾讯云轻量应用服务器，国内访问稳定，价格也便宜。系统选 Ubuntu 22.04。

买完服务器，记得开放端口：需要开放 18789 端口（OpenClaw 控制台）和 22 端口（SSH 连接），这个在防火墙设置里添加规则就行。

第二步：连接服务器，一键部署

拿到 IP 地址和root密码，用 MobaXterm 或者其他终端工具 SSH 连上去。

连接成功后，直接复制粘贴官方一键部署命令：

    bash <(curl -fsSL https://gitee.com/Comfortable_blog/linux/raw/master/openclaw_control.sh?cdn=fastgit)

输入回车，它就自动跑了，一路选默认配置就行。

跑成功之后，它会给你一个控制台地址和 token，记下来。

第三步：浏览器访问控制台

把地址里的 127.0.0.1 换成你服务器的 IP，改成 https，然后用浏览器打开，接受风险提示继续访问，就能看到 OpenClaw 控制台了。

第四步：授权你的访问设备

第一次访问需要授权，在终端里输入：

    openclaw devices list

拿到请求 ID，然后授权：

    openclaw devices approve <请求ID>

刷新浏览器，就能进去了。搞定！

手动安装方式（适合懂技术的朋友）

如果你不想用一键脚本，想自己装，也很简单，三步搞定：

     1. 安装 Node.js 22+

    curl -fsSL https://deb.nodesource.com/setup_22.x | bash

    apt-get install -y nodejs
    
     2. 安装 OpenClaw

    npm install -g openclaw
    
     3. 初始化

    openclaw init

生成工作目录，然后按照提示走就行，十分钟也能跑起来。本地 Mac 也能这么装，但生产环境建议丢云服务器，不然关机就断了。

避坑专区：

打不开控制台 → 检查防火墙端口开了没，检查是不是用 http 访问的，必须用 https

连不上服务器 → 检查 IP 对不对，检查 22 端口开了没

部署卡住不动 → 通常是网络问题，重新跑一遍脚本就行

飞书没反应 → 90% 是权限没开全，去开发者后台检查能力开通状态

域名和 HTTPS 配置解惑

很多人纠结要不要买域名？这里讲清楚：

OpenClaw 默认用 WebSocket 长连接，飞书主动连过来，不需要公网 IP 暴露，也不需要域名。前期直接用服务器 IP 测试就行，完全没问题。

正式上线后：建议绑个域名，十几块钱一年，方便记忆，SSL 证书 OpenClaw 会自动申请 Let's Encrypt 免费证书，配置的时候填好域名就自动搞定，不用手动操作。

如果你要接外部 Webhook：才需要公网可访问域名，否则不用。

所以新手不用纠结，IP 先用着，跑起来了再买域名不迟。

2.5 API Key获取、模型对接与飞书机器人接入

好了，框架装完了，接下来就是最关键的一步——接上你的大模型大脑。OpenClaw本身只是一个框架，它不提供大模型，你得自己去各大厂商申请API Key，填进去才能用。

很多人看到这里就头大，其实真没那么复杂。我当时第一次配也以为很难，实际操作下来，二十分钟搞定。我把我踩过的坑都给你写清楚，你照着做就行，保证一次成功。

先给你讲明白，到底什么是API Key？其实一句话就能说清楚：它就是大模型厂商给你的“开门钥匙”。你用人家的模型，人家要认你是谁，要算你用了多少token，要扣你钱，这个Key就是你的身份凭证。

所以你理解了吧？API Key这个东西，一定要保管好，就像你的银行卡密码一样，千万别截图发到网上，千万别放到公开的GitHub仓库里，不然被人扒走了，刷爆你的额度你哭都没地方哭去。我见过好几个新手吃这个亏，你别犯。

第一步：获取大模型API Key

目前国内用得比较多的几个厂商：DeepSeek、MiniMax、豆包、 Claude 3。流程大同小异，我以DeepSeek为例给你走一遍，其他厂商照着来就行：

1. 打开DeepSeek开放平台官网
2. 注册账号，完成实名认证（这个是必须的，不然不给你Key）
3. 进入“API Key管理”，点击“创建新的Secret Key”
4. 给Key起个名字，比如“OpenClaw使用”，创建完复制保存下来

记住了：这个Key只显示一次！你不复制保存，关掉页面就再也看不到了，只能重新创建。所以一定要复制好了找个地方记下来。

支持多模型同时配置，这个设计真的很香。我现在同时配置了Claude、DeepSeek、GPT三个模型，复杂推理写文章用Claude，简单活发发通知用DeepSeek，这样既能保证质量又省钱。你也可以这么干，不用吊死在一棵树上。

第二步：在OpenClaw里配置大模型

拿到Key了，接下来填入OpenClaw就行，操作很简单：

打开OpenClaw控制台 → 左边菜单栏找到Model Settings → 点击“Add Model” → 选择你用的模型厂商 → 把刚才复制的API Key粘贴进去 → 点保存，搞定。

就这么简单。配置完了你测试一下，在控制台发个消息，如果能正常回复，说明接上了，往下走。

第三步：飞书机器人接入（这步必须配）

OpenClaw最好用的地方在哪里？就是它能直接把结果推到你飞书上。你不用天天开着控制台，随时随地手机就能看，发指令干活也在飞书里直接发，这个体验真的用过就回不去了。所以这一步一定要配，别偷懒。

我把完整步骤给你拆解开，你一步一步来：

1. 打开飞书开放平台，用你自己飞书账号登录
2. 创建「企业自建应用」，填好应用名称（比如“我的AI团队”）
3. 创建完进入“开发”-“基本信息”，这里能拿到App ID和App Secret，记下来
4. 进入“权限”，把这些权限都加上：`auth:userid`、`im:message`、`im:message:send`、`bitable:read`、`bitable:write`、`doc:read`、`doc:write`、`calendar:read`
5. 权限加完了，去“版本管理与发布”，点发布版本，然后申请企业启用（如果你是个人账号，用自己的飞书，直接启用就行）
6. 最后一步，打开OpenClaw配置文件 `~/.openclaw/openclaw.json`，找到 `channels.feishu.accounts`，把你的app_id和app_secret填进去
7. 重启一下OpenClaw网关：执行 `openclaw gateway restart`

3.1 单Agent调教：USER.md/SOUL.md定制与定时任务配置

咱们从一个 Agent 开始。先教会你怎么调教单个 Agent，掌握了方法，你想加多少个 Agent 都行。

核心：用USER.md和SOUL.md把规矩说清楚

我在第二章说了，USER.md 是告诉 Agent「我是谁，我的习惯是什么」，SOUL.md 是告诉 Agent「你是谁，你要干什么」。这两个文件是调教的核心，一定要写清楚。

我拿我的"选哥"（选题官）给你做例子：

USER.md（用户信息）：

     用户信息
    
    - 我是：林琨奇，账号「我是林kunki」创始人
    - 账号定位：AI时代一人公司实践者，分享一边实战一边成长的真实经验
    - 我的受众：主要是大学生、想做副业的年轻人、AI爱好者
    - 选题偏好：喜欢真实的成长故事、可操作的实战方法、有争议的观点，不喜欢空泛的理论
    - 我的更新频率：每周更新3-4条，优先保证质量

就这么简单，把核心信息说清楚就行，Agent 读一遍就知道你的调性了。

SOUL.md（岗位职责）：

     选哥 - 选题官
    
     你的定位

    你是「我是林kunki」账号的专职选题官，帮老板找符合账号定位的好选题。
    
     你的核心职责

    1. 每日爬取小红书、公众号、抖音热点榜，筛选符合定位的选题
    2. 结合已订阅行业大号的最新文章，提炼可创作选题
    3. 每日早上6:55主动推送5个候选选题给老板，带推荐理由
    4. 对公众号监控助手推来的新文章做选题价值初判
    
     选题标准

    - 符合账号定位：大学生、AI、副业、一人公司、成长
    - 用户有痛点：读者真正关心，能引发讨论
    - 有话可说：老板有亲身经验可以分享
    - 避开太泛的题目：要具体，不要"AI改变世界"这种空题
    
     输出格式

    每次给老板推荐5个选题，每个选题包含：

    1. 选题标题
    2. 推荐理由（为什么这个选题好，用户为什么关心）
    3. 可选切入点建议（1-2个角度）

你看，这样写下来，岗位职责、标准、输出格式都说得清清楚楚，Agent 一上来就知道该干什么，不会跑偏。

我总结一下写 SOUL.md 的三段式结构，你套进去就行：

    1. 你的定位 → 一句话说清楚这个岗位是干嘛的
    2. 你的核心职责 → 列点说清楚具体做什么
    3. 工作标准 + 输出格式 → 告诉它做成什么样算合格，按什么格式输出

        }
      }
    }

3.3 验证与使用：多Agent协作测试与三种团队使用方式

配置完了，怎么验证对不对？怎么用呢？我给你说三种常用的使用方式。

第一种：直接@Agent，一对一指挥

这是最常用的方式。你在飞书群组里，直接@你要找的 Agent，给它发指令就行。

比如：

    @contenthelper 这是今天选的选题：「一个大学生怎么用OpenClaw一边准备保研一边做自媒体」，帮我写一篇公众号口播文案初稿，按照咱们的模板来。

它就直接给你出初稿了。非常直接，有什么临时任务就这么用。

第二种：Agent之间自动协作

你配置好了之后，Agent 之间可以互相调用，不用你每次中转。

比如我的流程是：

gzhmonitor（公众号监控） 发现新文章 → 自动推给 xuanguan（选哥） → xuanguan 看完做价值判断 → 有价值就放到候选选题池 → 第二天一起推给我。

整个过程完全自动，不用我管。这就是多 Agent 协作的魅力——一套流程配置好，它自己就能转起来。

第三种：Main总管调度，你只需要给Main说

Main Agent 是你的首席助理，你把需求给它，它帮你派活给各个专业 Agent，最后汇总结果给你。

比如你说："Main，帮我整理一下这周的运营数据，给我一份周报。" Main 就会去找数据 Agent 拉数据，找催活 Agent 汇总进度，最后整理成周报给你。

这种方式适合复杂任务，你不用记该找谁，Main 帮你安排。

怎么验证配置成功了？

给你一个简单的验证流程：

在飞书@每个Agent，发一句简单的测试话，看能不能正常回复 → 验证基础通信

测试定时任务：等一天，看它到点会不会自动推 → 验证定时

测试跨Agent协作：让公众号监控推一篇文章给选哥，看选哥会不会接 → 验证协作

三步都没问题，说明配置成功，可以投产用了。

 选哥（xuanguan）- 选题官：完整配置

     13大爆款元素评分体系

    每个选题 13 个元素打分，每个 0-10 分，满分 130 分，换算百分制：
    
    生存层（基础流量）：

    - 成本元素（0-10分）：选题有没有涉及赚钱、省钱、省时间？用户看完能不能觉得"这对我有利"？
    - 最差元素（0-10分）：有没有涉及避坑、踩雷、翻车、失败案例？人对避免损失的关注远大于获得收益。
    - 荷尔蒙元素（0-10分）：能不能引发强烈情感共鸣？愤怒、焦虑、感动、骄傲、FOMO都算。
    
    发展层（精准触达）：

    - 人群元素（0-10分）：你的目标读者看到这个选题，会不会觉得"这说的就是我"？核心读者：想用AI做内容/做副业/做自媒体的人、对数字经济感兴趣的大学生、非技术出身但想拥抱AI的人。
    - 场景元素（0-10分）：有没有具体的使用场景让人代入？读者能立刻想到"我什么时候能用"。
    - 数据元素（0-10分）：有没有具体的、让人震惊的数字？数字本身就是钩子，让人"卧槽"。
    - 对比/对立元素（0-10分）：有没有强烈的反差和对比？前后对比、新旧对比、认知冲突。反差本身就是标题的核心吸引力。
    
    超越层（破圈潜力）：

    - 反认知元素（0-10分）：有没有颠覆读者常识的点？直接打破读者的固有认知。
    - 怀旧元素（0-10分）：能不能唤起集体记忆或时代情绪？
    - 猎奇/揭秘元素（0-10分）：有没有"不为人知的内幕"/"行业真相"/"隐藏玩法"？让人觉得"这个信息别的地方看不到"。
    - 头牌元素（0-10分）：能不能借到名人、名企、名产品的势？OpenAI/马斯克/腾讯/苹果等自带流量的名字是标题的一部分。
    - 高维认知元素（0-10分）：有没有让读者觉得"这个人的认知段位很高"的洞察？看完让人觉得"这个人看问题的角度不一样"。
    - 钩子问题元素（0-10分）：能不能在开头抛出一个让人忍不住想知道答案的问题？问题本身就让人停下来想看答案。
    
    评分纪律：大部分选题应该在 60-80 分区间；90 分以上一周最多出现 2-3 个；某个元素完全不沾边必须给 0 分，不给"同情分"；每个分数必须有一句话理由。

4.1 选题的本质：不是你想说什么，是用户在搜什么、在焦虑什么

很多人做选题，犯一个根本错误：我想讲什么，我就写什么。

错了。大错特错。

选题的本质，一句话就能说清楚：不是你想说什么，是用户在搜什么、在焦虑什么、想解决什么问题。

你讲得再高深，再正确，用户不关心，这就是个坏选题。你讲得再"简单"，用户就是关心，这就是个好选题。

我自己总结，一个好选题，必须满足三个条件：

条件一：用户有明确的痛点或欲望

用户看到标题，第一反应是"这就是说我呢！""这正是我想知道的！"——这就成了一半。

比如：

❌ 坏选题："AI的发展历史与未来展望"——太宏观，用户没痛点

✅ 好选题："大三一边保研一边做自媒体，我是怎么做到时间够用的"——具体，有明确人群，有明确痛点

条件二：你有独特的视角或亲身经历

选题撞车不可怕，可怕的是你跟别人说的一模一样。用户为什么要看你的？因为你有别人没有的东西——要么是你亲身踩过坑，要么是你有不同观点。

我自己做「我是林kunki」，最大的独特性就是：我就是大三学生，我一边准备保研一边做AI自媒体一人公司，我实战跑通了。这个身份，这个经历，就是我最大的选题护城河。

条件三：能引发讨论和争议

太正确的废话，没人愿意评论。有点争议，有点不一样的观点，大家才愿意留下看法，数据才会好。

但这里有个度，我反复强调：critical but moderate——批判但不极端，观点不一样但说话留余地。这对我尤其重要，因为我还是在校学生，还要保研，绝对不能因为言论出问题。

我的红线原则分享给你：

✅ 可以讲象牙塔的不足，可以说学校里学的和市场需求有差距

❌ 不要贬低你的大学，不要全盘否定象牙塔，更不要发表极端言论

✅ 可以分享你的不同观点，可以说"我不同意这个说法，我认为是..."

❌ 不要人身攻击，不要一棒子打死一群人，不要说绝对话

这个尺度把握好了，既能引发讨论涨数据，又不会触碰红线，安全第一。我的经验是：把问题说清楚，把你的思考说出来，不骂人不极端，读者其实更买账。

13要素选题评分体系

很多人问我，选哥的选题评分具体是哪13个维度？我全给你，直接抄作业：

每个选题 13 个维度打分，每个维度 0-10 分，满分 130 分，换算百分制：

生存层（基础流量）：

成本元素：选题有没有涉及赚钱、省钱、省时间？用户看完能不能觉得"这对我有利"？

最差元素：有没有涉及避坑、踩雷、翻车、失败案例？人对避免损失的关注远大于获得收益。

荷尔蒙元素：能不能引发强烈情感共鸣？愤怒、焦虑、感动、骄傲、FOMO都算。

发展层（精准触达）：

人群元素：你的目标读者看到这个选题，会不会觉得"这说的就是我"？

场景元素：有没有具体的使用场景让人代入？读者能立刻想到"我什么时候能用"。

数据元素：有没有具体的、让人震惊的数字？数字本身就是钩子，让人"卧槽"。

对比/对立元素：有没有强烈的反差和对比？前后对比、新旧对比、认知冲突。反差本身就是标题的核心吸引力。

超越层（破圈潜力）：

反认知元素：有没有颠覆读者常识的点？直接打破读者的固有认知。

怀旧元素：能不能唤起集体记忆或时代情绪？

猎奇/揭秘元素：有没有"不为人知的内幕"/"行业真相"/"隐藏玩法"？让人觉得"这个信息别的地方看不到"。

头牌元素：能不能借到名人、名企、名产品的势？OpenAI/马斯克/腾讯/苹果等自带流量的名字是标题的一部分。

高维认知元素：有没有让读者觉得"这个人的认知段位很高"的洞察？看完让人觉得"这个人看问题的角度不一样"。

钩子问题元素：能不能在开头抛出一个让人忍不住想知道答案的问题？问题本身就让人停下来想看答案。

评分纪律：

大部分选题应该在 60-80 分区间

90 分以上一周最多出现 2-3 个

某个元素完全不沾边必须给 0 分，不给"同情分"

每个分数必须有一句话理由

筛选标准： >100分 S级必做，80-100分 A级优先做，60-80分 B级可做，<60分直接放弃。

AI 按照这个框架给你打分，比你瞎选靠谱多了。

第5章 文案：把选题变成能打动人的内容

选题定好了，接下来就是文案。很多人卡在这一步：选题很好，但就是写不出来，或者写出来干巴巴的没人看。

5.1 自媒体文案的底层逻辑：标题决定打开率，正文决定完播率，结尾决定转化率

讲具体方法之前，咱们先把底层逻辑讲透。不管是什么平台，文案写作都逃不开这三件事：

标题决定打开率——标题不行，内容再好没人点，白搭。

正文决定完播率/读完率——开头抓不住人，用户划走了，白搭。

结尾决定转化率——你想要用户干什么，点赞关注还是加微信，说明白。

就这三件事，把这三件事做好了，文案就成功了 80%。如图5-1就是文案的三层结构模型。

图5-1 自媒体文案三层结构模型

我一直跟我的内容助手说：不要写出来让用户"看不懂"，要写出来让用户"记得住，转得出"。

什么意思？就是：

用口语，别用书面语——你是跟朋友聊天，不是写毕业论文

每一段短一点——手机阅读，大段文字看着就累

有故事，有观点，有干货——故事抓情绪，观点给态度，干货给价值

5.2 标题写作：爆款标题的5种结构模板

标题是门面，太重要了。我总结了五种适合我这种成长型博主的爆款标题结构，百试不爽，你直接套就行。

结构一：提问式 —— "你有没有/为什么/怎么..."

直接戳用户痛点，用户一看就觉得"这说的就是我"。

模板：为什么+你想做一件事+就是做不成

例子：

为什么你天天看AI干货，就是赚不到钱？

大三了，你为什么还不敢开始做自媒体？

一边保研一边做自媒体，时间真的够用吗？

结构二：冲突式 —— "我 X 了 Y，发现根本不是这么回事"

打破用户固有认知，引发好奇。

模板：别再被坑了！+ 说出真相

例子：

别再交智商税了！AI副业根本不是你想的那样

我试过了五种"AI赚快钱"，只有这个真的靠谱

都说做自媒体要日更，我周更3篇反而涨粉更快

结构三：干货式 —— "X个方法/技巧，帮你解决Y"

直接给干货，用户一看就知道能得到什么。

模板：我总结了X个+解决什么问题+亲测有效

例子：

我总结了5个AI选题技巧，帮你永远不再缺选题

三个配置原则，我的六个AI机器人从来没乱过

大四学长亲测：这五个AI工具最适合大学生搞副业

结构四：经历式 —— "我是怎么从X到Y的"

讲故事，个人经历最容易拉近距离。

模板：我+做了什么事+用了多久+得到什么结果

例子：

大三开始做自媒体，三个月我攒了这些经验

我用OpenClaw自动化运营三个月，省出了一半时间

从0到1搭建AI一人公司，我花了多少钱

结构五：反向观点式 —— "别人都说是X，我却觉得Y"

抛出不同观点，引发争议和讨论。

模板：关于X，我有不一样的看法

例子：

关于大学生做AI副业，我跟很多博主观点不一样

别神话AI了，它解决不了你的根本问题

做自媒体不是越勤快越赚钱，我信这句话

这五种结构，覆盖了 90% 的情况，你拿到选题，直接往里面套，半个小时就能想出三四个标题，让AI帮你选一个最好的。如图5-2就是五种结构对比总结。

5.3 正文写作：不同内容类型的文案框架

标题搞定了，接下来是正文。我做「我是林kunki」，主要就是两种内容类型：观点文和干货文。我把两种框架给你，你照着套，AI 写出来就不会散。

类型一：观点文框架（适合谈看法、聊认知）

    1. 开头：用一个场景/一个问题引入，戳痛点

    2. 抛出你的核心观点（一句话说清楚）

    3. 分三点展开论证：

       - 第一点：为什么这个观点对？背后逻辑是什么

       - 第二点：反例，错误的做法是什么，有什么坑

       - 第三点：普通人可以怎么开始，给个简单行动建议

    4. 结尾：总结观点，引发讨论

就是这么简单，五段话，结构清晰，用户看着也不累。我那篇《很多人说大学生不要做AI副业，我为什么偏偏一边保研一边做？》就是这个结构。

类型二：干货文框架（适合教方法、讲步骤）

    1. 开头：说清楚这篇文章能帮你解决什么问题

    2. 前置说明：需要什么准备，难度多大，需要多久

    3. 分步骤讲解：一步一步来，每一步配操作说明

    4. 常见问题：把你能想到的坑先讲了，帮读者避坑

    5. 结尾：总结鼓励，给行动建议

这种框架用来写教程特别好用，比如这一章讲"怎么用AI写文案"，就是这个结构。

最重要的一点：保持你的人设口吻

你是什么人设，就说什么话。我是大三学生，实战派，我就说人话，不说黑话，不装高深。"我告诉你..."、"我亲测..."、"你别不信..."，这种口语化的词放心用，拉近跟读者的距离。

我把我的账号口吻写在了内容助手的 USER.md 里，它每次写都会模仿，所以写出来的初稿跟我自己写的语气差不多，我改很少。如表5-1就是不同人设口吻对比。

5.4 钩子设计：如何在文案中自然植入引流入口（不生硬、不违规）

做自媒体最终都是要变现的，引流到私域是绕不开的。怎么植入钩子既不生硬，又不违规？我试过几种方法，给你分享两个我常用的，安全有效。

方法一：资料钩子——免费干货引流

最自然的方式就是：你看了我的文章，觉得有收获，我免费送你一份配套资料，你加我领就行。

例子：

> 我把自己用的「AI选题自动化配置模板」和「六人团队分工文件」整理好了，放在我的公众号后台，回复「选题」就能领，需要的朋友可以去拿。

就这么自然，不生硬。因为你文章已经给了价值，用户觉得有用，自然愿意加你领资料。

方法二：链接钩子——引导看更多内容

如果你有多平台布局，可以互相导流：

例子：

> 想了解我更多保研+自媒体的日常，可以去看我的抖音@我是林kunki，我每周更两条实战vlog。

这也很自然，用户想看就去，不想看也不影响，平台一般不会管。

红线不能碰

不要直接放二维码在文案里，很容易违规

不要说"加我微信赚钱"这种话，太功利，也容易违规

不要诱导分享，"转发点赞才能领"，容易被限流

6.3 内容质检SOP：AI生产的内容为什么不能直接发

问题一：幻觉——事实错误

质检要点：

涉及工具链接、版本号，一定要确认对不对

问题二：调性不一致——太官方，不像你说的话

AI 写出来的东西，有时候容易变"官话"，跟你日常说话的语气不一样。读者一读就觉得"这不对，不是这个博主的风格"。

质检要点：

读一遍，哪里读着不顺口，就改成你平常说话的样子

删掉那些你平常不会说的词，比如"赋能""抓手""闭环"，你平常不说就别用

加点你的口头禅，更真实

问题三：观点跑偏——不符合你的定位

AI 容易"和稀泥"，什么都说一半，没有明确观点。或者观点偏了，跟你一向表达的不一样。

质检要点：

核心观点是不是你想表达的？

有没有哪里说过头了，需要收一点？

有没有触碰红线？（这个非常重要！）

问题四：错别字和语病

爆款复盘：它为什么火了？

爆款出来了，你要问这几个问题：

选题对了吗？ 这个选题是不是戳中了一个强痛点？用户是不是真的很关心？

标题开头对了吗？ 点击率完播率是不是比平均高？为什么？标题哪里写对了？开头哪里写对了？

内容共鸣点在哪里？ 评论区大家都在说什么？哪句话引发了最多共鸣？

能不能复制？ 这个选题方向/这个标题结构/这个切入点，下次还能用吗？

把这几个问题想清楚，你就能把一次偶然的爆款，变成你可复制的经验。下次你就按照这个成功路径再走一遍，爆的概率就大很多。

扑街复盘：它为什么没起来？

扑街了也别灰心，扑街也能学到东西。问这几个问题：

是选题问题吗？ 选题用户不关心？还是选题太泛了没有痛点？

是标题开头问题吗？ 点击率完播率是不是比平均低很多？

是内容问题吗？ 内容是不是没讲透？是不是没给用户价值？

5000收藏

《大三一边保研一边做自媒体，我是怎么平衡时间的》 → 800点赞 200收藏

你看，差异很明显：干货、方法总结类内容，收藏率就是高，说明用户需要，愿意存起来慢慢看。情绪观点类内容，点赞评论高，说明容易引发讨论互动。

那你下次做内容，想涨粉就多做点引发讨论的，想做私域引流就多做点干货收藏，数据告诉你了。

从数据到行动：AI 怎么帮你

AI 可以帮你做这些：

自动算平均值：告诉你哪条高于平均，哪条低于平均

自动分类：按选题类型、内容类型给你分组算平均数据

找出规律：哪一类选题数据 consistently 好，哪一类 consistently 差

给建议：根据规律，给你下次选题内容提建议

比如 AI 分析完告诉你："最近一个月，大学生时间管理类选题平均完播率比其他选题高 15%，建议下周多更这个方向。" 你照着做就行。

10.1 为什么公域流量必须导入私域

做自媒体变现，我最深的体会就是：公域是流量，私域是资产。

你在抖音/小红书/公众号有一万粉丝，但这些粉丝平台掌握着，说给你限流就给你限流，说封号就封号，你一点办法没有。但导到私域（微信），这些粉丝就是你的资产，你可以反复触达，可以做复购，可以做服务。

所以我的变现逻辑，从一开始就是：公域内容吸粉 → 引流到私域 → 私域转化变现。这个漏斗虽然传统，但对于中小博主来说，真的最稳，转化率最高，钱赚得也踏实。如图10-1就是我的变现漏斗。

图10-1 一人公司变现漏斗模型

为什么一定要导私域？

信任度更高：加了微信，用户对你信任度更高，更愿意买单

可以反复触达：你出新产品，发个朋友圈就触达了，不用等平台给流量

掌握主动权：不会因为平台规则变了，你就没饭吃

客单价更高：私域成交的客单价，通常比公域直接变现高很多
